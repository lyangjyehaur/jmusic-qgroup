## 已具備或已核對的項目

- 首頁及登入彈窗已有易找的 QQ 入口。76×24 藍色按鈕是官方視覺素材列出的尺寸；現在的圖片檔與此次下載的現行素材不是逐位元組／像素完全一致，未確認是否為另一官方版本，不能據此認定違規。要排除來源疑義，可換用本次官方直接下載的原檔，維持原比例，不自繪 QQ 商標。
- 首頁、操作說明、管理頁與公開回調均可訪問；無參數回調顯示引導，不產生帳號，這與接收合法 OAuth 回調是不同情境。回調 URL 無 localhost、任意端口或 fragment。
- 程式配置以同一 HTTPS origin 固定 `/auth/qq/callback`；token 交換使用相同 redirect_uri。QQ 後台實際登記值尚須逐字核對，包括 https、子域與路徑。
- OAuth 為伺服器端 authorization-code 流程，state 必填、隨機、限時、一次性，綁定發起瀏覽器和帳號／訪客。由後端交換 token、驗證 client_id／OpenID，再由使用者確認建立或登入帳號。
- 使用 `scope=get_user_info`，沒有多申請好友、發表或關係鏈權限。資料庫以平台、App ID 及 OpenID 關聯，不用稱呼當身分，不索取 QQ 號、QQ 密碼或強制 QQ 信箱；一般使用者無須另設網站密碼。
- App Key 留在伺服器，token 不交給瀏覽器或持久化；應用日誌遮蔽 code／state；HttpOnly、Secure、SameSite Cookie 已有。1Panel 代理層日誌是否同樣遮蔽，此次未查驗。
- 從線上主機可連線 graph.qq.com；這只證明網路可達，不能當作成功 token 交換或真實 QQ 登入驗收。
- 資料修改、群內稱呼與跨設備身分維持獨立；管理後台憑證屬獨立站務功能，不是要求 QQ 使用者再設定密碼。

## 審核期間的測試與先前說法更正

官方「申請註冊相關問題」的一、1、2 及三、5 提到：未審核時可以使用註冊開發者 QQ／調試 QQ 測試。部分說明與新增調試者流程針對移動應用，因此不能直接保證每個網站 AppID 都已具相同能力。

先前把「審核中」一概視為只能等待，說得過於絕對。現在應檢查本站申請帳號及後台是否提供適用的調試名單，再用對應 QQ 嘗試；之前實際的 100008 只代表當時該授權入口／帳號未能開通使用，不單憑它判定所有測試者都不可測。

真正仍待驗收的完整流程：QQ 授權 → 固定回調 → token／OpenID／基本資料 → 首次確認建帳 → 再次登入找回 → 另一設備同 QQ 返回同一帳號，以及取消、拒絕和過期回調。既有自動化使用模擬官方回應，不能替代此項。手機需覆蓋系統瀏覽器及實際群友使用的 QQ 內建瀏覽器；官方亦明示 App 內嵌 H5 場景有支援限制，不可從桌面結果推定手機必定成功。

## 建議完善，但不冒充文件明列的硬性條件

- 增加一般帳號「退出登入」，並提供如何到 QQ 授權管理解除連結的說明。官方 FAQ 第 18 題建議站內也有授權管理；它不是所有網站必須立即提供獨立密碼或強制綁其他登入的要求。
- 首頁目前沒有活動，可加簡短功能介紹及真實功能範例截圖，讓審核者登入前看得懂用途。文件沒有規定必須製造幾場活動；不新增虛構的正式報名或款項。
- 網站已改名「群聚看板」；QQ 申請名稱、圖標、簡介若還是舊版，待後台允許編輯時與網站真實用途同步。沒有查到「改名一定過／不一致一定拒」這種保證性條款。
- 本次讀到的審核規範沒有把唱歌或 KTV 字眼單獨列為禁止類別；它明確列出的是在線遊戲暫不合作。一般活動報名工具中的活動分類，與實際提供在線遊戲服務不同；審核仍看真實用途與內容。
- 不需要為網站 OAuth 接入額外添加 Android／iOS SDK、Universal Links 或 UnionID。2026-10-30 新增的網頁 CDN SDK 是接入選項，所查文件沒有要求既有合規的伺服器端 OAuth 必須遷移。
- 目前僅登入時讀取資料且不保存 token，不必為了審核硬加 refresh_token 續期。若後續要長期呼叫 API，應以屆時有效期通知與實際 expires_in 為準，不能照較舊 FAQ 的固定天數硬編碼。
