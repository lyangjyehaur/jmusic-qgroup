# 包間安排與包間結算第一版

狀態：已於 2026-11-14 完成正式部署，見[發布紀錄](releases/2026-11-14-room-settlement.md)。發布範圍：`both`，涉及共用 schema、結算／帳本與 QQ 結算通知；本次按成套組合驗證與切換。資料庫遷移 19，HTTP 寫協議仍為 2。

## 安排、權限與資料

發起人在已發布且未取消／歸檔、尚未發布帳單的活動保存預分包間，最多 50 間。名稱可自訂，最多 40 字、同活動不重名；以隨機穩定 room ID 關聯，不以名稱識別。每位人員最多一間，候補可預分，也可先保存未分配狀態。同行按各自 attendee ID 分配，不改原報名管理權、AA 責任及名額。付款人從活動既有付款身分選擇，可同一人負責多間，不自動取得財務管理權。

`event_room_plans` 以活動與遞增版本保存完整 JSON 快照，禁止 UPDATE／DELETE。遷移只新增空表、觸發器及版本，不改既有資料。安排異動在既有交易內追加 event_audit 並遞增活動 revision。活動詳情的 room_plan 與包間公開內容遵循原活動可見性。包間卡片直接展開人員與付款人，優先顯示於詳情，標記本人包間、代報同行、候補／待確認及未分配名單；「我」只依穩定 attendee ID 的 is_me 判定，不按稱呼或代報管理權猜測。已結算活動從該版 people 快照顯示姓名，退出或更名不會讓實際分配名單失去原姓名。

包間卡片的後續改善發布範圍為 `web`，沿用原 API 與存取權限，未修改 bot 契約；本次與整項包間功能一併按 `both` 發布。

只有發起人可調整包間名稱、人員與付款人。已接受的指定結算人可沿用安排核對費用、發布與操作帳本，不能透過結算偷偷變更安排。轉交活動後依當前發起人判定。預分包間不產生款項或變更原費用約定；已有重要安排／費用爭議繼續遵守原參加者確認與結算核對規則。

## 實際包間與費用

逐人結算新增可選 rooms；有預分安排或舊包間帳單時，缺少此欄位的舊客戶端拒絕寫入。明確傳空陣列表示普通結算，但已有有效包間款項時必須保留包間模式。舊人均結算接口不得覆蓋已設定包間的活動。

每位列入本版的結算人員必須歸屬一間，正式名單保留規則、缺席／退出、半 A／免 A 的核對原因及原付款責任分配仍沿用 P3。每間填一筆實際總費用，後端生成該房人員的 selected／shares 費用項，不能由客戶端另傳 items 覆蓋。金額用整數分及最大餘數，補分仍依原報名順序，各包間精確對平。同一人付款不合併全活動均攤。

本版凍結實際包間、名稱、付款人標籤、人員、費用、逐人責任與發布時帳本投影。更正新增版本，原帳單與款項保留；名稱變更不重新歸屬舊錢。有效款項已使用的 room ID 不能消失。可更正該房費用及人員，帳本按新責任重新顯示差額。普通結算仍維持原行為。

## 實際款項與轉款

每間明確選 unpaid／paid／recorded。指定付款人不代表已付款。paid 另填實際已付金額，使用 room_payment_details 的實際時間與方式，發布時原子追加每間 expense；只預覽不入帳。有已確認店家支出／訂金的包間不得再次使用隨帳單墊付，改選 recorded 並在帳本補錄。預覽 token 同時約束名單、金額、安排、帳單版本及帳本序號，並發變動要求重新核對；去重請求不重複入帳。

包間款項 payload 新增 room_id、凍結的 room_name。收款、償還墊付、個人支出、代收資金、訂金與更正皆按包間投影，不能花用別間代收資金、用別間淨投入退款或跨間引用支出／訂金。關聯原記錄必須同房。沖銷仍保留原始記錄與後續關聯檢查。

各房逐人應付減該房已確認淨投入，得待補／應退；正差額向該房指定收款人付款，負差額由該房指定收款人退還／償還，付款人自己的投入另與店家支出核對。同一收款人的各房轉款可合計顯示，但不同包間不淨額抵銷。確認 collection 只表示收款人持有活動代收資金，實際償還墊付另記 reimbursement；不能把同一筆自動算兩次。

「我的待補／應退」僅計本人既有綁定身分，代報管理權不等於同行費用屬於管理人。發布畫面及 QQ 為發布時快照；帳本的各房轉款明細隨實收付更新。結清額外要求每房的淨店家消費等於各自帳單，且每房每人差額、持有款及訂金對平，不能只憑全活動總額相等。

舊版無 room_id 的有效款項不猜分配。轉包間結算前須核對、沖銷並按正確包間重新登記；待核對申報仍須處理。這是第一版明確的轉換限制。

## 介面與限制

- `PUT /api/events/:id/rooms`：rooms、base_revision，可選 reason；要求協議 2、去重鍵、發起人身分。
- `GET /api/events/:id`：room_plan、can_manage_rooms；原有可見性不變。
- `GET /api/events/:id/settlement/roster`：增加 rooms、已有店家記錄的 room_record_ids。
- 原 settlement preview／detailed 接口接受 rooms：`{id,name,payer_id,person_ids,amount,merchant_mode,paid_amount?}`，另可帶 room_payment_details：`{occurred_at,method}`。
- 原 finance 接口的 transaction 增加 room_id；已設定包間時必填。finance view 增加 rooms、summary.room_balances，各房含 balances、transfers、實際消費／持有款／訂金。
- QQ 結算通知列包間、收款人及轉款方向，限制顯示長度後指向活動頁；沿用原明確勾選與公開群同步前提。

第一版每人一間、每間一筆總費用；不含跨房按分鐘、共用費用分層或各收款人收款碼授權。包間結算清空本版統一收款碼，拒絕傳入統一碼，避免拿發布者的碼代表多位收款人；歷史普通帳單圖片不改動。表單明示按各收款人實際渠道轉帳。

## 驗證與發布

新增測試涵蓋同人跨房付款、各房分付、個人 AA 責任、半 A、精確補分、只指定不入帳、多房墊付原子交易／重試、跨房資金隔離、快照與改帳、舊客戶端防覆蓋、權限、並發、舊款未分房、代報身分及重複遷移。瀏覽器驗證使用本機隔離資料庫，未對正式活動或真實 QQ 群操作。

正式發布仍須遵循 deployment-policy：功能先整合並推送 main，完整 SHA 通過 check_release_source.py，僅封存核准提交在乾淨目錄建置。遷移先用備份副本執行 verify_migration.py；記錄兩個服務實際版本及映像。包間帳單及帶 room_id 的新寫入出現後，舊程式不具各房對帳／寫入檢查能力，回退不能只看 schema 可讀，須禁止舊財務寫入並驗證版本組合；不得覆蓋成舊資料庫。
