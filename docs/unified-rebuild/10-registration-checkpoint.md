## 名稱註冊

- 登入頁只在管理員開放時提供名稱註冊；直接開啟 `/register` 或呼叫 `POST /api/v2/auth/register-name` 都不能繞過關閉狀態。預設仍關閉，不覆蓋已保存的設定。
- 訪客輸入 1–24 個 Unicode code point 的站內稱呼、明確同意目前版本隱私政策，並另行確認建立獨立帳號。拒絕空白稱呼、控制字元、過長或額外身份／權限欄位。稱呼不作登入憑證，重名不尋找、關聯或合併既有帳號。
- 表單提示未綁 QQ 時遺失裝置授權可能無法找回，提供後續 QQ 綁定／本人另一裝置授權的方向。可以選擇 QQ 登入或返回原任務，沒有填充文案。
- 寫入前重新檢查訪客 session、scope、Origin、CSRF、即時註冊開關及安全返回地址。保留 query／hash 的原任務，拒絕外站、跳脫與授權迴圈。
- 建帳號、隱私同意、session 輪替、帳號 grant、原 QQ 意圖失效及 `name_registered` 稽核在同一 immediate 交易。失敗不發新 cookie；同一訪客 session 競爭送出只有一個成功。已登入裝置不能透過此 API 再建帳號。
- 成功後回原任務；關閉註冊仍可登入、管理既有帳號與保存成分。回應無法讀取時停止重複送出，使用完整頁面載入核對實際帳號並保留返回入口。這不是持久操作回執：若 cookie 本身也遺失，尚無通用帳號找回保障。

## 管理開關

`/me/accounts` 的管理員入口連至 `/admin/registration`；API 為 `GET／POST /api/v2/admin/registration`。

- 使用既有 `user_admin_roles`，逐請求檢查目前帳號及角色；session 僅回傳自己的管理員狀態。私有讀取檢查 scope，寫入另要求 Origin、session CSRF 及綁 session／帳號／角色 revision 的管理 CSRF。角色撤銷或版本變更會拒絕舊頁。
- 開放或關閉都要另行勾選確認；開放提示允許訪客不經 QQ 建立帳號。更新使用設定 revision，其他管理頁已修改時回 409，不能覆蓋。
- 設定及既有 `admin_audit` 的 `name_registration` 紀錄在同一交易；值沒變不增加 revision 或稽核。未知結果或衝突會鎖住再次送出，重新讀取目前值後才重新確認。
- 不新增管理員、自動提升權限或讀取舊救援憑證。救援登入／憑證輪替、角色授撤歷史 UI、完整統一後台、政策更新與刪除申請處理仍待實作。

## 限流修正與隔離測試

新增邊界測試發現之前路由先於限流插件完成註冊，`onRoute` 未套用限流。現在將 API／SPA 路由註冊放在插件之後，驗證全域每 IP 每分鐘 180 次，以及 QQ 開始 12 次、裝置發行 6 次、名稱註冊 6 次的路由限制；429 有結構化錯誤與限制標頭。

限流使用程序記憶體，重新啟動會重置，未宣稱為持久或多節點濫用防護。`trustProxy=false`，不信任來路提供的轉發 IP；正式代理與共用 IP 配額仍須在部署演練驗證。

瀏覽器測試改為每個案例啟動獨立合成預覽程序／記憶體資料庫／限流計數，再釋放程序，避免案例之間消耗同一 IP 配額或殘留帳號／設定。沒有調高或停用正式限流；測試 adapter 仍不進 API 正常 bundle。登入測試先等待表單載入，再檢查同意項；成分衝突案例從空資料開始，不再依賴前一案例留下的成分。舊裝置權限矩陣使用不同合成來源 IP，限流邊界另有實際拒絕測試。
