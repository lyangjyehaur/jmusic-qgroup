# 舊逐人帳單的讀取與新版核對

2026-11-23。變更範圍按 **`both`** 評估：結算共用契約、網站讀取／發布與通知投影。schema、outbox 格式及 Python bot 沒有修改；不合併 main、不部署，不操作正式服務或 QQ。

## 原資料問題與修正

沿用已授權擷取的正式隔離副本，來源 manifest 為 `591a7209bf5ef07b3a79569a4abd411899660acfcf25b24ee1fb9e38098bbd7c`。原資料共三份逐人帳單，其中兩份較早版本沒有 `journal_seq`、`balances`、`group_notice`。原 Python 直接讀取這些歷史 JSON；新網站先前用原生發布的完整 schema 讀取，因而拒絕舊帳單。

新增專用的歷史讀取契約，只允許這三個欄位缺省，其他金額、名單、付款歸屬、費用與圖片仍驗證。缺省保持缺省，不補造序號、零收付款或群通知同意。原生預覽與發布仍使用完整嚴格契約；錯誤型別及缺少必要的新快照欄位均拒絕。

舊帳單可查看最新、歷史及編輯入口。沒有收付款快照時顯示原「付款人應付合計」，提示到帳本核對待補／退款，不顯示假定的已投入或待補額。重新核對後追加新版，原 JSON bytes 不改；加入新的帳本快照也是實際版本變動，後續相同內容不再追加。群明細與收款碼仍必須有明確同意，缺省不發送。

## 正式隔離副本對帳

固定原 web 來源 `83eb54ce94f935a4048aaf63a410206723f09bd8` 的 **34 個 qgroup_core 檔案**逐檔核對；使用原結算讀取、名冊、預覽與保存函式比對，沒有修改 oracle 的財務邏輯。

- **14 場活動、64 次 HTTP**；13 場依原權限可讀，另一場已刪除，相關入口維持 404。全部三份歷史帳單及原名冊／付款人／收款人與 Python 一致；兩份舊版保持三個欄位缺省。
- **3 次預覽、3 次附原因新版保存、3 次精確重試**皆通過。完整快照、歷史操作者／修改項與版本、活動 revision 與原保存一致；重試不再寫入，舊版本可重新讀取。圖片引用明確沿用原版，不猜測另一協議的缺省選擇。
- 讀取階段 **96 張表不變**；寫入後 API 基線 **87 張表不變**。獨立 Python 從原副本核對 **86 張表完全不變**，另有七個預先加入的合成 session。允許的寫入僅為結算新版、原 revision／稽核／通知／回執、凍結碼引用與隔離 outbox。
- 舊歷史、原帳務、rowid、SQLite 儲存型別、全部原 bot rows 保留。**118 筆原 outbox**未更動；另兩筆只在隔離克隆排隊，沒有 consumer／網路投遞，沒有未同意的逐人明細或收款碼。其餘 **5 張 bot 表**完全相同。
- **4 張原圖片**、刪除紀錄 bytes、完整性與外鍵通過。原驗證資料庫沒有寫入；私人帳單、身份、群資料及原圖均留在 Git 外。

最初 harness 的權限、跨協議圖片缺省、BigInt 序列化、原時間格式及新增凍結碼表核對失敗也保留。修正驗證輸入／比較方式後重跑，不放寬服務權限、修改預期財務結果或覆寫原資料。
