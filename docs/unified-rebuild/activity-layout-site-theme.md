# 活動版面、網站名稱與主題底色

發布範圍：`web`（`frontend` + `api`）。目前完成本機驗證，尚未正式發布。

活動清單使用有邊界的卡片，手機上把日期、標題與地點、報名人數與狀態分區排列。活動詳情在較窄的內容區讓標題使用完整寬度，操作列置於下一行。人數先呈現正式報名數與最低成團門檻，補上還差幾人；有限上限與候補人數仍顯示。達到門檻只描述人數，不代替發起者確認成團或改動活動狀態。

卡片入口後續調整的發布範圍為 `web`（`frontend`）：移除箭頭與其預留欄位，將標題的原生連結點擊範圍延伸至整張卡片。保留鍵盤焦點、Enter、中鍵開新分頁與連結選單；「前往確認」保持獨立點擊與焦點。草稿編輯、活動詳情與分房分析仍沿用原來的目的網址。

四種主題各有配套的淺色／深色背景、卡片、側欄、欄位、文字與邊線；Yahha UI 使用共用顏色變數，彈窗跟隨頁面底色。報名成功等語意狀態保留原來的顏色。手機緊湊模式縮減同好卡片內距，保持文字與觸控尺寸。

管理員可在 `/admin/appearance` 的「網站外觀」修改網站名稱，限制為 1–40 字。名稱套用至網站導覽、可及性首頁標籤與瀏覽器標題。既有 PWA manifest 與已安裝的捷徑名稱未改。沿用外觀設定的管理權限、CSRF、版本核對、交易、稽核與 UUID 重播保護；反向修改回原值不算未保存變更。舊外觀回應缺少 `siteTitle` 時使用「群聚」。

網站名稱儲存在既有 `music_documents` 的獨立 `site_appearance` 類型，不新增 schema、路由或 outbox 格式，也不改活動、報名、結算、bot 設定或通知規則。Python bot 讀取的資料與深連結入口保持原狀；此次測試未投遞真實 QQ 消息。正式發布前仍須按部署政策核對當時的 API／bot 運行版本組合，不能僅替換靜態前端檔案來提供新名稱設定功能。
