# 第十批實作：舊成分找回與 QQ 授權關聯

日期：2026-11-17（Asia/Taipei）。分支：`codex/unified-rebuild`。發布範圍 **`none`**。本批只修改隔離重構程式及合成資料，沒有部署或操作正式 bot、憑證、群設定及待送工作；未放行正式切換。

## 使用流程

- 訪客與已登入、尚無成分的會員，從「我的成分」進入 `/me/music/recover`。以舊 QQ 和原來的 4–6 位數字 PIN 驗證取回權利；PIN 不能直接登入網站、建立一般會員或覆蓋已有成分。
- PIN 驗證成功建立綁定原瀏覽器 session 的十分鐘 intent，再完成**本次** QQ 授權與登入／綁定確認，最後明確確認關聯原成分。一般舊登入結果、其他瀏覽器的授權及無關 OAuth attempt 都不能替代這一步。
- 訪客沿用 QQ 對應的現有帳號，或在必要的登入確認後建立帳號；名稱註冊會員綁定目前帳號，不偷偷切換、合併另一帳號或替換原 QQ。目標帳號已有成分、已關閉、原成分有關聯或資料已變更時拒絕提交。
- 原固定成分 ID、稱呼、詞條原順序與程度、舊 QQ 查詢標識及聯絡資料保留。找回成功作廢原成分的舊 session／intent 和其他待認領證據，更新 music epoch；活動、名冊、付款責任與 bot 工作不轉移。
- 已進過空白編輯器但尚未做任何選擇的頁面，返回時讀取原成分，不再顯示空白選擇。有實際未保存選擇或未知操作時仍保留原稿，按版本規則核對，不自動覆蓋。

## 失敗、取消與安全重試

PIN 及其摘要不保存在瀏覽器；sessionStorage 只保留操作 UUID 和查詢鍵。先保存操作編號再送出，無法寫入就不送出口令。伺服器以來源 session、操作 UUID 及輸入摘要判斷同一次操作；未收到或無法解析回應時先查伺服器狀態，不自動重送 PIN。

OAuth 取消可重新授權，保留尚未過期的 PIN intent；明確取消找回不刪原成分或目前帳號。完成結果遺失可查回，關聯提交不重複寫入。切換帳號、裝置撤權、登出、帳號關閉、成分刪除、PIN／revision 變更及到期均會阻止舊證據使用。新建空白成分與進行中的找回互斥。

QQ 每小時 8 次、IP 每十五分鐘 30 次的 PIN 嘗試寫入 SQLite，錯誤 PIN 和後續業務衝突仍消耗次數，重啟不清零。使用直接連線 IP，不信任客戶端偽造的 forwarded headers；正式反向代理配置與真實流量策略仍須另外驗收。

schema 5 新增 `music_claim_attempts`、`music_claim_intents`。4→5 與成套匯入均保留有效來源 rate bucket，格式不符拒絕並回滾，不忽略舊失敗次數。後續 [schema 6](17-ownership-checkpoint.md) 另加關聯歷史；目前開發版本循序升級至 6。
