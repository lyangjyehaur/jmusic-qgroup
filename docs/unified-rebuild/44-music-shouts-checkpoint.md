## 統一入口

- 同好 `/people` → `/people/shouts`，直接發布與查閱目前內容；`/people/shouts/history` 提供歷史分頁；`/people/shouts/:id` 查詳情及聯絡資料。
- 詳情 → 發布者成分 → 成分比較 → 原詳情 → 原列表，保留安全返回白名單與原歷史分頁。聯絡 QQ 標示來源與未經騰訊驗證，複製失敗可手動選取原文。
- 同一管理後台 `/admin/shouts` 可查活躍／歷史、逐頁核對、明確確認後移除；一般會員不能使用管理 API。管理頁沿用帳號管理員與救援授權。

全部為直接 React／TSX，沒有舊 DOM 控制器、iframe 或第二套登入。頁面只保留位置、資料、操作及附近的規則／狀態／錯誤提示，沒有新增展示或裝飾文案。

## 發布、歸檔與恢復

發布使用 session 本人目前的成分 ID 與 musicEpoch，不接受查詢 QQ、偽造發布者或舊成分授權。前後端共用 Python 相容的空白正規化，依 Unicode code point 計算最多 140 字；超長內容明確拒絕，不截斷。每 24 小時一則，新發布把本人上一則移入歷史；30 天門檻保留原浮點時間比較，輸出時間沿用整數秒。

列表、詳情與管理查詢在同一立即交易內檢查權限、歸檔與讀取。歷史按原建立時間降序、同時穩定排序；發生移入時保留最近 500 則，與原 Python 邏輯一致。未發生移入時不無聲裁切既有匯入歷史。管理刪除後的冷卻沿用舊規則：檢查目前活躍內容，不把原本未用於限流的 `lastShoutAt` 改成新的永久限制。

草稿按帳號 scope／musicEpoch／成分 ID 隔離，頁內返回、離開及重整可恢復。寫入前保存內容與操作編號；回應遺失、無法解析或不確定失敗時鎖定原操作，重整後仍以同一編號確認結果，避免重複發布。管理移除亦如此，原詳情已經 404 時仍能查回原成功操作。讀不到草稿時保留原始內容，先另存恢復副本；儲存失敗時阻擋寫入。

## 遷移、隱私與 bot 保全

schema 11 將 `music_documents` 中兩類原喊話投影成獨立的內容／發布紀錄／移除紀錄表。原始副本和浮點時間保留，使用 legacy key 或原生固定 ID 對應作者；不存在的作者只顯示原稱呼，不暴露原識別。來源重複 ID、非法欄位、時間或作者歧義會中止並回滾遷移，不猜測或靜默丟資料。既有匯入工具同步建立投影，重跑仍不覆蓋後續寫入。

內容與發布者聯絡資料限已保存成分的會員，全部使用 `no-store`、scope 與現有 CSRF／來源驗證。輸出只允許內容、時間、顯示稱呼、固定成分 ID 與權威聯絡號及來源，不讀出私人留言、性別、PIN、登入 QQ 識別、token 或帳號連結。切帳號、跨分頁變更與刪除沿用全站刷新及授權撤銷，晚回應不能重建舊名單。

移除／歷史裁切同時清除原匯入副本並更新 migration map。刪除成分的 trigger 在同一交易清除本人活躍／歷史內容、最後發布時間及對應原始副本，包含以原生固定 ID 匯入、沒有 legacy profile 關聯的情況；既有持久刪除流程將發布回執改為 410，不會重建內容。管理刪除紀錄與重試回執只保留操作所需 ID／管理者參照，不複製發布者姓名、聯絡號或內容。

59 張相容表及其 DDL、原 Python bot、outbox、群設定、模板與深連結均未修改。檔案型合成庫在遷移與發布／歸檔／管理移除前後，直接以 Python `qgroup_core.accounts`、`bot_views`、`identity` 讀取；逐表核對非成分資料與既有 pending／sending／sent／failed／skipped 工作、claim、retry、simulated 欄位不變。沒有啟動實際投遞者或呼叫 QQ。
