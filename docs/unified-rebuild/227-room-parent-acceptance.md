## 修正

第一次用實際資料與固定 Python 對帳，2,314 次分析／576 次分房有 **1,328 次不一致**：其中 1,136 次分析的孤立成員 tie 與 192 次分房不同。原程式按 QQ／原會員鍵的 Unicode codepoint 順序打破同分，新程式卻按遷移後 profile／attendee ID 排序。先前合成差分的兩邊使用相同 ID，因此未涵蓋這個差異。

來源投影現在按原會員鍵建立**內部數字排序序號**。分析的孤立提示、分房種子與性別種子使用該序號；工作執行緒只收到序號，不收到 QQ／原鍵。公開 ID 不變，序號不進 HTTP 回應／分享／原稿。序號納入 source fingerprint，晚身份順序變更也會撤銷舊結果。原生未遷移成分依其穩定 ID 排序；沒有序號的純演算呼叫保留 ID 順序。

原活動成分頁還能讀取現有包間，先前新工作區漏了這個入口。現在活動概況可進入包間合拍度，試算來源包含當前預分／實際包間；實際包間優先，包括明確空陣列。工作區顯示全部現有房名與人員，按「保全草稿並載入現有包間」後保留房名及無成分者，原稿留在保全版本，重新計分後才開放分享。正式安排、付款及帳務均不因載入或計分而寫入。

若現有安排超過單次 40 房／40 人，或包含已不在目前名冊者，完整安排仍可查看，載入會給出具體原因，不截取一部分假裝成功。正式預分仍維持原 50 房限制。

實際舊帳單也揭露包間讀取不應要求新版結算編輯器全部欄位：本批新增專用的房間／凍結姓名投影驗證，供概況與試算來源讀取。原生結算編輯與金額／帳本驗證未放寬；原歷史 bytes 不變。HTTP 邊界與依賴重新審閱、更新釘選，原權限／scope／CSRF／worker 完成後重驗不變。

## 本機驗證與限制

本批 **86 個單元案例**通過：原分房差分、映射後身份同分、真 worker、隔離環境、scope／來源／取消／CPU、活動名冊／包間概況、原結算與包間恢复。新增現有預分／原帳單實際包間與空實際陣列案例；讀取／重算不改原安排。**33 個瀏覽器案例**通過，無 skip／retry／flaky；包含現有房名／無成分者載入、原稿保全、重算、分享、重新開頁及正式安排不變。

strict TypeScript、HTTP 契約／審閱 pins、前端／API／bot 建置及空庫 bundle 煙霧驗證通過。第一次建置的 Viewer 型別誤用已修正；第一次瀏覽器有一項逾時，原因是舊測試固定取第一房，而修正同分順序後移走成員使第一房為空。測試改為找仍有人員的房間，完整三份 suites 重跑通過，沒有延長時限。

目前線上來源 `07defc429d619a7558ab7218372886f531813ae3` 的 Python bot 與當前 bundle 完成 **532 次隔離 HTTP、71 次原 worker 及 9 次 TypeScript worker**，含通知／深連結、重試、未知／模擬投遞、限流與雙向接手，正常停止通過。52 個原 Python 公開來源檔及 bundle pins 保持原樣；仍是固定來源配合模擬網路，`actualProductionImageCombination=false`，不是完整 B01–B15／實際映像驗收。

私人 API harness 的早期失敗也保留：新版完整金融 schema 導致原帳單包間讀取 500，已修正為專用讀取投影；假設所有活動都可讀的 harness 拒絕，改為逐一驗證原權限拒絕，不放寬服務權限。

本批增加 6 個本機通過父項，合計 **38 個既有父項通過，128 個及 U01–U03 待完整審核**。當前固定 activation／實際 bot 映像恢復組合、固定原服務成套回退與其餘父項尚未完成；`originalP6Complete=false`、`releaseEligible=false`，不移到 P7。
