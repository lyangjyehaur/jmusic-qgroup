# 第十二批實作：管理口令重設與原關聯歷史

日期：2026-11-17（Asia/Taipei）。分支：`codex/unified-rebuild`。發布範圍 **`none`**；只修改隔離重構系統，未部署或操作正式 bot、資料與憑證。未來切換仍先按 **`both`** 準備，不能以本批合成測試批准單邊發布。

## 入口與操作

在 `/admin/music/:id` 沿用同一管理授權、成分核對與關聯操作。原數字 QQ 成分提供可展開的「重設找回口令」，平時收起；重新整理後有待確認操作或損壞的操作編號時自動展開。直接建立的帳號成分及原非數字成分不提供此入口，後端也拒絕。

管理員不需先有自己的成分。輸入 4–6 位數字新口令與重設原因，核對成分及申請人後明確確認。重設只更新找回口令，不解除或轉移關聯；已關聯成分仍不能用 PIN 取回，未關聯成分仍須完成本次 QQ 授權與最後確認，PIN 不作會員登入。

關聯與口令表單不允許在同一頁同時編輯或提交，避免混淆核對對象。口令可明確清空；離開時提示尚未送出或結果未確認，口令不保存。所有文案只提供欄位、操作、限制、狀態及恢復提示。

## 寫入與恢復

- `POST /api/v2/admin/music/:id/pin` 檢查目前管理角色／救援授權、Origin、帳號 scope、一般及管理 CSRF、明確確認、原因與 profile revision。每 IP 每分鐘最多 10 次重設請求；沒有放寬原找回的持久 QQ／IP 限流。
- PIN 摘要沿用舊版 `jpm-pin|` 計算以保持找回相容。新摘要、profile revision、該成分的找回授權撤銷、稽核與最小成功回執在同一 IMMEDIATE transaction；任一寫入失敗全部回滾。
- 撤銷該成分的未完成 PIN intents、其相關尚未使用 OAuth attempts 及匯入的舊 sessions／entry_intents，更新來源對照狀態。不撤銷一般網站登入，不修改其他成分的找回授權、現有關聯、選擇程度／順序、聯絡、帳務或 bot 設定／工作。
- 送出前，瀏覽器只保存 UUID 操作編號，依會員 scope、管理授權 scope、profile ID 隔離；不保存 PIN、摘要、完整請求或重設原因。送出後立即清空口令及確認。
- 回應無法解析、斷線、429／5xx，或成功後讀目前狀態失敗時，保留操作編號並鎖住重設輸入。重新整理不重送 PIN；明確按「查詢口令重設結果」使用 `POST …/pin-result` 查最小回執，仍須目前管理授權與兩層 CSRF。
- 查到完成後讀目前資料，不把舊成功回執重套為現在的狀態。尚無回執不代表原請求必定失敗；可稍後再查，或明確核對目前版本後重新輸入口令及確認。延遲的原請求與新請求仍受 revision 競態保護，不靜默覆蓋。
- 儲存不可寫時不送出；損壞操作紀錄先保全再清理。409 保留本頁原因，清空 PIN／確認，由管理員核對目前版本後重輸。跨刷新只保留操作編號；未送出原因不宣稱可恢復。

## 歷史與隱私

原匯入 `link_audit` 已與新關聯紀錄合流到同一「關聯變更紀錄」，每頁 50 筆。新紀錄在前，原紀錄按來源順序接續；內部分頁使用負游標銜接來源列，不改寫來源 ID／順序。API 另保留原紀錄 ID 及原秒數，頁面顯示原紀錄編號與轉換後的時間，不虛構原版沒有的原因或 revision。

原時間／ID／帳號欄位不合法時，回報 `MUSIC_HISTORY_INVALID`，來源資料仍保留。回應只含展示所需欄位，遮蔽救援憑證、舊 actor 原文及其他私人遷移欄位；有對應站內帳號的操作者顯示稱呼，否則顯示操作者類型。

schema **7** 新增 `music_pin_history`，目前共 **81** 張使用者表（59 張相容表＋22 張重構／遷移表）。重設紀錄追加保存原因、操作者、原持有人、版本與時間，不保存新／舊口令或其摘要；更新及未刪除成分的刪除均被 trigger 拒絕。6→7 保全原列、DDL、trigger 與流水號，碰撞回滾，重開不重複建立；舊版升級案例同步驗證到最新版本。

只關閉帳號時，涉及持有人或操作者的重設紀錄列入共享資料待審；刪除成分時才清理其新重設歷史，原關聯歷史仍依既有成分刪除流程清除。原 native archive、舊協議 adapter 及回退投影尚未啟用；不能讓原快照的 PIN 或關聯重新蓋回權威資料，也未宣稱這些回退能力已完成。
