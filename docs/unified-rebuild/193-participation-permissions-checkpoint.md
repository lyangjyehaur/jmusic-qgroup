## 新增驗證

`apps/api/testsupport/participation-permission-matrix.test.ts` 使用獨立宣告的預期權限，測試實際 HTTP handler。14 種身份與公開／邀請活動組成 28 個交叉案例：發起者、實際代理、由他人代理的參加者、四種單獨活動職責協辦、名單與出席協辦、只獲查看權的會員、管理員、獲查看權的管理員、無關會員、訪客及未登入者。

交叉案例核對逐人報名、補報名邀請及認領的讀取投影、本人／代理標記、token 可見性、可決定及可撤銷標記。使用有效 body 嘗試越權寫入，斷言具體的 401／403／404，不把輸入錯誤當作權限驗證成功。每批讀取及每次拒絕操作都比對全部使用者資料表，不能留下部分寫入或額外通知。每個 fixture 使用自己擁有的 `:memory:` 資料庫、synthetic session 與停用 bot。

另外 26 個案例涵蓋：

- 16 個符合身份與資料狀態的逐人編輯、確認、拆分、退出及退出審核操作；相同 UUID 重播與收據查詢保留原結果、不重複寫入。
- 即使仍為實際代理，撤銷名單職責後也不能重播退出審核或讀取原審核收據；變更實際代理後，舊代理不能重播編輯或讀取其收據。
- 邀請與認領 token 有各自有限的查看／操作協定，不能一律以私人活動查看權阻擋。接受邀請授予查看權；之後移轉代理或撤銷查看權會阻擋接受重播。
- 私人活動的認領申請不授予查看權；核准後才授予查看權並移轉代理，保留原付款責任。
- 保留既有核准收據例外：原代理可以恢復已完成決定的最小結果，但不能作新決定；撤銷私人查看權也會阻擋這份恢復。
- token 發行者不再是實際代理或名單協辦時，原認領 token 失效。
