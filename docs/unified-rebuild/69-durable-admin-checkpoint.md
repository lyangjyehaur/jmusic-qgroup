# 第六十三批實作：管理原稿與權限失效保全

日期：2026-11-18（Asia/Taipei）。分支 `codex/unified-rebuild`。變更範圍 **`web`**，實際發布範圍 **`none`**。只修改 React 表單、共用本機儲存與隔離測試；API、schema、outbox、共用業務核心、bot 指令／政策／模板與原網址不變。保留 Python bot，未推送、未合入 main、未部署，未操作正式憑證、群設定、資料庫或真實待送工作。

## 管理原稿

使用者管理的內部備註、人工 QQ、角色命令，以及刪除申請審核的處理說明改接 `useDurableRecord`／IndexedDB。保留原 v1 key 與 payload：`viewer.scope`、`access.scope`、固定帳號／申請 ID、revision，以及 `pending.kind`／`pending.input`／UUID，不換對象或重新產生待確認命令。白名單只新增 `admin-user` 與 `admin-privacy` 兩類帶完整帳號／管理授權 scope 的 key。

提交前必須等 pending 整筆本機交易完成；同步 busy guard 防止連點，提交前卸載不發 HTTP。明確拒絕也先保存移除 pending 的狀態才解鎖。伺服器接受後，本機確認保存或後續讀取失敗均保留原操作；關頁後可由統一收件匣回原頁明確查回，原 UUID、body 與管理授權均不變。角色操作成功不會順便送出或覆蓋尚未保存的私人備註／人工 QQ。

未提交原稿重開後須明確恢復；恢復、讀取衝突、載入保全版本或核對目前資料都清除當次授權／審核確認勾選。已建立的 pending 保留原 `confirm:true` 命令，用於核對原操作，不能把它當成一筆新授權。不同裝置的伺服器 revision 衝突仍要求重新核對；同瀏覽器的分頁衝突則先保存雙方原稿，提供下載與明確載入。

## 權限失效與清除

本機 `epochs` store 增加依帳號 scope 的管理清除世代，不變更 IndexedDB 版本。管理原稿的保存、保全替換與 retire 都檢查管理世代；清除與世代遞增在同一筆交易，防止沒有 BroadcastChannel 的舊分頁重新建立原稿或保全版本。世代遞增後也不再匯入舊分頁留下的管理 session 原稿。

管理入口收到 401／403 後卸載管理畫面、移除管理私人查詢快取，並清除該帳號全部管理原稿及保全版本，再提供救援登入。其他帳號的管理原稿與目前帳號的一般會員原稿保留。清除失敗顯示具體提示及本機重試；不重送角色變更、審核或登出命令。分頁儲存清除失敗也會回報，同時仍嘗試持久庫清除與世代阻擋。

會員角色管理員登出仍清除整個裝置的原稿；救援管理登出保留會員登入，由失效管理入口負責該 scope 的清除與重試。未知登出結果先查目前狀態，不重送登出。更換救援授權後的新管理 scope 不會載入或重送前一授權的 pending。

救援憑證、PIN、裝置 token、OAuth 內容、管理 CSRF 及隱私收據 secret 均未新增到原稿庫；原確認命令只有既有業務欄位。管理成分關聯、詞庫／bot／外觀等表單與含憑證流程尚未完成遷移，不能因本批白名單擴充而整包匯入。

新增 `durable-admin.spec.ts`，涵蓋 metadata／role／privacy 三種命令的關頁收件匣查回、成功後確認交易 abort、pending 交易 abort 不發 HTTP；兩種私人原稿的明確恢復與確認重設、雙分頁保全／下載／360px；真實角色撤銷後無分頁訊號的阻擋與會員原稿保留；救援登出清除 abort／重試、其他帳號保留與舊保全替換阻擋；兩種原 session pending 的失敗保全及逐欄遷移；救援授權更換不跨 scope 重送。
