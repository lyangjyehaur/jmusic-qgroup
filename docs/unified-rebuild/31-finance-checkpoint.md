# 第二十五批實作：統一收付款帳本

日期：2026-11-17（Asia/Taipei）。分支 `codex/unified-rebuild`。發布範圍 **`none`**：本機隔離實作、驗證與原始碼同步，未部署、未整合 main。款項、通知及 bot 網址為跨服務依賴，正式切換仍先按 **`both`** 驗證，保留 Python bot。

## 入口與功能

React／TSX 的 `/activities/:id/finance` 整合目前應付、本人補退款、店家支出、未退訂金、代收資金、逐付款人／包間核對、私人申報、已確認帳本與操作表單。活動頁、收件匣款項待辦、舊 `/?event=…&action=finance` 與活動 `?task=finance` 都進入同一帳本；開啟不提交任何操作，訪客可讀公開活動的已確認款項，登入返回保留原帳本。完整款項表單預設收合，有未完成或損壞原稿時自動展開；沒有可查看申報時不保留空卡片。

原生 TypeScript API：

- `GET /api/v2/activities/:id/finance?before=…&before_report=…`：活動存取驗證、公開帳本、本人或結算管理者的申報、穩定款項人員、可用原支出／訂金引用及結清阻擋原因。
- `POST /api/v2/activities/:id/finance/preview`：嚴格驗證現行活動 revision、操作、金額、人員、引用、時間、權限及投影，產生綁定正規化內容與 revision 的 SHA-256 預覽。
- `POST /api/v2/activities/:id/finance`：重新核對權限與預覽，立即交易一次追加資料、稽核、站內通知與精確回執。

十種款項全部保留：collection、refund、reimbursement、expense、merchant_refund、deposit、deposit_return、deposit_apply、credit_transfer、cash_transfer。八種操作全部保留：申報、直接登記、確認申報、退回、本人撤回、沖正、結清及重新核對。

金額維持整數分、正額、最多七位整數與兩位小數；必須是帶時區的實際時間且不可在將來。備註與依據按 Unicode 字元長度驗證。實際轉／收款人與款項歸屬分開，代付不同人時須依據；個人墊退、活動代收資金、店家退款、訂金抵消費及款項歸屬更正各自保留流向，不會自動發起付款。

結算人可建立最多兩個本次實際使用的其他款項人員。ID 穩定、同名不合併；活動會員鍵、未綁同行鍵、原付款責任、歷史帳單的付款人／收款人／其他人員與所有款項快照持續保留。代報、認領、更名、退出、管理交接不改寫舊款項。管理同行可代申報，但同行欠款不冒充管理人本人欠款。

## 帳本與隱私

沿用既有 finance_entries、finance_reports、finance_report_actions 與追加式觸發器，沒有 schema 遷移。申報先列待核對，不計入現金帳本；最多每人 20 筆／活動 500 筆待核對。管理者確認時直接採用原申報凍結內容，不按目前姓名或重新輸入金額取代。退回須原因，撤回僅原申報者。已決定申報不可重決。

私人申報只給原申報者與目前具有 settlement scope 者；公開 API 不回 actor_id／reporter_id。report／reject／withdraw 稽核不存 transaction 與私密原因；已確認款項則在活動帳本公開實際金額與依據。資料序列化按明確欄位挑選，不回傳任意匯入 JSON。網站管理員不自動取得私人活動或結算 scope。

已確認款項只能追加沖正，不 UPDATE／DELETE。已退款／抵扣關聯須先逐筆沖正後續依賴，禁止超過原剩餘額、負投入、負代收資金及破壞守恆。結清須詳細帳單、逐人義務、各包間店家淨消費、訂金、代收資金與待核對申報全部對平；close 凍結本版帳單與帳本序號。新款、申報、沖正或改帳會依現況重新待核對，不因舊 close 永久關閉。

包間使用同一 journal 分開投影；禁止跨包間花代收資金、退款、引用或淨抵。各房列應付／投入／差額與人到人的轉款，另按收款人加總待收款，保留原逐房明細；管理者自己的包間應付仍顯示在差額中。

獨立分頁各 100 筆已確認記錄及已處理申報，待核對申報只在申報首頁附上；續頁不重複。API seq、cursor 與 last_seq 使用十進位字串，內部 BigInt／SQL 整數比較，超過 JavaScript safe integer 仍不丟位。close 的資料庫 payload 保持舊 Python 的數值檢查點與相同預覽 hash，wire 回字串。游標輸入延續來源 1–18 位正整數限制。詳細帳單中的店家退款／減免可為負費用項，總應付仍按原帳單，不把合法折扣當資料損壞。

## 草稿、恢復與資料更新

同頁先預覽、確認後提交，修改欄位清除預覽與確認。409 保留原額、人員、時間及依據；明確讀取最新資料後重新預覽，不靜默改 revision 重送。每次寫入須會員、同源、scope、CSRF、UUID；回放回執前仍重新核對目前活動存取與命令權限。

送出前保存精確原操作及 UUID。未知結果經重整仍鎖住原操作，由使用者明確確認同內容與同編號；不因看到頁面、待辦或恢復清單自動送出。儲存失敗阻擋寫入；損壞原稿先保全副本，不覆蓋。未完整填寫的金額、原因與其他款項人員仍能保存。恢復清單新增帳本入口，清單只查回執存在，不顯示原款項內容。

帳號 scope 隔離 query 與 sessionStorage，跨頁登出清除帳本原稿，延遲成功不補回前帳號資料。完成款項後更新帳本，失效收件匣待辦／未讀數與活動歷史。兩個歷史續頁各自重試，保留已載入資料。

## bot 相容性

新增原生 finance_closed／finance_reopened 群卡及 finance_updated 個人通知，保留舊文字、rich template context、按鈕深連結、群政策、去重與已凍結 payload。明確 reopen 以及 closed → collecting 的隱含變動都送重新核對卡；未開群同步或非公開活動不產生公開卡。站內通知仍按 owner／settlement scopes、交易付款人與原申報者通知，排除操作者；私人 bot 通知只含通用提示與活動連結，不含姓名、金額或申報備註。

可選 bot hook 使用巢狀交易隔離，失敗不撤銷款項、站內通知、稽核或回執；必要業務／稽核／回執失敗則全部回滾。這沿用現有相容性模式，不宣稱可選通知失敗已有自動重建。

以合成 SQLite 產生新結清、重開與私人通知，實際保留的 Python OutboxWorker 經 Mock transport 消費公開卡一次、再次無重播；未綁定個人通知仍保留既有處理語意。沒有連正式 QQ、操作正式 bot／群設定、憑證或真實待送工作。與 Python 逐項比對十種款項預覽／每筆前綴投影、完整摘要、結清 hash、群卡文字／模板／按鈕及原 worker 消費。
