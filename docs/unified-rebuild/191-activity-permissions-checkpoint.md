## 交叉驗證

新增 `apps/api/testsupport/activity-permission-matrix.test.ts`，以獨立宣告的預期權限測試實際 HTTP handler，不使用 production guard 或 `eventScopes` 計算預期結果。每個案例建立自己擁有的 `:memory:` 資料庫與 Fastify app；bot 維持停用，沒有正式資料、憑證或真實投遞。

每個組合檢查名冊、安排確認、款項、安排編輯、出席、生命週期、管理分工及草稿八個讀取入口；同時檢查名冊的本人／代理標記、只屬於目前代理的安排確認人員、款項管理權限、生命週期動作，以及只有發起者可取得的管理邀請與目標。管理員協助修改安排不等於擁有其他活動職責；救援登入不會把訪客變成會員。

使用有效 body 嘗試沒有權限的安排、生命週期、出席、現場補錄、個人安排確認、補報名邀請、款項及管理邀請操作。斷言具體的 401／403／404，拒絕把 `INVALID_INPUT` 當成成功的權限驗證。每批讀取及每次拒絕操作都比對全部使用者資料表，涵蓋操作收據、名冊、安排、帳務、通知和 bot 工作，不能留下部分寫入。

另外 32 個案例檢查合法操作、撤權與狀態限制：

- 安排、草稿、暫停報名、補報名邀請、出席、現場補錄及款項登記可由正確身份完成；相同 UUID 重播返回原結果且不重複寫入。
- 撤銷 schedule 或私人查看權後，原安排寫入與結果查詢分別回傳 403／404；單獨保留活動職責不授予私人活動查看權，單獨查看白名單不授予草稿查看權。
- 變更實際代理後，舊代理不能重播安排確認或查回原收據；發起者、名單協辦及管理員也不能代替目前代理確認。
- 所有權變更後，原發起者不能重播 owner 動作或取得其操作結果。出席及款項職責撤銷後，原寫入收據不能越權重播。
- 現場補錄同時需要 roster 與 attendance。歸檔阻擋安排及出席修改；已有結算阻擋安排改寫及現場補錄，但不阻擋解除歸檔後的出席核對。
- 保留已刪除活動的例外：實際發起者仍可讀取生命週期以恢復移除結果；其他入口及其他身份不能查看。沒有把刪除狀態一律改成相同結果。
