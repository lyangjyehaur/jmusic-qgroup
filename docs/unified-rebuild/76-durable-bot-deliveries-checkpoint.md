# 第七十批實作：群通知原重送操作持久化

日期：2026-11-18（Asia/Taipei）。分支 `codex/unified-rebuild`。變更範圍 **`web`**，實際發布範圍 **`none`**。未合入 main、未部署，未接觸正式資料、憑證、群設定或 bot 工作。

## 原命令與授權入口

活動／時間投票的手動重送改用共用 IndexedDB 紀錄，沿用原本 scoped session key 與原 `{id,key,input:{reviewToken,confirm:true}}`。保存完整交易完成後才送出；關閉分頁後能從收件匣「群通知重送」回原業務入口。收件匣只顯示操作類別與固定路徑，不顯示 review token、通知內容或目標群；泛用回執查詢使用成員 `/me/operations/:key`，不混入管理回執。

重送權限仍由活動／投票業務規則決定，管理員投遞紀錄頁維持唯讀，沒有建立 durable 重送紀錄。權限變更後隱藏私人通知內容並禁止操作；不再直接刪除仍待確認的原命令。其他帳號無法取得該 scoped 操作；登出完成後清除紀錄，沒有 BroadcastChannel 的舊頁也不能重新發送。

原紀錄路徑僅接受目前帳號的活動或投票通知入口，要求 canonical 編碼與長度，排除任意 URL、query／hash、額外路徑、異常編碼及 dot segments。損壞命令保留原文，可保全下載，但不能視為可送出的新命令。

## 中斷、競爭與回執

查回先以本機 CAS／清除世代確認原命令仍有效，再 GET 原回執。已有回執時只核對原通知 ID、業務類型及活動／投票 ID，保存本機完成狀態，不重送 POST。不符的回執保留原命令並提示核對。

查無回執時須明確選擇「以原操作編號重送」；送出前再次查回，且使用完全相同的 UUID／body。政策、目標或通知變更由原 review token 驗證拒絕，不替換成新版 token。已接受的模擬命令遇到後續實送政策，只查回原結果，不另外排入一筆實送工作。

put 成功但交易 abort 時不發 HTTP。接受結果或明確拒絕後的本機確認交易失敗，仍保留原命令，待下次核對。雙分頁衝突保全競爭命令並阻擋第二個 HTTP，讀取已保存版本後清除舊確認及重送選項。舊 session 紀錄在 durable 遷移提交後才刪除；遷移 abort 保留來源，不自動重送。
