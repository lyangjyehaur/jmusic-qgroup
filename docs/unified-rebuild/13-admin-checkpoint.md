# 第七批實作：統一管理、角色與刪除申請審核

日期：2026-11-17（Asia/Taipei）。分支：`codex/unified-rebuild`。發布範圍 **`none`**。本批推進 A01–A04／A08 與 I14／I15 的管理邊界；所有操作限於隔離開發程式與合成資料。未部署、未變更正式 bot、憑證、群設定、資料庫或真實 outbox。166 項能力仍未完整驗收，不具備正式切換資格。

## 管理入口與授權

`/admin` 是共用後台入口，連至 `/admin/users`、`/admin/registration` 及 `/admin/privacy`。會員角色和獨立救援憑證共用授權模組，不要求管理員先建立成分。

- 每次私有讀取重新確認目前裝置、帳號 scope 與有效角色／救援 session；寫入再檢查 Origin、會員／訪客 CSRF 及管理 CSRF。會員角色優先，與舊 Python 相同。角色版本、裝置或帳號變更後，舊 CSRF／操作授權不可沿用；撤銷後重新授權也不重播原授權的寫入回執。
- 救援憑證只接受隔離入口的 `REBUILD_ADMIN_KEY_HASH`，值為小寫 SHA-256 hex；未配置不影響帳號管理員。沒有讀取或回退至正式 `KANBAN_ADMIN_KEY_HASH`。執行中的 callback 每次讀取程序設定；修改外部環境檔仍需由啟動流程載入，不宣稱 `.env` 熱更新。
- 救援登入限制每 IP 每分鐘 6 次，要求明確確認，建立獨立一小時 HttpOnly／SameSite=Lax cookie；HTTPS 下加 Secure。資料庫僅存 session token hash 及配置摘要，不新增會員。配置摘要輪替或 session 到期立即拒絕。對舊 ISO `+00:00` 到期時間採時間解析比較。
- 憑證不存瀏覽器 storage，任何登入嘗試後清空欄位；結果不明時停止重送憑證，先檢查實際管理狀態。
- 登出救援管理保留會員登入；帳號管理員登出撤銷本裝置全部會員 grant，並清除救援 session，其他裝置不受影響。會員登出與獨立救援登入仍是不同授權；一般會員登出不代替專用管理登出。
- 帳號管理登出直接發行單一訪客 session，避免兩分頁同時刷新各自建立不同訪客 cookie。先刷新 session，再清理／重設管理查詢，避免舊 scope 或已移除的活躍查詢使後台停留於舊授權。登出回應不明時，明確重新確認 session／管理狀態，不重複登出。

## 使用者、角色與私人備註

`GET /api/v2/admin/users` 每頁 20 筆；可按稱呼、站內 ID、第三方暱稱、內部備註與人工 QQ 搜尋，並篩選已取得 UnionID／已綁 QQ 但缺少 UnionID／未綁 QQ。身份狀態按完整 provider／client／subject 關係判斷，避免不同 app 的相同 subject 誤配。不輸出 OpenID、UnionID 原值、client ID、登入 token 或憑證摘要；已關閉帳號不列入可管理名單。

`/admin/users/:id` 分開處理角色 revision 與 metadata revision。所有變更需 UUID 操作編號，在 immediate 交易中重新授權、比較版本、寫入與記錄最小回執；角色及不可變角色歷史同交易。禁止帳號管理員自撤、對已關閉帳號授權，以及用舊版本覆蓋其他管理員的修改。角色歷史每頁 50 筆，可讀取更早紀錄；操作人投影為帳號稱呼／帳號關閉／救援憑證，不外洩 credential digest。

人工 QQ 可以留空或填 5–12 位、不以 0 開頭的 ASCII 數字，具唯一檢查；內部備註最多 1000 個 Unicode code point。兩者僅後台可見，不改變 QQ 身份、UnionID、登入或成分 ownership；沒有以手填 QQ 自動認領／合併資料。按原文安全顯示，HTML 不執行。

## 刪除申請與真實保留範圍

`/admin/privacy` 分頁列出全部帳號刪除申請，沒有沿用舊清單最多 100 筆的截斷。`/admin/privacy/:id` 顯示申請、時間、內部處理說明及目前仍關聯該帳號的共享紀錄種類／數量；不出私人選擇、收據秘密或完整活動／帳務內容。

- `POST /api/v2/admin/privacy/:id/review` 要求 1–1000 字處理說明、確認、讀取版本及 UUID 操作編號。版本同時涵蓋申請資料及即時共享紀錄計數；其他管理頁或保留範圍變更均須重新核對。
- 不接受 client-supplied status。只要已知共享紀錄仍存在，讀取與保存結果均是 `shared_review`，即使舊列誤存 completed 也不顯示已完成。無共享關聯時，記錄說明後才可更新為 completed。
- 除原看板檢查與新版帳號／角色／成分歷史外，也檢查 `bot_outbox.recipient_user_id`。只剩私人通知收件人關聯時仍阻擋完成；審核不改動或重播 outbox。
- 保存處理說明不刪除活動、名冊、帳務或不可變歷史，不新增「勾選全部已刪除」的捷徑。依原版語意保留最新處理說明及更新時間；完整審核歷史／選擇性共享資料處理尚未建立，不能把本頁當作資料清除工具。
- 刪除收據保留的是當次不可逆操作的結果；管理申請顯示目前審核狀態。沒有在審核時重寫原收據或外部 erasure ledger。

## 草稿與錯誤恢復

角色／備註與隱私審核各有綁定 viewer scope、管理授權 scope、目標 ID 的分頁草稿。送出前先持久保存原內容與操作 key；結果不明時鎖住編輯，刷新後只安全重試原操作，再讀目前資料。衝突保留輸入，必須明確讀取目前狀態並再次確認，不能自動覆蓋。

storage 無法寫入時不送出；損壞草稿保留原始資料，使用者可先保全再繼續。離頁與關閉分頁提示未保存／待確認操作。權限失效、管理登出及本裝置登出清理私有管理草稿與恢復副本；跨分頁同步清理。新管理 session 不自動重播舊管理授權的 pending operation。查詢快取按管理 scope 分離，保存後更新目前資料，返回頁面不再從舊快取誤判未保存內容。
