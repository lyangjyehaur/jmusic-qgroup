## 修正原文字與斷線保存

原 Python `strip()` 與 JS `trim()` 對 NEL／record separator／BOM 的處理不同。結算費用名稱、人員原因、自訂付款人、備註、店家資料及收款碼名稱改用既有 `originalString`；隨單 expense 的財務契約使用同一規則，避免第二次裁掉 BOM。原程式接受的名稱內部換行與 NUL 沒有另加禁止條件；長度及其他功能限制照原規則。

收款碼表單傳原輸入交給共用契約處理；pending 紀錄以同一契約核對名稱，不自行 trim。BOM 名稱的未知保存結果重載後保留原 body／UUID，僅查回，不自動重送。原 Python 的 raw payload／預覽憑證／簽名亦保全。沒有新增展示文案。
