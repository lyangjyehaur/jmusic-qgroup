# 第六十二批實作：帳號與成分原稿持久化

日期：2026-11-18（Asia/Taipei）。分支 `codex/unified-rebuild`。變更範圍 **`web`**，實際發布範圍 **`none`**。只修改 React 前端、共同本機儲存與隔離測試；API、schema、outbox、bot 指令、政策、模板及原入口不變。保留 Python bot；未推送、未合入 main、未部署，未操作正式資料、憑證、群設定或真實待送工作。

## 本批範圍

以下表單改接 `useDurableRecord` 與共用 IndexedDB，保留原 v1 payload、欄位內容、基準 revision 及未知結果請求格式：

- 帳號稱呼：稱呼、revision、原 `requestKey`，以及最新稱呼核對、跨頁帳號顯示更新與歷史。
- 聯絡 QQ：固定 profile ID、music epoch、revision、原號碼與 `requestKey`；保留無效未完成輸入，送出時仍按原規則驗證。舊成分 QQ 的唯讀限制、查詢及複製功能不變。
- 成分資料：稱呼、私人留言、自訂／內建性別、公開選擇及原 `pending.input`；不截短舊資料。性別公開是原稿的實際欄位，恢復時保留，不能當成臨時確認勾選清掉。
- 共用成分選擇：原 profile ID／music epoch／revision、選取順序、熟悉度及 `requestKey`。詞庫、排行、詞條詳情、我的成分與分享仍使用同一個工作區，5／15／20 上限、搜尋、返回活動／同好及既有選取動線不變。

共同 hook 的 `blocking` 增加 React Router predicate 支援；既有 boolean 預設行為保留。工作區內導覽保留同一份記憶體與保存中的請求，離開工作區則等待原稿佇列完成後離站。恢復／保全控制集中在工作區，詞庫或詳情入口同樣可處理，不重複建立 blocker。修正只留在此分頁的過時提示；未送出原稿重新開頁須明確恢復，分享也等待恢復或保全完成。

## 交易與身分

每次編輯依序保存，提交前等待整筆 pending 本機交易完成；同步 busy guard 防止連點，保存期間卸載不送出。伺服器明確拒絕也須先保存移除 pending 的狀態才解鎖；接受成功而本機確認保存失敗則保留原 key／body，從新分頁收件匣明確查回。

帳號稱呼與成分原稿各自隔離。成分資料／聯絡 QQ 載入時檢查原稿及內層命令的固定對象與 epoch；不符就鎖定並保全原稿，不能拿新成分 ID 代換後送出。所有原稿仍由裝置／成分清除世代阻擋晚到寫入，沒有 BroadcastChannel 也不能在刪除後重建原稿。只刪成分不刪帳號稱呼原稿。

成分選擇首次建立時的 null profile ID 有不同語意：同 epoch 的另一裝置或自建詞條可能已先建立帳號的成分。保留原 null target 與輸入，只有明確核對最新版本才接到該成分；已有固定 ID 或 epoch 不符不得接到替代成分。沒有修改後端驗權或幂等鍵的作用範圍。

成分選擇的未知結果在查回原操作後重新讀取目前伺服器資料，與稱呼／聯絡／資料表單一致；若成分已再次變更，顯示目前內容及結果提示，不把舊 receipt 的選取快照當成最新成分。

白名單只新增帳號稱呼、成分選擇及帶 scope／epoch／profile ID 的資料與聯絡原稿。PIN、OAuth／救援憑證、裝置 token 及隱私收據 secret 仍不進持久原稿庫。私人原稿存於同源本機，沿用明確恢復、衝突保全、版本下載及登出清除規則，並非加密儲存。

## 驗證
