# 保留舊版詞條變動懸浮儲存列

日期：2026-11-25。發布範圍：`web`。僅前端互動及樣式，沒有修改 API、schema、bot 或正式環境；尚未提交、推送或部署。

依使用者明確偏好，沿用舊版 `ui/music/SelectionPanel.tsx` 的 `MusicTools` 交互：詞條選擇有變動時持續顯示固定儲存列，直到明確保存成功或恢復原選擇。保留目前原型的共用元件、配色及布局。

`MusicSaveDock` 直接使用既有 `MusicSelection`，沒有第二份選擇資料或新的保存機制。勾選、取消、調整細分程度均觸發；領域不新增喜歡程度。詞庫、同好、搜尋、分享與趨勢等共用工作區之間維持同一份原稿，不因導航自動送出。

桌面固定於內容區下方；手機置於底部導覽及鍵盤避讓區上方。對話框把儲存列放進獨立頁尾，只捲動內容區，保留返回與編輯入口，避免背景的固定列被 inert 或焦點限制擋住。同一時間只有一個懸浮儲存列；既有側欄及詞條內的明確儲存操作保留，移除原先僅在手機成分編輯頁顯示的重複固定列。

保存失敗時保留懸浮列；結果不明時沿用原操作編號確認，沒有建立新的重送。原稿無法保存時不送出 API。成功訊息在工作區顯示，成功後收起懸浮列。回到頂部按鈕和頁尾留白依懸浮列實際高度避讓。

驗證：

- 最終 `npm run build:rebuild` 通過。
- 原型直接接入、共用工作區整合及懸浮列相關 17 個瀏覽器案例同一輪全部通過。
- 新增案例涵蓋桌面／手機捲動、跨頁、搜尋及詞條對話框、程度調整、恢復原選擇、明確保存成功、本機保存失敗不發送，以及回應中斷後以同一 UUID／內容重試。
- 手機導覽與回到頂部不被遮擋；對話框頁尾不橫向溢出，保存及返回控制保持在視窗內。檢視實拍時另修正手機頁尾 flex 方向及桌面對話框整體捲動造成返回操作不可見的問題；最終案例明確驗證這些幾何限制。

## 實際頁面更新與背景原稿提示修正

使用者回報外部勾選仍看不到懸浮列，以及每次勾選都使布局抖動。直接檢查現有瀏覽器後確認：頁面仍執行上一版資源，只有舊的列表底部摘要；先前僅更新服務端與隔離測試，沒有完成使用者當前頁面的更新，不能視為交付完成。

透過既有「保留草稿並離開」保存當前原稿，再從應用程式設定頁安全重新載入，核對實際 script URL 與本機建置一致。返回原網址並恢復原稿後，18 個原有未保存選擇逐項相符，頁面已實際顯示固定儲存列。沒有將使用者選擇提交至後端。

`MusicWorkspaceFeedback` 將被動本機原稿進度設為安靜顯示，避免每次選擇插入和移除一行進度文字。其他表單仍沿用原有預設；本機保存失敗、原稿損壞、衝突、恢復及伺服器結果不明提示保留。

回歸新增逐畫面位置採樣與 DOM 變動檢查：直接在列表勾選時，頁首及首列位置差異不超過 1px，沒有插入「正在保存本機原稿」；桌面、手機與共用工作區共 9 個案例全部通過。建置及 diff check 通過。

另在使用者正在使用的資料複本頁面直接勾選／取消同一詞條，懸浮列即時由 18 更新為 19 再回到 18；頁首及首列的文件座標均保持不變，原有未保存選擇完整保留。此段後續驗證取代前述「尚未重新載入」的狀態。本輪仍為 `web`，尚未部署。

## 回饋顯示的最終規格與整個保存流程驗證

後續回報揭露前述量測仍漏掉成功回饋。完整檢查另外找到：成功訊息在主內容插入段落、列表底部依 dirty 增刪整塊摘要、儲存列依可見狀態改變主內容 padding、恢復／版本提示在主內容流，以及對話框頁尾依保存狀態改變高度。先前只覆蓋勾選瞬間，不能證明完整保存流程穩定。

最終實作將所有成分操作回饋集中在 `FeedbackLayer`，一般頁面使用固定浮層，對話框使用其內部的絕對定位浮層。成功確認四秒後消失，錯誤、結果不明、原稿損壞、恢復與保全操作持續可用；都不在頁首與列表之間插入提示列。本機被動原稿進度仍安靜執行。

列表底部不再增刪重複的完整摘要；固定儲存列提供「檢查我的選擇」入口，完整編輯器保留還原及核對最新版。主內容的尾部避讓空間從進入工作區起保持固定，不隨顯示／收起變動。對話框的儲存列脫離頁尾排版流，頁尾位置以實際高度量測；編輯器的還原／核對控制保持位置，只切換可用狀態。更新與離線提示也移至浮動區，並避讓儲存列及回到頂部按鈕。

驗證以逐畫面採樣涵蓋勾選、送出中、成功出現與四秒消失、離線提示出現／消失、重新載入後恢復原稿，以及儲存失敗和對話框內的結果不明重試。受測頁首／詞條列或對話框標題／內容的座標變化不超過 1px，並核對沒有瀏覽器錯誤。首次恢復量測在延遲頁面載入前抓到空節點；修正為等待受測內容可見，不放寬位移限制。
