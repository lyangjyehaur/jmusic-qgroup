# 第三十批實作：音樂詞庫與會員自建詞條

日期：2026-11-17（Asia/Taipei）。分支 `codex/unified-rebuild`。發布範圍 **`none`**：只有本機實作、隔離驗證及原始碼同步，不部署、不整合 main。保留 Python bot；本批不更動其程式、群政策、outbox、正式音樂資料或憑證。完整 bot 詞庫查詢改用新權威資料及混合版本驗收仍是正式切換前的必要工作，不能據此單獨上線新版網站。

## 同一份詞庫與管理入口

`/music` 使用原生 TS API 顯示領域／細分、分類、選用人數、名稱／別名、建立者稱呼，兩類依實際選用人數分榜排列。分類篩選只列目前詞庫實際存在的分類，不憑空補出分類。相同人數依 Python 的 Unicode 字元順序排序，不依執行主機語系改變順序。計數包含仍保留的未關聯成分，排除已刪除成分。

名稱與別名搜尋支援 NFKC、零寬移除、Python whitespace 及 casefold；有類型／分類篩選、清空與 `/` 聚焦快捷鍵。搜尋條件和所開詞條使用 URL 參數，重新整理仍保留；`?entry=…`可從重名提示直接找到既有詞條。詞條顯示保留使用者原文，不把名稱或別名轉換成簡繁。完整拼音／首字母／假名搜尋、氣泡與誰選了仍待後續實作。

`/me/music/entries` 列出目前成分有建立者權限的詞條、原分類／別名、即時選用人數及建立數限額；由此進入建立、編輯及刪除頁。音樂與我的成分都直接連到同一管理入口，保留原選擇草稿。建立詞條不會自動選取，也不覆寫成分選擇。尚無成分時，經明確建立操作同時建立空白成分；正在找回舊成分時禁止悄悄建立新成分。

## 原生規則與原資料保全

- 領域最多自建 2 個、細分最多 8 個；建立上限依原會員 `created` 清單計算，新詞條以穩定成分 ID 記錄。原清單與 `createdBy` 不是同一種資料，不擅自合併成單一來源。已刪除詞條不再占用額度。
- 只有目前擁有該成分且符合詞條建立者的會員可編輯／刪除；保留匯入的舊建立者鍵，不以聯絡 QQ、姓名或 body 的 user ID 授權。成分移交後，舊帳號不能再修改，新的成分擁有者延續原建立者權限。管理員完整詞庫維護另行實作。
- 名稱依 Python whitespace 整理，須為 1–24 個 Unicode 字元，拒絕控制字元與正規化後空白；超長明確拒絕，不悄悄截斷。跨領域／細分、名稱與所有既有別名一起查重，提示指向既有詞條。改名不刪除原別名。
- `kind` 與 `category` 分開保存；原分類與原文可原樣保留。新建領域沿用原 `领域` 分類；改類型保留既有選擇、熟悉度與順序，不強行改寫所有成分，也不新增來源沒有的改類型配額限制。原本因改類型而超出的建立數仍如實顯示；後續新建再按當前類型計數。
- 有任何仍使用該詞條的成分就不能由建立者刪除，伺服器在同一 immediate 交易重新核對，不能只相信頁面顯示的人數。沒有選用者時只刪詞條和對應建立清單項目，不改他人的成分。

## 交易、競態與未知結果

`GET /api/v2/music/catalog` 只回公開欄位，不傳回原建立者鍵、QQ、user ID、session、PIN 或私人資料。`GET /api/v2/me/music/entries` 要求有效會員及 account scope。`POST` 同一路徑使用嚴格 create／update／delete 契約、同源／CSRF、UUID、成分 ID／epoch 及詞條內容版本核對。

詞條、必要的首次空白成分、原建立清單和回執同一交易完成；回執失敗全部回滾。回執綁定成分，成分刪除後改為 410，不因重試重建詞條或原成分。刪成分保留公共詞條與別人的選擇，同時清除新詞條的建立者關聯；舊建立者的匿名化沿用原規則。不新增 schema 或修改原 bot 資料表。

每份 React 原稿按 scope 與操作目標保存於 `qgroup:rebuild:music:entries:v1:…`，送出前先保存完整原 body 與 UUID。建立／改名／刪除回應不明，重整或收件匣都只提供明確恢復入口，不自動重送；明確查回後再讀目前詞條，避免以舊回執覆蓋新名稱。競態保留輸入，重新核對版本後須再次確認。損壞原稿先保全；儲存拒絕時不送出。帳號切換不混用原稿，登出及成分刪除清除相關原稿。

保存成分後使詞庫與本人詞條人數失效重讀，避免沿用舊的刪除提示；伺服器仍再次驗證。詞條寫入後也更新基本選擇詞庫，已選草稿不被覆蓋。
