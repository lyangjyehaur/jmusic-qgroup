# 第二十七批實作：逐人結算與實際包間

日期：2026-11-17（Asia/Taipei）。分支 `codex/unified-rebuild`。發布範圍 **`none`**：本機實作、隔離測試及雙邊原始碼同步，未部署、未整合 main。結算、帳本、凍結圖片與 outbox 涉及 web／bot 契約；正式切換仍須按 **`both`** 驗證，保留 Python bot。

## 操作入口

- `/activities/:id/settlement`：最新逐人結算、舊人均帳單及歷史版本。保留原分母、舊金額、人均捨入差額；逐人版展示各項消費、費用約定、共同份數、付款歸屬、發布時差額、包間收款人及變更原因。舊快照不跟隨現況改名或新款項變動；後續付款明確連到收付款帳本。
- `/activities/:id/settlement/edit`：正式人員全部保留；候補、待定與退出者可明確納入。份數 0／0.5／1、非正式、缺席、退出申請及未接受安排等例外須寫原因。逐人確認接受版本、原付款身份與出席，再預覽及確認發布。從舊人均轉換須明確勾選，舊版本保留。
- 費用項目支援消費／店家退款／減免、共同／指定範圍，以及 shares／equal／weights／fixed／duration。固定金額逐人精確對平，比例 0–1000／三位小數，時長 0–1440 整分鐘。每項獨立最大餘數補分，同餘數按資料庫凍結名冊順序；請求重排不改結果。總額與個人淨額不能為負，零元可以發布；消費退款不冒充資金退款。
- 每位參加者可指定 1–20 位付款人，依比例或固定金額分配；支援多人同付及額外付款人。同名保持不同 ID；認領、更名、退出及交接不把原付款責任併到管理人。
- `/activities/:id/rooms`：發起者預分包間、指定付款人及人員，僅建立追加式計畫，不記款、不群發。允許實際結束後、首版帳單前核對預分；草稿、取消、歸檔或已結算時不能改計畫。Unicode casefold 重名拒絕；人員最多歸一房；已有有效款項的 room ID 不能移除。
- 實際包間在結算頁再次核對，每位納入結算的人員必須恰好一房，免 A 者也保留。協辦結算人只能改金額與款項狀態，包間身份、名稱、付款人及人員安排只有發起者可變。各包間分別分攤及核帳，不能跨包間抵款。

編輯頁以收合的人員／費用明細降低資訊密度，只保留欄位、實際資料與操作提示。從活動、帳本、歷史原圖及 bot 舊連結可進入同一結算；`?event=…&action=settlement` 和活動 `?task=settlement` 只導航，不執行發布。

## 原子發布與已付金額

TypeScript 原生 API 提供結算查詢、context、50 版游標歷史、單版讀取、預覽／發布及預分包間讀寫。沿用 schema 9 與既有表，不呼叫 Python 執行業務。輸出經已知欄位 schema 驗證，不原樣公開任意匯入 JSON、內部 user ID、來源憑證或磁碟路徑。

發布要求當前 settlement scope、活動權限、同源、CSRF、匹配 account scope、UUID、精確 revision／base_version 及再次確認。只可在實際結束或取消後發布，包含已歸檔的結束活動。預覽 token 同時綁活動、revision、版本、凍結名單／安排、圖片摘要、費用、付款、包間、帳本序號及群通知選項；任一實質變動須重新預覽。這是原生 token 協議，不聲稱與 Python 的 JSON 雜湊逐位相同；業務快照以 Python 差分核對。

每版同時保存不可變 history／detail、收款碼／憑證引用、當前帳單、實際支出、audit、會員通知及原操作回執。必要寫入失敗全交易回滾；已完整落盤但沒有提交引用的圖片不公開，沿用既有 prune。可選 bot hook 用巢狀 savepoint 隔離，失敗不能撤回必要業務，也不留下部分群工作。同內容再核對不加業務版本；相同 UUID 精確重試先驗當前權限再回原回執，不受已成功後的 revision 變動影響。不同內容不可重用 UUID。

費用與實際付款分開。`unpaid` 不造款，`recorded` 必須有有效店家支出／訂金，`paid` 才在同筆發布交易追加 expense；已有支出或訂金時阻擋再次隨單記款，改到帳本核對補錄。實際付款人、金額、時間、方式、店家及依據都走既有 finance transaction／projection。新實際包間明確傳給 finance 驗證，不能錯用舊計畫；有未指定包間的有效業務款項時先阻擋，要求沖正並按包間重登。房內款項與全局投影均驗證。

`journal_seq` 在 JSON／SQLite 保持精確整數，HTTP 使用十進位字串；超過 JavaScript 安全整數後，相鄰序號仍保持區別，不把帳本與凍結版本改成浮點數。

## 圖片與表單恢復

接入前批私人碼庫與凍結圖片服務。每版最多三張消費憑證、微信／支付寶／其他碼各一張，合計最多 6 MiB；每張維持 PNG、2 MiB、1600px、chunk／CRC／EOF 驗證。前端保留本機 JPEG／WebP 轉換及原圖預覽。憑證可引用同活動任一已存在的歷史版，收款碼沿用還要核對原發布者；新收款人須選自己的碼。實際包間版不附統一收款碼。發布前可查看實際選入的碼及憑證；版後按原版本檢視／下載，不套入新圖。

結算及預分表單保存於 `qgroup:rebuild:activity-draft:settlement:v1:<scope>:<event>`、`…:rooms:v1:<scope>:<event>`。允許未完成金額／付款人草稿；送出前才使用完整契約驗證。切換分攤方式只提交目前方式的數值，不讓隱藏的未完成金額阻擋操作。

未知結果保留原 UUID 與精確提交內容，鎖住修改；重整／收件匣只顯示恢復入口，不自動重送。pending 只存一份提交內容與圖片，重新載入時還原表單，避免重複佔用圖片配額。儲存不足或禁止時不提交；損壞原稿先保全再繼續。帳號 scope 隔離原稿、query 與圖片；已卸載頁面不讓延遲結果還原私人資料，裝置登出清除原稿與 recovery 副本。更新名冊／帳本要明確重讀、保留輸入、重新勾選核對及預覽。發布成功同時更新 context 快取，避免返回編輯頁誤判過期。

## bot 保全與驗證

保留 Python worker，原生新增 `settlement_updated` 文卡、按鈕、版本去重及逐碼圖片工作。群明細是每版明確 opt-in，預設關閉；關閉時文字不夾帶人名、個人金額或圖片。開啟時凍結逐人 AA、付款歸屬、待補／應退，包間版顯示逐房及轉款。必要明細不因自訂模板省略 `{details}` 而遺失；普通與 rich 模板、長度退路、網址與按鈕沿用保留的來源規則。每張碼是獨立 outbox 工作，payload 保存凍結引用，不放圖片原文；文字先確認送達再處理圖片。

新增後端 17 項與 Chrome 8 項。來源差分涵蓋五種分攤、負項、補分順序、合付、同名／原付款來源、例外、舊轉新、版本差異、實際包間、隨單付款、圖片與普通／rich 模板。隔離 Python worker 使用 Mock API 消費新版文字及三種碼：文字／三圖各完成一次，共七次模擬 API 呼叫，第二次 poll 不重送。測試沒有連線真實 QQ、讀正式憑證或操作真實群。

必要故障、並行發布、精確重試、權限／私有活動／scope／CSRF、包間款項保留、無房款項阻擋、圖片總量、原圖、版本保留、超安全整數帳本、斷線／重整／收件匣恢復、儲存拒絕／損壞、跨帳號、登出、360px 與 bot 深連結均有合成驗證。
