# 新增活動沿用舊版操作

發布範圍：`both`（web frontend／API 與 bot）。活動進行中仍可報名，同時調整 bot 查詢顯示的報名狀態；不能保留會誤稱「已開始，補報名請聯絡發起者」的舊回覆。

新增活動以「發布活動」為主操作，另可保存草稿。一次交易建立活動、發起者報名、條件同意、稽核與建立識別；群通知沿用現有 outbox 與隔離的可選 hook。草稿端點未帶發布旗標時保持舊語意，待確認請求保留相同 payload、冪等 key 與建立識別。

主表單保留名稱、類型、地點、注意事項、日期／開始時間／1–24 小時時長、最低成團人數與 QQ 群推送；全新活動預設明天 18:00、3 小時、群推送開啟。類別預設時長只有在使用者尚未手改時才跟隨。容量、可見性、截止、退出、時區、費用及修改原因收在進階設定。

沿用舊版唯一時區 offset 驗證、曆日運算和開始倒數。凌晨需選當天或次日，跨日／凌晨發布再次核對完整日期與星期。輸入依所選 IANA 時區，DST 不存在或重複時段拒絕提交；舊原稿原先固定 UTC+8 的時間轉成原活動時區，待送內容不變，已有秒數保留。

報名截止預設跟隨活動預定結束；手動修改後保留，亦可恢復連動。截止及退出期限不能晚於預定結束。`scheduled`／`ongoing` 在報名開放、尚未截止及尚未到結束時可報名、候補遞補與暫停後恢復；手動開始保留開放／暫停選擇。取消、实际結束、歸檔、移除和已有結算仍阻擋。沒有時長的舊資料維持開始後不開放，不推造結束時間。已存在活動的截止時間不批量修改。

驗證：305 項活動／契約／bot 測試通過；63 項相關瀏覽器案例完成驗證（初次三項失敗修復後重驗通過），含草稿恢復、跨帳號、建立識別、發布競態、手機佈局與直接發布。建置 API／bot 原生 runtime、HTTP／WebSocket、ACK／Resume、投遞不確定／模擬狀態與隔離靜態產物 smoke 通過。手機截圖確認懸浮回頂按鈕不遮擋發布。全量重構套件的並行試跑受重型恢复測試超時影響而中止；不以該次試跑宣稱全量通過。

沒有 schema、群設定、憑證、投遞格式或真實待送工作遷移；沒有對真實 QQ 群發測試通知。正式發布需從核准遠端 main 固定 SHA 建置，驗證实际映像後記錄於 `docs/releases/`。
