# 第七十五批實作：隱私與管理刪除回執持久化

日期：2026-11-18（Asia/Taipei）。分支 `codex/unified-rebuild`。變更範圍 **`web`**，實際發布範圍 **`none`**。本機隔離實作，未合入 main、未部署，未操作正式資料、憑證、群設定或真實 bot 工作。

## 原操作與憑證保存

會員資料刪除、管理成分刪除及全站成分重置改用獨立 IndexedDB `qgroup-erasure-receipts-v1` 的 `operations` store。保留原 UUID、256-bit 回執能力、刪除範圍、profile revision 或管理預覽 revision、原帳號／管理授權；完成後保存經驗證的結果，會員另保存本機清除確認狀態。關閉全部分頁後能重新讀取，不會自動查詢或重送。

這是瀏覽器本機的回執能力儲存，沒有宣稱加密、跨裝置同步或抵抗同源腳本讀取。資料不進通用原稿庫、衝突版本或網站備份／成分匯出，日誌與網址不承載憑證。收件匣只讀目前帳號的安全標籤與固定原頁路徑，不帶 input、秘密或通用查回 requestKey。

會員使用單一裝置恢復槽，優先處理已有操作，避免原帳號關閉後訪客／另一帳號看不到原回執。查詢原回執不需登入；查詢 404 只提供明確「重新提交原刪除」，不自動刪除。重送前取得新 session，必須仍為原帳號，送出保存後的同一命令。管理紀錄按原帳號及 canonical 目標路徑隔離；目前管理授權可查回原回執，重送還必須與原授權 scope 相同。救援登入仍支援無會員／無成分的管理員。

## 交易、遷移與恢復

整筆原文 CAS 與 strict durability 交易必須提交後才允許 HTTP；競爭分頁不能用新 UUID／秘密覆寫已保存操作。HTTP 前再次比對原紀錄，切帳號或授權後不重放。卸載後不採用晚回應，已提交原操作仍保留供明確查詢。回執必須符合原 UUID、會員 target 或管理 command，否則不確認成功、不清除原紀錄。

會員成功先保存回執，再清除本機原稿；確認交易失敗仍保留原證明並清除已刪資料。完成按鈕僅在回執與本機清除狀態均保存成功後可用。清除失敗顯示伺服器已完成，關頁後仍可只重試本機清除，不再提交刪除。管理成功保存回執直到明確完成；完成／清除紀錄交易 abort 保留原證明。

舊分頁紀錄先驗證原 schema 與上下文；目的交易提交後才移除原鍵。同一原操作可保留目的已確認結果，不同原操作不覆寫。登出／撤權清除一般管理原稿時排除尚未遷移的刪除證明，避免丟失回執；續用仍受目前權限驗證。不可辨識原文不再複製進 recovery 鍵／版本庫；先下載原檔，明確確認保全後清除原紀錄。提示下載檔可能含回執憑證。
