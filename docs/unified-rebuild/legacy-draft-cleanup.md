# 舊版本機草稿清除

發布範圍：`web`（`frontend`）。API、bot、schema、outbox 與網站入口契約不變。

建立活動遇到舊站本機草稿阻擋時，可直接「清除舊版草稿，重新填寫」。舊站紀錄頁也提供相同操作。刪除前在按鈕附近说明範圍與不可復原；不清除其他帳號、新版草稿、歷史版本或已送出的原請求。

以儲存來源區分版本：只刪除 `kanban-local-v1/entries` 的 `draft:<目前帳號 scope>:`，以及 `qgroup-legacy-local-v1` 對應的 snapshots／mappings。新版 `qgroup-reviewed-drafts-v1`、sessionStorage、伺服器草稿不在清除範圍；不依瀏覽器時間戳推斷上線時間。

先在 strict transaction 設定此帳號的舊草稿自動匯入停用標記並增加舊紀錄 epoch，再刪除舊來源。舊分頁晚到的寫入不會重新匯入。原請求不受停用標記影響，pending 與 done 均保留；仍有未核對原請求時继续阻擋。來源清除失敗提示重試，不宣稱已完成；不存在的來源不會被建立。匯入功能仍允許使用者明確選擇保全檔。

本次新增瀏覽器驗證涵蓋：新版草稿恢復與版本逐位元保留、其他帳號隔離、未知草稿清除、pending／done 原請求保留、舊分頁不復活、兩階段 transaction abort／重試、來源不存在、切換帳號與新版待確認操作保留。線上資料副本驗收與正式發布結果另記於發布紀錄。
