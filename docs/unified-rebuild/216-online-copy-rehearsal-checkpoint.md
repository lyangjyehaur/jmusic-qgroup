## 新寫入與回退

在第二份隔離副本加入兩個合成帳號，使用來源詞庫執行實際 API 流程：保存成分、同好、建立／發布活動、三人報名、分房計算、正式採用、開始／結束與逐人結算。三人帳單為 900 分，付款責任與名冊、房間 ID 一致；無權採用被拒絕，結算同一操作重送不新增寫入。原有全部 bot outbox 與設定逐列保持不變，沒有建立或啟動投遞者。

完整新庫、看板 SQL、成分 JSON、身分、journal 與媒體使用既有回退工具投影並獨立對帳。兩份新成分映射為穩定的舊格式生成鍵，原選擇、程度、歸屬及新版 audit 保留。固定線上 bot 來源 `07defc429d619a7558ab7218372886f531813ae3` 的 Python 核心在禁止網路的程序中讀取回退後看板，房間、名冊計數及完整凍結帳單相符；沒有執行正式 bot 映像。

另以隔離 SQLite／JSON／native profile mirror 模擬舊側新增標題、revision 與成分程度，再執行 forward business reconstruction。變更、900 分凍結帳單、新版 audit 與原 bot 工作均保留，完整 integrity／FK 檢查通過。舊側寫入是明確的資料模擬，不能標成舊 HTTP handler 或真 QQ 驗收。

30 份來源成分配對歷史全部套用最新擷取的成分刪除鍵並對帳。版本 1 私人回退套件共 183 個檔案，以 0700／0600、獨佔落盤與 fsync 保存，再按外部保存的 manifest SHA 重新讀取及核對各領域。套件保全本次授權來源，不含 bot 外部日誌／設定檔或主機看板備份，仍為 `rollbackEligible:false`。

驗證 helper 的失敗也保留：目錄中間層權限檢查、腳本轉譯、錯用 API 欄位，以及把 HTTP 的 decimal-string `journal_seq` 與原 snapshot number 直接比較。修正 helper 後重新驗證；帳單原始 snapshot 按原字串核對，HTTP 表示另按既有契約核對，沒有修改產品或放寬金額／歷史断言。
