# 第三十九批實作：管理詞庫 CRUD 與合併

日期：2026-11-17（Asia/Taipei）。分支 `codex/unified-rebuild`。發布範圍 **`none`**：本機實作與隔離驗證，未部署或整合 main。新增重構 schema 12，跨服務影響先按 `both` 評估；未取得切換後實際 bot 版本組合的完整證據，不宣稱可單邊發布。

## 統一管理入口

`/admin/music-entries` 與 `/api/v2/admin/music-entries` 提供原生建立、編輯、刪除、合併。沿用同一管理後台與帳號／救援授權；管理員無須先保存成分。共用音樂搜尋支援名稱、別名、拼音／首字母、類型與分類，每頁 20 筆。按鈕只保留操作名稱，以可及性標籤辨識目標。

建立不套會員自建限額；編輯保留既有別名、建立者與原時間。名稱檢查沿用 Python 相容的空白與正規化規則，拒絕名稱／別名碰撞。刪除前列出選用人數與建立紀錄數，明確確認後才移除所有相關選擇與建立清單；會員自刪仍受有人選用不可刪的限制。

## 合併與版本保護

合併以原 Python `api_admin_merge` 為差分基準：來源換成目標，選擇依原順序去重，重複時保留先出現的熟悉度；建立清單同樣替換與去重。來源名稱及別名按正規化規則加入目標；目標原建立者、編輯權、分類及時間保留。

schema 12 的 `music_entry_creations` 將建立清單與目前編輯所有權分開。合併前把原生作者衍生的建立紀錄實體保存，避免來源刪除後建立歷史及額度消失；匯入的原建立清單也同步處理。受影響的成分 revision 遞增，舊草稿仍保留，但不能直接覆寫合併結果；會員須明確核對最新版及移除已不存在詞條。

管理核對 revision 涵蓋整份詞庫 metadata、會員選擇、成分 revision 與建立清單，防止確認期間影響範圍改變。修改、引用轉移、版本、migration map、追加稽核及精確回執在同一立即交易完成，回執寫入失敗全部回滾。

## 恢復、隱私與 bot

管理草稿以會員 scope 與管理 scope 隔離。送出前保存原命令與 UUID；回應遺失後鎖定原操作，重整即使來源已不存在，仍可用完全相同 UUID／body 查回結果。損壞草稿先保全原文；儲存失敗不送出；版本衝突保留輸入，重新核對才可確認。撤權及切帳號使原查詢與畫面失效，晚回應不能恢復管理資料。

新增 `music_catalog_actions` 是不可更新／刪除的操作稽核，只保存管理者參照、命令、詞條 ID 與影響數，不複製會員選擇或私人內容。隱私共享紀錄如實列入管理者的操作數；刪除成分清除 transferred creation records，不刪掉別人仍使用的目標詞條。

既有 59 張相容表、Python bot、outbox、群設定、模板與舊網址契約未修改。合成檔案庫在合併／刪除前後用原 Python bot 讀取並逐表核對非成分資料；pending／sending／sent／failed／skipped、claim、retry、simulated 狀態保持不變。沒有啟動真實投遞者或呼叫 QQ。
