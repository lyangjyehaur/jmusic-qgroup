# 第五十二批實作：統一群通知紀錄與明確重送

日期：2026-11-18（Asia/Taipei）。分支 `codex/unified-rebuild`。發布範圍 **`none`**：只做本機隔離實作與驗證，不合入 main、不部署，不啟動正式 bot、不使用正式憑證、群設定或待送工作。schema 維持 **14／94 張表**；正式 Python bot 保留。

## 統一入口與權限

React 新增 `/admin/bot/deliveries`、`/activities/:id/bot-deliveries` 與 `/time-polls/:id/bot-deliveries`，由 bot 後台、活動及投票管理頁進入。清單提供狀態／通知類型篩選、每頁 50 筆與數字游標，SQLite 64 位識別碼以字串保全，不經浮點轉換。只列出 group 通知，不把個人通知轉成群通知。

網站管理員可以唯讀核對全站群投遞紀錄，但不因此取得活動／投票的業務重送權。活動發起者可核對一般通知；獲授權結算人只可查看／重送該場結算通知；投票限發起者。API 每次查詢、提交及回執恢復重新驗權，活動仍須通過原存取規則。回應 `no-store`；React 快取與待確認操作依帳號 scope 隔離，撤權後隱藏舊資料，較晚完成的舊帳號回應不能恢復內容。

清單不回傳原始 payload、claim token 或私人收件者。核對頁只取明確的文字欄位、凍結圖片名稱及必要投遞狀態；匯入錯誤訊息遮罩 URL、授權及已知密鑰欄位並限制長度。群通知正文可能含業務資料，只供已授權讀取者核對，並未提供任意 payload 下載或公開查詢。

## 重送與不確定結果

核對頁顯示原目標、本次目標、部署繼承／模擬／實送設定、到期／重試／送出時間及可驗證的原文／預備內容。明確勾選後才能建立新的 pending 工作，原工作與失敗次數、已投遞內容保留；不重做報名、投票、定案或帳務。事件追加稽核、投票追加管理歷史，記錄原工作與新工作字串 ID；新工作與回執在同一交易提交，稽核失敗一併回滾。

API 與 worker 共用通知適用性／內容準備規則。確認 token 包含原列、目前政策、解析後目標、業務列及預備內容；設定、工作、業務或重新生成的投票內容改變，必須重新核對。群目標不匹配、已記錄群指紋改變、失效提醒、已歸檔、舊結算版本、原發布者結算權撤銷、凍結圖片不匹配及已有待送副本均阻擋。提醒保留仍有效的 schedule key 與原 due_at；投票只重新生成目前有效候選，不改原票。

已送、pending、sending、失效略過與已知不確定結果不能重送。不確定結果仍要求維運離線核對，未新增線上「當作已送」或自動重設狀態。模擬紀錄只有經明確操作才可建立新工作，切換實送設定本身不重播舊模擬。

新版投票管理頁統一使用群通知紀錄入口；原 `manage action=bot_retry` API 保留，供既有客戶端／待確認草稿恢復。該相容 API 維持既有「重新生成目前投票公告與目前目標」語意及 revision／confirm／idempotency 檢查，未改成新核對 token 協議；同步採用已送／待送／不確定結果阻擋。新核對 API 對舊通知目標則採較嚴格的匹配規則。不能宣稱所有相容入口已使用相同核對協議。

## 回應遺失與本機操作保全

POST 前先將原 UUID、工作 ID 及精確確認內容寫入 scoped sessionStorage；保存失敗不發送請求。回應遺失時重載仍保留操作，先查本人回執。查無回執後，需另按「以原操作編號重送」，再次查回執再使用同一 UUID／body。查回執暫時失敗或限流不清除操作；已提交回執不因新的核對 token 過期而失去精確重播能力，但每次仍先驗目前業務權限。

這是同分頁 sessionStorage 保全，不代表跨裝置或關閉瀏覽器後的持久草稿已完成。伺服器仍保留操作回執；完整持久草稿／恢復入口另依主計畫驗收。
