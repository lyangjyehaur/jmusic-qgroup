## 活動中的包間

活動詳情直接顯示預分／實際包間、房付款人、每房人員、未分配人員及本人的房間，不需要進入管理表單。只有目前發起者且活動允許修改預分時，顯示分配操作；一般會員與訪客可查看有權存取的安排及歷史。分配、歷史、活動與對應結算版本互相連結。

本人標示只依目前有效名單的 `attendee.user_id`；同行標示只依當前名單的 guest 與管理者關係，不以姓名、聯絡 QQ 或代報者推斷本人。同名人員依名單位置區分。候補預分有明確提醒，未分配者不會被誤顯示為已有房間。

預分使用目前名單姓名，已退出且不在目前名單中的原安排成員顯示「名單已變更」。歷史預分快照原本沒有保存成員姓名，不能虛構當時姓名；原房名、報名對應及付款人標籤保留。已發布結算的實際包間則使用該版凍結的人員姓名、狀態與房付款人，僅本人／同行標示依目前身份重新判斷。退出後不把歷史同名成員當作本人。

概況沿用舊公開介面的選擇規則：最新帳單有 `rooms` 時顯示實際安排，包括明確空陣列；沒有 `rooms` 的非分房帳單回看最新預分。不是依「已有任何結算」就抹掉原預分。

## 讀取與權限

新增 TypeScript 唯讀 API：

- `/api/v2/activities/:id/rooms/overview`
- `/api/v2/activities/:id/rooms/history`，每頁 50 版，數字 `before` 游標。
- `/api/v2/activities/:id/rooms/history/:version`

三個入口沿用活動可見性與 account scope。只有 cookie 而無 scope 時仍為匿名視圖；scope 不符或撤銷 session 不能讀取先前身份的標示。邀請活動不因站點管理員身份而公開；草稿仍須有效活動職責；不存在或刪除活動回 404。

公開契約只列顯示所需資料，不傳回原 SQL 快照、付款帳戶 ID、user／manager ID、私人備註或結算付款明細。概況、歷史及快照的組合讀取在同一 SQLite 交易中完成，不追加版本、不改報名、不產生款項或 bot 工作。

React 歷史頁可選版本、查閱原安排、讀取更早版本、返回最新頁，讀取失敗可明確重試。所有查詢按 account scope 隔離，帳號切換及登出後不顯示先前的本人／同行標示。分房保存與結算發布會使包間相關查詢失效重讀。
