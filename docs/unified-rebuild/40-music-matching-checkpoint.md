日期：2026-11-17（Asia/Taipei）。分支 `codex/unified-rebuild`。發布範圍 **`none`**：本機實作、隔離驗證與原始碼同步，不部署、不整合 main。本批修改新版 web、TypeScript API、領域計算與契約；沒有 schema、原 Python bot、outbox、設定或 bot 網站深連結變更。日後發布範圍候選為 `web`，仍須完成實際切換版本組合驗收，不能把本批隔離回歸當成線上相容性證明。

## 統一入口與動線

`/people` 同時提供指定成分查詢、比較與依目前已保存成分產生的同好推薦。推薦保留共同項／冷門與個人熟悉度兩種排序；URL `sort` 保留選擇。主榜前三位展開，其餘名單與資料不超過三項的會員分別折疊，回應保留完整結果，不以分頁或前三名裁去功能。共同／獨有詞條分領域與細分，保留每側程度、詞條人數、共同本命、冷門項、覆蓋關係、低資料提示、嚴格重合及校準匹配度。

`POST /api/v2/music/compare` 接受固定 ID、原查詢別名或目前聯絡 QQ；viewer 一律取 scoped session，拒絕提交另一個 viewer、自己與不存在的成分。號碼只在 JSON body，結果導向固定 ID 的 `/people/:id/compare`，不把輸入號碼放入 URL。另有 scoped `GET /api/v2/music/profiles/:id/comparison` 支援站內連結。比較包含共同、雙方獨有、雙方完整詞條及各自程度；來源只有單側或兩側空白時，明確回傳零分、實際詞條數及空集合，不沿用原來源的缺欄位 `{}`。

推薦／比較／成分卡的詞條連入既有共用音樂工作區，可選取、移除、調整細分程度及保存；不另做一份選擇控制器。返回連結保留推薦排序與原比較頁，未保存選擇仍由既有離開確認與分頁草稿保全。只有允許的站內路徑能作為返回目的地。成分卡與比較互相切換，也保留推薦來源。複製名稱、固定 ID、聯絡 QQ 及手動複製退路沿用共用元件。

## 原始計算與明確差異

以 `music_site/upstream.py::match_stats`／`compute_matches` 的實際執行邏輯為準，不採用已過期的 30／70 docstring：

- 領域 55%、細分 45%；某類完全缺少時以現有類型完整比重計算。各類使用 weighted Dice，程度 1／2／3／4 權重為 0.3／0.5／0.8／1，共同項取兩側較小權重。
- 嚴格分採 ties-to-even；顯示匹配度為 `100 × sqrt(ratio)`，共同 0／1／2／3 項上限 0／36／49／64%，四項以上上限 100%。推薦用已四捨五入的嚴格分重新計算標籤與校準分，直接比較使用未取整比例，保留此來源差異。
- 主榜共同項排序：共同項降序、證據折算分降序、冷門項降序、名稱 Unicode code point。資料較少分區則用共同項降序、嚴格分降序、冷門項**升序**、名稱；保留來源看似反向的 tie-break。
- 熟悉度排序依 viewer 的共同本命數、共同熟悉度總分、共同項數及主榜證據折算分；資料較少分區不加最後的證據分條件。領域也參與熟悉度排序。名稱完全相同時保留來源插入順序，不額外改以 ID 排序。
- 冷門為使用人數不超過二；共同本命只算雙方細分程度四。證據折算 `round(score × shared / (shared + 3))`，熟悉度四檔分數為 1／0.6／0.2／0.05。

差分發現原 Python 用隨機 set 迭代累加 0.3／0.5／0.8，某些精確半分會浮動到半分上下，導致同一份資料在不同程序得到 22 或 23。本批將權重乘十使用整數，混合比例保留分子／分母，再明確 ties-to-even；例如精確 22.5 穩定為 22。這是刻意修正非決定性，不能描述為原來源每個程序逐位完全一致。500 組差分同時對原函式與獨立 Python `Fraction` 對帳；只有實際精確半分且差一分時接受原浮點偏差，原生必須等於有理數基準，其他指標、標籤與校準仍核對。

## 私人留言與身份限制

留言沒有公開提供。推薦只讓目前**所選排序主榜首位**顯示留言，其餘主榜與所有資料較少分區回傳空字串。成分卡與直接比較則按**預設共同項排序主榜首位**判斷；自己的成分卡可看自己的留言與未公開性別。這與來源 `NOTE_TOP_N=1`／`note_allowed` 相同，不能因熟悉度頁看到某人留言就永久取得其成分卡留言權限。獨立原生欄位優先，未轉成獨立欄位的匯入資料仍按既有 parser 讀取。

表單提示已更正為具體的條件可見範圍，移除先前「私人留言不會公開展示」這種無法說明會員有限存取的文字。其他會員只取得公開性別；固定 ID、別名及自填 QQ 只用於定位資料，不授予所有權。私人成分身份、PIN、帳號鍵、憑證、原始欄位與內部性別欄位不經白名單回應。

每次讀取將 session／已保存成分門檻、完整資料快照、排序及授權放在同一 SQLite 讀取交易。成分卡／查詢原有門檻亦移入同一交易。刪除、解除／重新指派、聯絡修改與已保存選擇立即影響下一次讀取，不存在持久的留言授權旗標。回應沿用 `no-store`／`Vary: Cookie`，查詢號碼的 POST 要求 origin、CSRF、scope 並保留限流。前端私人查詢以 scope／musicEpoch／sort 或 target 分鍵，進入時等候新讀取；推薦與比較定時刷新。保存選擇／資料／聯絡使相關查詢失效，跨分頁依既有帳號通道更新；切換帳號、刪除與登出清除舊私人顯示，延遲回應不能重新顯示。
