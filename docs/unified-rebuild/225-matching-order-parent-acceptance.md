## 線上隔離副本與排序缺陷

沿用第 219 批授權擷取的同一副本，capture manifest 為 `591a7209bf5ef07b3a79569a4abd411899660acfcf25b24ee1fb9e38098bbd7c`；原成分來源固定為 `be51e065bd0d64a2df3a783ca14672d92ba6d49a`，9 個 Python 檔案釘選保持原樣。

第一次圈子比對在門檻 40 拒絕：群組成員一致，但部分同頻標籤及同大小成員順序不同。原因是 Python 保留 JSON 中的 QQ 插入順序，JavaScript 普通物件卻會先按數值排列整數索引鍵。原匯入有 51 個位置不同，`profile_source.position` 也受影響。

修正後嚴格 JSON parser 在私有 WeakMap 保留原鍵顺序，匯入與獨立對帳使用該順序；身分資料庫補回的原生成分依原 rowid 接在原 JSON 成分之後，刪除紀錄仍先套用。資料物件、一般 `JSON.stringify`、原 canonical hashes 及 schema 不變。

管理匯出、歷史匯出及私人回退套件的成分／詞條字典，改用明確保留順序的建構與寫出。回退獨立檢查同時核對成員／詞條順序，不能只比對集合與數值。管理匯出仍在原管理權與最新刪除紀錄交易中；重新審閱兩個管理讀取入口後只更新 source pin，權限條件不變。

所有驗證均使用新建私人副本，原匯入及失敗證據保留。新匯入保留原 import clock，沒有用新的驗收日期代替原取樣時間。

- **68 份成分、152 個詞條、682 筆選擇**；全部 **4,624** 組有序配對和 68 個 viewer 的兩種排名與固定 Python 相同，原浮點半偶數修正次數為 0。
- **43** 個原已連結帳號的 86 次同好讀取、3,460 列推薦、86 份分享 context、原欄位，以及 68 張成分卡、67 次 ID／67 次原別名比較通過。全部公開／私有讀取無資料寫入。
- 6 種圈子門檻全部與原程式一致；門檻 60 的 9 個群組完整保留，原 API 前 8 個仍相同。趨勢點、漲幅、近期詞條／會員及統計亦一致。
- 隔離測試 140 字留言／12 字性別、超限拒絕、清空、隱藏性別及精確重試；**91 張非欄位操作目標表**不變。獨立 Python 排除合成 session 與另行取樣後重新核對 **89 張表**，其中 **6 張 bot 表**在原匯入、新匯入及操作副本完全相同。
