# 遷移、實作順序與驗收

本文件是待執行計畫，沒有任何正式切換已完成。此次文件發布範圍 **`none`**；未來整合重寫預設 **`both`**，涵蓋舊 web、music 與 bot 三服務向新網站／worker 過渡的相容性。

## 1. 驗收台帳

每個[功能 ID](01-capability-inventory.md)建立以下台帳，不以頁面完成比例取代功能覆蓋：

| 欄位 | 必填內容 |
| --- | --- |
| capability_id | 本次矩陣的穩定 ID；若拆項保留父項關係 |
| new_entry | 路由與主要操作位置；純後端項記 API／worker／維運指令 |
| implementation | TSX、use case、policy、repository、遷移與兼容 adapter 路徑 |
| behavior_evidence | 舊行為 fixture／既有測試依據；新系統測試名稱及結果 |
| data_evidence | 該項的原列、ID、版本、金額、資產與刪除對照結果 |
| permission_evidence | 可操作者與拒絕者；公開／邀請及撤權情況 |
| ux_evidence | 相關桌面／手機／鍵盤流程與截圖，或說明純後端不適用 |
| state | 未開始、實作中、待驗收、通過、受外部阻擋；不以「有畫面」標通過 |

全部既有功能是正式切換門檻。新增的全站搜尋、正式採用音樂分房及圈子 UI 另記整合需求，不混充既有能力的測試通過。已停用的舊入口不復活；功能矩陣明確列出的替代方式仍須可用。

## 2. 資料來源與權威順序

遷移輸入是切換時現有專案的資料，不是已下線老站的原始匯出。2026-11-15 的最後匯入之後，新站已有新寫入；禁止重新整份匯入老站備份覆蓋它們。

| 來源 | 必須納入 | 驗證方式 |
| --- | --- | --- |
| 看板 SQLite | 所有使用者表、欄位、遷移、trigger 語意、序號、session、角色、通知、待完成工作 | 原始副本封存；逐表逐欄與新模型對照；外鍵及完整性 |
| 看板媒體 | images、舊 BLOB、每版收款碼與憑證、私人碼庫引用 | bytes／digest、版本、授權與孤兒資產報告 |
| 看板 erasure ledger | 目前與恢復前可取得的最新刪除意圖 | 重播、再重播，帳號不可重新登入／復活 |
| music `data.json` | entries、members、selection、created、settings、shouts、shoutHistory、trend 及未知欄位 | 正規化前封存；逐欄映射；不能解析的欄位保留並阻止遺漏放行 |
| music 身分 SQLite | links、prelinks、overrides、audit、native_profiles、profile_contacts、sessions、used_oauth、限流、entry_intents | 重播目前權威投影；逐筆 ownership、空值與單次授權核對 |
| music 資產與備份 | walls、manifest、配對備份、歷史 JSON、最新 `erasures.jsonl` | 先套最新刪除再提供歷史下載；確認備份不是完整身份恢復的替代品 |
| browser IndexedDB | 活動、投票、結算含圖、款項、pending requests、身份 scope | 同 origin 的版本化 client migrator，保留原 store 至成功確認；不能靠伺服器匯入 |
| browser 偏好／SW | 成分未保存選擇（若仍在記憶體須離站提示）、主題、排序、壁紙開關、舊 `/music/` scope | 能搬移則搬移；不能擷取的記憶體輸入清楚提示；逐 cache namespace 退役 |
| bot 狀態 | outbox、claim、重試時間、實際投遞本文、設定與歷史、群政策、診斷、節流、健康／連線狀態 | 不能重送已送、不能發送 dry-run 歷史；連線狀態可失效重連但保留業務工作 |
| 正式設定 | 公開 origin、QQ App、限流／註冊／群政策、版本 manifest、備份排程 | 僅在私人受控環境讀取；不進 Git、fixture 或公開報告 |

資料優先順序：**最新刪除意圖 → 有效帳號與關聯覆寫／授權紀錄 → 已提交業務與凍結歷史 → 相容投影 → 舊匯出**。衝突生成私人待核對報告，不能用暱稱、QQ 或檔案修改時間猜誰覆蓋誰。

## 3. 映射與匯入規則

1. 建立 `migration_map(source, entity_type, source_id, target_id, source_revision, payload_digest, status)` 及執行 manifest；來源帶 namespace，避免兩個 `sessions`／`login_attempts` 混表。已存在 ID 能保留就保留，任何轉換都有可逆對照。
2. 第一個整合版本先將既有看板表作相容儲存模型，保留舊 bot 可能讀取的 schema／欄位與觸發器。新增音樂正規化表，不一開始就重命名／刪除所有舊表。後端實作仍全新，資料形狀的短期相容不等於保留舊網站。
3. 成分 JSON 轉入 entries／profiles／selections／trends／shouts／settings，先套最新 erasure、native profile 及 contact 投影；import 與 mapping 同一交易，失敗整批回滾。再次匯入相同快照不新增第二份、不覆蓋較新的業務修改。
4. 保留舊 `users`、event、attendee、party、room、payer、request、poll ID；排序序號與 `sqlite_sequence` 不倒退。保留所有人均／逐人／包間帳單版次，不把它們重算成「目前名冊應付」。
5. 舊成分會員鍵保留為 legacy key，新的固定 profile ID 與公開 person ID 另行映射。解除關聯保留兩份資料；新空白成分不搶佔舊成分。自填 QQ 清空及管理 override 的解除都必須保留。
6. 單位轉換（秒／ISO 時間、bytes、BigInt 字串等）明確記錄。未知時區、實際開始／結束與空欄位原樣保留，不能自行推導成已發生。
7. 待完成 OAuth／限時邀請分別決定是否可續用：有效且安全可驗證的 session、裝置、認領及交接連結延續；跨新舊環境無法證明的 OAuth attempt 失效並回原任務重新授權，不消耗或錯配權利。不強制已關聯會員再認領一次。
8. 未完成 request 保留同身份、方法／原路徑、payload、key 與結果查詢；新版 API signature 若改欄名，舊 adapter 先按舊協議驗證再轉 use case，不能拿新 signature 誤認是另一筆操作。
9. browser 草稿 migrator 保存原 scope、base revision／version、client_intent、圖片和 key；先確認服務端原結果，再轉為新草稿。不可因舊草稿仍在就建立第二場活動。切換帳號後不可讀取別人的草稿。
10. 未知 JSON 欄位及過時設定保留在受保護的 legacy archive，逐欄列出用途／取代／停用理由；未分類欄位數必須為零。公開匯出不得帶入 PIN 摘要、已刪內容或 OAuth 憑證。

## 4. 對帳門檻

- SQLite `integrity_check`、`foreign_key_check` 通過；重跑初始化／匯入不新增重複資料。所有來源實體都在「保留、明確映射、按刪除意圖移除、明確安全失效」其中之一，沒有無說明丟棄。
- 活動生命週期、報名順序、候補／整組阻塞、管理人、付款歸屬、安排同意、出席、邀請／認領／交接狀態逐項相同。
- 所有帳單版本總額、人頭分母、逐人與付款責任、包間及歷史圖片完全相同；帳本原始列、有效投影、未處理訂金、每房與各持有人餘額對平。不允許以「新演算法比較正確」重寫歷史。
- 成分原選擇、等級、建立詞條、稱呼、聯絡別名、留言、性別公開旗標、喊話與趨勢都完整；effective ownership 對照一致，無重複擁有者、幽靈帳號、失效關聯與已刪會員復活。
- 待送工作的 target、due_at、重試、模擬、claim 與內容版本有去向；已送不變待送。被撤權、隱藏或停用通知不得在切換後補發。
- 媒體雜湊和引用對上；歷史備份下載先過最新刪除與權限；恢復後再執行相同檢查。

## 5. 建置順序與退出條件

階段名稱只表示實作順序，不縮減最終範圍。全部在 `codex/*` 分支，已整合分支停止開發，後續從最新 main 建分支。

| 階段 | 產物 | 必須通過才往下 |
| --- | --- | --- |
| P0 基線與行為鎖定 | 本組文件、台帳、可重播合成案例、有效路由／資料欄位清單、爭議項決議 | 所有功能 ID 有來源；舊文件差異有實際程式判據；敏感欄位沒有混入測試 |
| P1 新骨架 | 新 workspace、API／worker、contracts、UI shell、登入／角色／錯誤／草稿／CI | 真正 TSX 掛載與 strict；無舊 UI runtime；API 拒絕未授權寫入與 scope 混用 |
| P2 資料與垂直流程 | 隔離匯入、會員登入→成分保存→同好→活動→名單成分 | 一套 session／model；有效關聯正確；遷移可重跑；從活動往返不丟任務 |
| P3 全活動與社群 | 活動狀態、代報／同行、候補、認領、安排、角色／轉交、現場、投票；詞條、推薦、圖表、喊話、分享 | I／E／R／T／M／C 功能矩陣全部有測試，含拒絕與失敗路徑 |
| P4 分房與完整財務 | 自由試算→活動建議→正式安排→實際包間、所有結算／帳本／碼庫 | P／S／F 全部通過；精確分攤與帳本差分零差異；權限及並發通過 |
| P5 後台、bot、維運 | 單一後台、完整 TS bot、公開 v1／舊 URL adapters、匯出備份／刪除／恢復、SW 退役 | A／B／O 全部通過；QQ 模擬／真實界線清楚；舊群按鈕與 API 相容 |
| P6 成套驗收與演練 | 全功能瀏覽器證據、隔離正式副本演練、固定版本組合、切換及回退工具 | 全台帳通過；新寫入回退已演練；資源量測達標；沒有尚缺功能 |
| P7 正式切換 | 已合遠端 main 的完整 SHA、核准封存、唯一候選映像、實際版本紀錄 | 完成下節切換／保全，發布後唯讀驗收；原服務才可退役 |

先做一條垂直流程是驗證架構，不是能先刪掉其他現有功能上線的授權。設計中的爭議項在 P0 對照程式補測並寫明決議；無法確定權限時維持較窄可見範圍，不把個人資料擴大公開。

bot 相容性是 P1–P7 的持續條件。P1／P2 建立既有 bot 的資料、設定、outbox 與網址契約；P3／P4 每條網站業務一併驗通知和 bot 查詢結果；P5 完成替代 worker。任何階段都不能把 bot 功能延後到網站正式上線後才補。

### 切換前

1. 確認兩邊遠端設定，功能驗證後合入並推送 main，核對 git.dan.tw 與 GitHub 分支 SHA；任一失敗補推。選定完整 commit，在乾淨 checkout 跑 `python3 deploy/check_release_source.py --commit <完整 SHA>`，只封存核准提交，在乾淨暫存目錄建置一次。
2. 保存現有 web、music、bot 的實際來源／image ID／digest、schema、設定／資產與 latest erasure；記錄新 website／worker 對應關係。獨立固定每個服務映像，不只改共用 `QGROUP_TAG`。
3. 使用成套備份隔離副本做兩次匯入與恢復，核對差額；驗證工具無外網、不帶正式憑證、明確 CPU／RSS／PID／時間限制。完整測試與建置優先本機或獨立 CI，正式機只做受控備份及輕量驗收。
4. 預先準備舊映像及**可接收新版新寫入**的回退方案。沒有此方案，不能把「換回舊程式」列為可行回退；此階段應只允許向前修復或延後切換。

### 維護窗

1. 取得部署鎖，停止舊 bot，再停止 web、music 及背景寫入，取得 music 維護鎖。關閉舊連線與寫入，避免匯入時仍變動。保存停機當下完整 DB／JSON／身份／媒體／ledger／outbox。
2. 以最新成套快照匯入新資料庫，不以預演副本直接取代正式資料；記錄高水位與 digest。執行完整對帳，失敗時尚未接受新寫入，可恢復原服務及原狀態。
3. 啟動新版網站，唯讀檢查資料、入口、權限與資產；啟動新 worker 或已驗證相容的保留 bot，確認只有一個投遞者。再開放業務寫入。
4. 新頁處理舊 `/music/` Service Worker：同 origin、精確 scope 和 cache namespace 退役，確認舊管理頁／離線快取不再攔新 API；不刪除其他應用快取或本人草稿。
5. 記錄新服務實際來源／映像與 schema、未更新服務身份、驗證結果及不相容限制；不在正式庫新增演示活動、付款或測試會員。

### 開放新寫入後的回退

新版一旦接受新選擇、正式採用分房或新帳務，舊 music JSON 和舊 schema 就不能被視為最新資料。預先實作帶 checkpoint 的回退匯出器：保全最新新庫及 ledger，停止新寫入，將切換後變更轉回舊版能表達的資料，保存 ID／版次／金額／刪除，再對帳驗證才啟動固定舊映像。

若某項新資料不能無損表示，採向前修復或維護窗處理，不能丟掉它們以求快速回退。已發出的 QQ 消息無法撤回，不能透過回退重送。恢復任何舊備份前先保存並重播最新刪除 ledger；絕不將舊備份直接覆蓋目前已開放寫入的資料。

## 8. 尚須在實作中取得的證據

- 正式資料的實際數量、資料欄位分布、待認領／衝突及最新工作高水位；本輪沒有讀取正式資料，歷史發布數字不作現在的驗收總數。
- 匹配留言可見性與舊公式註解差異的最終規格和合成案例；不以 UI 宣傳語擴大授權。
- server2 等級資源下 Node／SQLite native module、分房及圖像的實測 RSS／延遲與候選映像相容性。
- QQ 真實授權、WebView、按鈕與真群投遞；必須區分外部平台阻擋與程式已驗證部分。
- 切換後新寫入的回退匯出器、browser 草稿 migrator、舊 SW 退役與版本鎖定工具；這些都尚未實作，不能只憑本文件放行發布。
