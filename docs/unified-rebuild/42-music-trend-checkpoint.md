## 原取樣、圖表與資料

對照 `music_site/upstream.py::compute_trend`／`trend_snapshot`／`trend_loop` 及 `music_site/public/app.js::drawTrend`：

- 背景每 30 分鐘取樣，即使沒有人修改也保留快照。 runtime 啟動時記錄一點，排程依牆鐘下一個半小時；距最後有效快照不足 1770 秒不重複記錄。多程序 SQLite immediate transaction 去重、時鐘倒退不追加、長時間離線不虛構中間點。Fastify 關閉時停止 timer；失敗記錄錯誤，下個排程繼續。
- 匯入原 `trend` 文件保持原順序及內容，不原地改寫；新取樣另用 `trend_sample` 類型，最多 48 點。讀取先接原歷史、再接原生快照，最後最多回傳 48 點。若目前選用人數與最後快照不同，回應額外接上目前讀值，但 **GET 不落盤**；相同則不補點。取樣只有詞條 ID 與合計人數，不包含個別會員、號碼或留言。
- 折線各點是相鄰快照差值，減少記 0，第一點為 0；漲幅是正差值總和，包含下降後回升，不能當成淨增或現在總數。先取領域前二、細分前三，不足五項再按漲幅補齊。相同漲幅保持來源首次出現順序；已刪詞條的歷史保留，現行詞庫不存在的項目不繪圖。漲幅榜只列所選五線中的正漲幅，保留來源範圍。
- 回應保留最近八個詞條、最近八個成分、24 小時及 7 天新增、總數和實際取樣時間。詞條／成分原建立時間獨立於最後保存、改名或匯入時間；原欄位不存在不猜成新加入。來源 24 小時統計用 float，7 天／排序／顯示用 int，嚴格大於 cutoff；日期字串不冒充來源秒數。非法舊時間以未知處理，不能渲染的極端日期不使頁面崩潰。

舊資料若已包含取樣，即保留匯入快照；目前 importer 不讀取舊小時備份來補種一段歷史。原服務 `seed_trend_from_backups` 的備份補種／完整來源對帳仍待遷移階段，不能聲稱已完成全部趨勢資料驗收。

以直接 TSX SVG、容器寬度量測與固定可讀字級繪圖，沒有導入舊 DOM controller 或外部圖表 CDN。圖例、時間範圍與漲幅提供完整名稱及連結，快照資料表可展開、鍵盤聚焦及橫向捲動，手機頁本身不溢出。文案只保留計算規則、取樣缺口、資料狀態與必要操作提示。

## 權限與保全

公開 `GET /api/v2/music/trend` 僅有詞條、匿名合計及時間；最近會員另由 scoped `GET /api/v2/music/trend/members` 提供。會員端沿用「已保存成分才可查看同好」門檻，只回傳固定成分 ID、名稱及原建立時間，不提供自填 QQ、帳號、關聯鍵、私人留言、性別、PIN 或憑證。這是依新版既有存取規則收窄原始內部 Handler 名單，不把舊入口權限較寬當成擴大公開的理由；舊 HTTP adapter 尚待驗收。

兩個讀取放在單一 SQLite 交易快照，拒絕額外 viewer／target 查詢參數，沿用 `no-store`／`Vary: Cookie`。私有查詢以 scope／musicEpoch 分鍵，進入頁面等候新回應；登出、切帳號、刪除後的晚回應不可恢復舊名單。刪除成分後移除目前身份、選用計數與原建立記錄；已取樣的匿名合計歷史仍保留。

## 隔離驗證

新增九項 API／取樣測試：實際 Python Handler 的完整 points／最近詞條／最近成分／7 天／總數差分；私有白名單、session／scope／查詢限制與全表／總寫入數不變；float／int 時間邊界；刪除後身份與歷史分離；原文件保持、無改動取樣、多次啟動／時鐘倒退／離線及 48 點；半小時排程、失敗恢復與關閉；損壞歷史明確報錯保留原資料；顯式 runtime mode 與 Fastify close；重開庫去重及實際 Python bot 唯讀 probe 前後一致。

新增八項 Chrome 流程：匿名圖表／圖例／統計／名單門檻、同一草稿／搜尋／詞條返回、同好／比較返回／360px／鍵盤資料表、保存後即時讀值與離開確認、獨立錯誤重試與舊圖移除、延遲名單與切帳號／登出、跨分頁刪除、單快照／無新增／空圖／長名稱與極端日期。與推薦及分享合跑 **30 項通過**；已檢視 360px 截圖並修正原始桌面 viewBox 縮小造成刻度過小，圖表文字的實際高度亦納入瀏覽器檢查。

全套回歸遇到前批推薦的 Python set 浮點累加差異：相同精確 22.5 可能為 22 或 23。執行碼保持前批既定有理數半偶規則；排序測試也改以獨立 Python Fraction 產生基準，僅允許實際半分且差一的原浮點誤差，並在四種 `PYTHONHASHSEED` 下執行真實 Handler 的排序。原 500 組未修改 scoring 差分仍保留，沒有單純放寬斷言或固定某個偶然 seed。
