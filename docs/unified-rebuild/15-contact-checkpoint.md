# 第九批實作：聯絡 QQ 與同好成分入口

日期：2026-11-17（Asia/Taipei）。分支：`codex/unified-rebuild`。發布範圍 **`none`**。只使用隔離合成資料，未部署、未操作正式 bot、憑證、群設定或待送工作。P2 及全部 166 項功能的完整驗收仍未完成。

## 已實作行為

- 「我的成分」直接進入 `/me/music/contact` 編輯／清空聯絡 QQ，或查看 `/people/:id` 成分卡；「同好」可按固定成分 ID、舊會員鍵或目前聯絡 QQ 查詢。查詢號碼放在 POST body，不進網址、瀏覽歷史或 request URL 日誌。
- 沿用舊站成分會員的查閱範圍：必須登入、scope 相符且已有未刪除成分。只有看板帳號、尚無成分時提供保存成分的連結；API 同樣拒絕查閱。訪客不能查詢或查看他人聯絡資料。
- 自填 QQ 去除首尾空白，接受首位非零的 4–12 位數字或空字串。空字串明確清除目前別名；原號碼不再可查，固定 profile ID、登入身份、QQ 綁定與原選擇均不變。
- 舊數字會員鍵延續為固定查詢標識，會員不能改寫或清空；更正仍須管理員核對。新成分與舊 native profile 的自填別名可修改，不能使用他人正在使用的號碼。匯入後未完成核對的孤立 contact reservation 也不能被搶占。
- 成分卡只提供固定 ID、名稱、目前聯絡號／來源、原順序詞條及程度。匯入成分延續其獨立稱呼；目前新成分使用帳號稱呼。號碼明示未經騰訊驗證，不能當 OAuth 身份或 ownership 證據。
- 複製成功回報結果，Clipboard API 被拒絕或不可用時提供手動複製提示。未提供號碼時不保留空按鈕。沒有加入宣傳或裝飾文案，並移除成分頁重複的帳號副標。

## 交易、草稿與刪除

聯絡號使用獨立 revision；每次有效變更同時提升成分 revision，讓舊刪除確認及選擇編輯不能忽略剛發生的資料更新。相同號碼不追加變更歷史。唯一索引、IMMEDIATE transaction、帳號／CSRF 驗證、寫入、追加歷史及操作結果在同一交易；任何一步失敗全部回滾。

request key 綁方法／路徑與內容，跨操作或變更內容不能重用。先驗目前身份，再讀取回執；撤權或切換帳號後不能重播。保存回應遺失／無法解析時，草稿先保留完全相同的 payload 與 key，再安全重試；取得原結果後另讀目前聯絡資料，避免把已再次變更的號碼誤顯示為目前值。

聯絡草稿按 scope、music epoch 及 profile ID 隔離，只留在目前分頁。儲存失敗時不送出；損壞原稿須先另外保全，不直接覆寫。尚未通過格式驗證的使用者輸入仍可保存為草稿。離開未保存頁面須明確選擇；競態衝突保留原輸入，先讀目前版本再明確保存。

修改聯絡號不覆蓋未保存的詞條草稿。返回時若選擇與目前保存版本完全一致，只更新基準 revision；有不同選擇或待確認操作時保留原稿，遇到新版本需明確核對。成分刪除會清理各分頁聯絡草稿、目前聯絡號與聯絡歷史，並把相關舊操作回執轉為 410；重建得到新 profile ID／epoch，不復活舊聯絡資料。只關帳號仍保留獨立成分與聯絡資料，相關聯絡歷史明確計入後台共享紀錄待審。

## schema 與匯入

新增 schema 4：共 77 張使用者表（59 張相容表＋18 張新站／遷移表）。新增權威 `music_profile_contacts` 與追加式 `music_contact_history`。3→4 投影已有舊成分目前聯絡值，包括 native 的明確清空，不改任何原看板表、身份、選擇或帳務。1／2／3 開發庫循序升級，當次遷移失敗會回滾；重開不重複投影。

成套匯入器直接寫入 schema 4 的權威聯絡表。之後編輯同步更新目前 legacy profile 的 contact 欄位；`music_legacy_identity` 中凍結的來源證據仍停用，不能重新蓋回權威聯絡表。後續舊協議 adapter、歷史下載與恢復工具必須套用權威聯絡值，包含清空。本批沒有讓這些尚未完成的 adapter 自動啟用。

舊版 schema 3 候選可開庫升級，但舊匯入 manifest 不會被工具靜默改寫或重新匯入；不同 schema 的既有目的地仍拒絕覆蓋。正式混合版本、回退匯出與維護窗操作仍未驗收，不能據此切換。

## 驗證證據

- 後端／領域／資料庫共 **116 項**通過。本批新增 9 項聯絡 API／隱私／競態測試及 2 項 schema 升級測試；包含只關帳號的保留狀態、刪除回執、重建與舊請求拒絕。

- strict TypeScript、React／API 建置、隔離空庫 built smoke、舊 UI 生成檢查通過；前端約 547 kB，仍有原本超過 500 kB 的 bundle 警告。
- 合成事件、名冊、結算、帳務、登入／QQ 身份、bot 設定及 pending／sending／sent／failed／skipped 工作在聯絡變更前後逐列相同；既有 Python bot 讀取新庫的隔離測試亦通過。這不代表 B01–B15、真實 QQ 或正式版本組合已驗收。
