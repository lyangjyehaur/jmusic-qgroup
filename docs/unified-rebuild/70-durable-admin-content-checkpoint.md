# 第六十四批實作：管理內容原稿持久化

日期：2026-11-18（Asia/Taipei）。分支 `codex/unified-rebuild`。變更範圍 **`web`**，實際發布範圍 **`none`**。只修改 React 管理表單、本機原稿白名單及收件匣索引；API、schema、outbox、bot 依賴的入口及業務契約不變。保留現有 Python bot；未推送、未合入 main、未部署，未操作正式憑證、群設定、資料庫或真實待送工作。

## 三種管理原稿

詞庫管理、壁紙管理及找搭子移除改接共用 `useDurableRecord`／IndexedDB。保留原 v1 key 的帳號與管理授權 scope，原 command、目標 ID、revision、UUID 及 input 格式均延續。白名單只接受三個已審查的 key 家族與完整 scope，不匯入登入憑證、PIN、管理 CSRF 或隱私收據 secret。

詞庫保留新增、編輯、刪除與合併；壁紙保留原圖上傳、輪播間隔、啟停、排序與刪除；找搭子保留有效／歷史清單、固定內容核對與刪除。關閉分頁後保留原稿；尚未提交的原稿必須明確恢復，恢復、讀取其他分頁版本、載入保全版本及核對最新資料都重設確認勾選。找搭子選定移除對象也算未完成原稿，不能在未取消時直接切換目標。相同管理頁的搜尋、分頁及範圍篩選不觸發離頁攔截；離開頁面則等本機保存完成。

壁紙選圖先讀取原始 bytes，在記憶體保留並等本機交易完成；儲存失敗保留可重試的原圖。未知上傳結果沿用原序列化規則，只保存一份 base64，讀回時從 pending input 恢復預覽。分頁衝突與版本保全同樣保留原圖，不以縮圖取代。

## 原操作查回

每次送出都先等 pending 的整筆本機交易提交；成功的 put request 仍不足以送出 HTTP。同步 busy guard 防止連點，保存期間卸載則不再開始請求。明確拒絕先保存解除 pending 的狀態才解鎖；伺服器成功後若本機確認交易中止，原 pending 與原稿仍保留，不把它當成新的命令。

統一收件匣新增三種固定管理入口，只展示操作狀態與編號，不揭露詞條內容、圖片、找搭子內容或任意儲存網址。重開後只明確查回原操作，不自動重送；已消失的詞條、壁紙或找搭子目標也不阻擋原 pending 查回。原帳號／管理 scope、目標、UUID 及 body 不變。共用管理清除世代繼續適用，無須變更資料庫版本。

舊 session 原稿逐筆遷移，交易提交後才移除來源。損壞或 command／input 不一致的原稿阻擋操作，提供原文保全與下載；不猜測修正為另一個操作。伺服器 revision 衝突與同瀏覽器分頁 CAS 衝突分別驗證，兩者都不能無聲覆蓋。

## 驗證與剩餘工作

`durable-admin-content.spec.ts` 新增 27 個情境：十種命令關頁後由收件匣查回，逐一核對原管理授權、目標、UUID、body 與不重複修改；三種成功後本機確認交易 abort；三種 pending 交易 abort 不發 HTTP；三種明確恢復與確認重設；三種 session 遷移中止／保留來源及提交後移除；三種不一致 pending 保全；詞庫與壁紙雙分頁版本保全／載入、原圖 bytes、下載及 360px 畫面。
