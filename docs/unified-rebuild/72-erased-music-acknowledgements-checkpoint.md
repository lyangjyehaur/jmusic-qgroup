## 刪除後仍可查回

原本管理頁必須成功讀取成分，才會載入關聯與 PIN 的待確認操作；成分被其他操作刪除後，收件匣雖有入口，頁面卻停在 404。本批只將明確的 `404 PROFILE_NOT_FOUND` 視為成分已不存在，仍載入原帳號、原管理授權與成分 ID 所屬的本機紀錄。其他 404、5xx、格式錯誤及授權錯誤保持失敗處理，不能繞進恢復流程。

沒有成分時移除新關聯、重設口令、刪除與歷史入口，只在有原稿時顯示停用的原目標與核對原因；不保留空白操作表單。仍可明確恢復、保全版本、下載、捨棄未送出的關聯原稿及核對待確認操作。所有離開保護仍由同頁唯一 blocker 處理。

關聯核對沿用原命令的目標（含解除的 null）、revision、UUID、body 與原授權。伺服器既有冪等回執在成分刪除後仍可確認已接受的原操作；未接受的原命令會得到成分不存在，不能重建成分或重新指派。收到拒絕後保留原目標及原因，解除 pending 必須先完成本機交易。

PIN 繼續只以原 requestId 查回執，不重送口令。已完成操作即使最新成分讀取為明確的刪除狀態，也可保存本機確認，並提示「原操作已完成；成分目前不存在或已刪除」。找不到回執且成分已不存在時，只有再次查詢或「保全操作編號並結束核對」；保全只包含 `{requestId}`，不包含口令、原因或確認。保全成功後可下載，或明確載入再查詢；沒有自動重放。若在舊頁重新核對版本時才發現成分被刪除，同樣保留原 requestId。

## 競態、權限與相容性

原操作已接受、但讀取最新成分前被刪除的情況也能完成核對。確認結果後本機交易 abort、分頁 CAS 衝突或管理清除世代失效時，原 pending 不會被靜默丟棄；PIN 保全與結束核對的版本寫入及清除仍在同一筆交易。PIN 格式異常紀錄沿用檢查點 71 的下載隔離流程。

API 的原授權、Origin、帳號及管理 CSRF、操作簽章檢查全部沿用。新增伺服器驗收證明：刪除後已接受的關聯／PIN 回執仍可辨識，新命令不能建立原成分、變更原 body 仍為衝突、普通會員不能查管理回執；成分、關聯／PIN 歷史、帳號 epoch、bot outbox 及 bot 設定在查回期間不變。

本批沒有變更正式服務或跨服務契約。新版 web 與正式運行 bot 的實際版本組合、真實 QQ 及資料切換驗收仍待完成，不能以本機測試取代。
