# 開始時間的成團判定

狀態：已完成本機實作與隔離驗證，尚未正式部署。發布範圍：`both`（web 的 frontend／API，以及保留的 Python bot）。

## 行為

- 最低成團人數大於 0 的活動，在開始時間檢查正式報名人數；同行算人數，候補、待確認、邀請及已退出不算。
- 不足人數時，實際取消活動、停止報名並列入往期「未成團」。原因記錄判定時的人數與門檻。一般報名、補報邀請與舊請求恢復不能繼續加入。
- 達到門檻時保存成團結果，保留原報名開關與截止時間；活動中仍可加人。之後有人退出不會重新取消活動。
- 發起者事先確認成團、手動開始、最低人數為 0、草稿、刪除及歸檔活動不由自動判定覆蓋。
- 不撤銷名冊、不改動報名備註、出席、結算或款項。系統稽核 actor 為 null，actor_name 為「系統」。取消通知使用既有 `event_cancelled` outbox，沿用群政策、模板、去重及提醒失效機制；不新增投遞者。
- 列表、詳情、報名區、管理狀態、活動歷史與 bot 顯示同一個結果。保存的成團結果或實際開始記錄也用於往期分類與參與統計；只計目前正式報名者，退出者仍不計次數。

## 排程與歷史

正式 API entry point 開啟檢查；啟動、每 15 秒與 API handler 前執行，受現有隱私一致性 guard 保護。測試用 createApp 預設不啟動背景判定，整合測試明確啟用。

未來活動的 `formation_state` 記錄 `auto_pending`，表示已納入自動判定。這個內部標記不增加安排或名冊版本。已納入的活動，即使服務中斷跨過結束時間，恢復後也補做一次判定。首次啟用時仍在預定活動期間的活動立即判定；已經過期、沒有自動判定標記的舊活動保持原 lifecycle，避免以目前名冊追溯取消歷史活動。

判定使用 SQLite IMMEDIATE transaction，在取得鎖後重新核對活動與名冊；結果寫入 `formed` 或 `unformed` 後不重複稽核或取消通知。背景檢查與網站資料刷新不是毫秒級排程；列表及詳情沿用每 30 秒刷新，操作入口則先檢查狀態。

## 相容性與發布

schema 維持 15，沒有遷移。新增狀態使用既有、不受 enum 約束的 `formation_state` TEXT。Activity 回應加上可選的 formationState、actualStartedAt、cancellationReason，保留原欄位與網址。outbox 格式、通知種類、群設定與憑證不變。

保留的 Python bot 與 TypeScript bot 查詢均認識保存的結果。Python 報名狀態顯示也改為使用活動結束與原報名截止，避免已成團且可繼續報名時仍要求聯絡發起者補報。

HTTP 存取來源指紋已按實際修改核對更新：沒有放寬 session、Origin、account scope、CSRF、管理員、發起者或協辦權限。新增系統檢查只在既有隱私 guard 通過後執行。

正式發布仍須先合入並雙邊同步遠端 main，通過明確 SHA 的 release-source 檢查，在乾淨目錄建置；核對發布當時的 API、Python bot 及前端版本組合。不能只替換前端靜態檔。舊程式回退可讀既有表結構與取消狀態，但不具備新自動判定，且可能把保存成團、之後人數下降的活動錯標未成團；回退需另驗證展示與業務相容性，不能只看 schema 版本。
