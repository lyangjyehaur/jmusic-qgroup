# 正式切換與舊版唯讀對照

2026-11-25。本輪範圍：`none`，只核對來源與記錄需求，未修改或部署服務。本次新版整體切換仍先按 `both` 評估，不能以最近 UI 修改的 `web` 範圍代替整合版本的相容性判定。

後續使用者已授權正式部署，並更新要求：先停用舊服務，讓新版延續切換當下的正式資料；新版穩定後再建立獨立舊版測試站，允許在其副本寫入。以下唯讀對照為前一階段方案，不再是本次切換的前置條件。舊版測試站不得與新版共用正式資料或啟動真實 QQ 投遞。

## 使用者指定的資料方向

- 所有使用者轉向新版；切換後業務新資料只寫新版。
- 舊版保留作功能與歷史資料對照，不再接受業務寫入。
- 採切換時的獨立凍結副本，不與新版共用正在寫入的資料，也不做雙向同步。
- 舊版呈現切換當時狀態，不會自動出現切換後的活動、成分、投票或帳務。

## 資料形狀與來源

新版保留原看板相容資料表，新增正規化音樂、身分／映射與整合功能資料；原成分 JSON、身分 SQLite 和看板資料經匯入／對帳整合，不能假設舊程式可以直接操作整個新庫。

正式輸入必須取自維護窗停止舊 web、music、bot 及其他寫入後的最新成套快照，包含資料庫、成分、身分、媒體、最新刪除紀錄及待送工作。目前 5086 是可變的測試副本，不能提升為正式資料。舊版對照副本與新版匯入使用相同切換時間點，以便對帳。

## 唯讀對照部署要求（待實作／驗證）

- 固定舊 web／music 映像與獨立資料副本；舊版只供維護者對照，使用獨立入口及 cookie 範圍。
- 在服務端禁止業務寫入，包含任何經 GET 觸發的副作用；不只隱藏按鈕或僅封鎖 POST。資料檔及圖片採唯讀保護，驗證舊程式啟動／登入是否需要獨立的可拋棄 session 儲存，不能直接假設唯讀掛載後所有頁面仍可運行。
- 不啟動舊 bot、排程、通知或其他背景工作；隔離正式憑證與對外投遞，避免已送消息重播。新版實際 bot／worker 維持唯一有效投遞者。
- 封存資料保留原本權限與隱私保護；後續刪除要求亦須涵蓋可查閱的舊版副本，不能以歷史快照為由持續公開已刪內容。
- 原有使用者入口切向新版，維持舊連結適配、同 origin 草稿遷移及舊 Service Worker 退役。
