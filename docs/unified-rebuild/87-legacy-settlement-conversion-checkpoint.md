## 實際帶入結算表單

`舊看板本機紀錄` 現在支援原 invoice fields 與 `{react:1,value,revision}` 兩種草稿，先核對現在的活動存取及結算管理權，再明確帶入實際 TSX 編輯器。保全原事件／名冊快照、原名冊與帳單版本、逐人份數及付款責任、項目及房間 ID、文字、原圖、收款碼選擇與未送出的欄位；不送出原請求。

fields 原稿的發布帳號須與目前收款人一致。React 原稿沒有保存帳單版本、發布帳號與活動時長，標為未記錄，帶入後必須重新核對最新名冊與帳本。核對只更新基準，保留原輸入。原已核對及群通知勾選仍保全，但新確認從未勾選開始；重新核對與同意公開後才可發布。

未選人員的份數、原因、多人付款及金額／比例留在 `retained_people`，可在原人員區核對，納入時恢復；取消納入也不清空設定。原稿漏選的現有正式人員仍可納入，納入後維持正式人員必須結算的既有規則。已不在名冊的 active 人員不自動刪除，須明確核對。

模式切換保留另一方式的房間與商家付款欄位；項目及統一收款碼也保留。包間模式只送出實際包間及付款設定，不把未採用的項目／統一收款碼或本機保全資訊送到 API。未完成的原商家狀態保持空選項，不能默默當成 unpaid。原 paid 遇到帳本已有店家款項，仍由既有後端阻擋，須明確選 recorded 並核對帳本，不能重複建立商家支出。

## 原分攤、時間與圖片語意

共同 shares／equal 依原 payload 使用空 allocations；selected 只採用本版列入人員。fixed 的空值沿用原 `0.00`，weights 的空值沿用 `1`；duration 未填的分鐘只取原捕捉時長或使用者明確提供的原時長，不能用目前活動設定。缺時長時保持空白及提示，須逐人補齊。原未選人員及尚未採用的分配數值保留於編輯原稿，computed 金額／標籤與 breakdown 不混入新的輸入。

原結算與原活動／收支有不同的時間規則：結算使用 `new Date(datetime-local).toISOString()`，按當時裝置時區解析。轉換要求明確的原 IANA 裝置時區；DST 重複時段取較早時刻，缺失時段向後移動，與原 Date 行為一致並提示核對。沒有時區或時間無法解析時保留原值及原因，目的時間留空。秒與毫秒不截斷。

PNG 只移除可選 data URL 前綴，不重編碼、縮放或替換；收款碼庫 ID、歷史碼版本及歷史憑證項目 ID 保持。缺圖片／版本／ID 的引用拒絕轉換。多碼陣列存在時優先於舊單張 QR，包括空陣列；備用原 QR 保全在來源並提示，不額外附入新帳單。

## 目的提交與編輯原稿封存

先 strict IndexedDB transaction／CAS 提交目的原稿，再保存來源映射。目的已有不同原稿須明確保全，任何 pending 均禁止覆寫。來源、session、頁面有效性、device epoch 與目的 raw 在關鍵階段重驗；put 成功但 transaction abort 不算保存成功。目的成功而映射中止可以精確重試 staged raw。已知同 key、同原發布帳號的歷史稿一起保全；未知稿、不同發布帳號與原請求仍阻擋後續操作。

結算建立新 pending 前再次檢查晚到舊稿／請求。為保全後續修改過的未選人員與休眠模式，送出前在保存精簡 pending 的同一筆交易封存目前編輯原稿；封存中止則 pending 也不提交、不發出網站 mutation。pending 只保存原操作 UUID／完整 payload，避免重複 active 圖片。未知結果關頁後依原操作查回，完成後可明確載入封存版本恢復未採用的輸入。

兩個 IndexedDB 沒有跨庫原子鎖；同源舊頁停寫、原請求精確 adapter、全部未映射來源解決及來源退休後的目的版本查回仍是後續切換條件。本批不將保全映射當成全站遷移完成。
