# 第五批實作：站內稱呼、QQ 頭像與重新授權提醒

日期：2026-11-17（Asia/Taipei）。分支：`codex/unified-rebuild`。發布範圍 **`none`**。本批屬 P1，延伸 I06／I10 與 I07／I16，不代表階段或完整驗收完成。未部署，未操作正式網站、bot、資料庫、憑證、群設定或待送工作。

## 帳號稱呼與恢復

帳號頁連至 `/me/profile`；`GET／PUT /api/v2/me/profile` 只操作目前帳號。稱呼須為 1–24 個 Unicode code point，去除首尾空白，拒絕空白、控制字元、超長及額外權限欄位。改稱呼不換使用者 ID、scope、QQ 身分，不合併同名帳號，不修改付款歸屬或歷史帳單。

私有讀取驗 scope，寫入驗 Origin／CSRF／scope／有效帳號。修改的版本取自追加式 `account_audit` 中此帳號最新 `nickname_changed` ID；先修改再改回原稱呼也不能繞過版本檢查。新版本、帳號稽核、相關活動稽核及去重回執都在同一 immediate 交易，任何必要稽核失敗整筆回滾。相同操作編號及內容可讀原回執，另一份內容回 409；重播先重新檢查目前授權，撤權或已註銷帳號不能讀回執。

原 legacy `/api/profile` 會對本人仍有非 withdrawn 名冊的活動保存前後快照，更新活動版本，包含同場由本人代管的參加者顯示名稱。新 API 保留此行為與原 actor_name、排序及逐人快照欄位；只擔任管理人而沒有本人有效名冊的其他活動不新增歷史。名冊列、排序、狀態、付款人和凍結財務不改動。另增加帳號稱呼操作紀錄供版本與本人歷史查詢使用。

React 表單將草稿及待確認操作編號保存在目前分頁、目前帳號 scope 下；送出前持久保存原內容及編號。回應遺失時鎖住編輯，以相同編號／內容安全重試；刷新仍能恢復。成功後讀目前版本，避免原回執覆蓋後來的名稱。衝突保留輸入，須明確核對目前稱呼再保存。儲存不可用不送出，損壞原稿先保全再重開；未保存離站有確認，切換帳號保留原稿，當前裝置登出清除稱呼及既有音樂草稿。跨分頁只送 refresh 訊號，各頁向伺服器讀目前身份與稱呼。

## QQ 頭像與提醒

Session 的 QQ 摘要只新增經 `safeAvatar` 過濾的 `avatarUrl`；即使來自匯入／修復資料也重新驗證。只允許 HTTPS qlogo.cn 及其子網域；既有 HTTP 會升為 HTTPS，其他來源、憑證、port、fragment 或錯誤 URL 不回傳。CSP 對圖片加入相同官方來源；圖片使用 `no-referrer`，載入失敗或未提供時顯示具可及性標籤的稱呼首字備援。站內稱呼與 QQ 暱稱分開展示。

缺少 UnionID 的已綁 QQ 帳號，在無 query／hash 的活動列表或「我的」顯示非阻擋式提醒；編輯頁、邀請、回調、確認、裝置與管理頁不自動提示。依原 `kanban-qq-reauth-v1:{scope}` localStorage key 節流 24 小時，並在此次造訪記憶體內去重。儲存不可用時仍可繼續用網站，但跨重新載入不能保證 24 小時節流。

提醒可稍後處理；手動更新入口始終留在帳號頁。進入重新授權使用 `mode=bind`，保留原帳號及返回路徑，不先登出，也不以新 QQ 替換舊綁定。開始重新授權也會記下提醒時間。完成後只依伺服器實際 UnionID 綁定布林值顯示「已更新」或「仍未取得」；不回傳 UnionID 本文，不承諾 bot 個人功能已開放。授權成功但仍缺值時保留原帳號與手動重試，暫停自動提醒。

## bot 相容性

稱呼修改不改名冊狀態，因此舊 `on_append` 不新增報名廣播。若版本化 bot 設定啟用，但該活動已不符合公開群同步條件，新 API 同樣只將 pending／sending 的 group 工作標為 skipped；保留 private、sent、failed、已 skipped 的列與 payload／claim／模擬紀錄。不因改名重送既有工作。

此特定 hook 使用巢狀 savepoint，錯誤只記錄活動 ID，不阻斷帳號及不可變稽核，也不留下半筆 hook 修改。重構 runtime 的部署預設值由隔離 `REBUILD_BOT_ENABLED` 提供；不隱式沿用舊正式環境設定。資料庫明確 enabled 值優先。正式遷移仍須把既有實際有效預設與版本化設定對帳，不能據此宣稱正式環境配置已銜接或所有 TS bot 已完成。
