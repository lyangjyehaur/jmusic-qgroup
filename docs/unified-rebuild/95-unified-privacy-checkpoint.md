## 政策與原有用途

React／TSX `/privacy` 使用 `unified-2026-11-18`，明示是未上線統一系統的版本；沒有宣稱正式政策已生效。正式切換前仍須確認公告、生效資訊及適用版本，測試同意不能當成正式服務同意。

政策保留帳號、QQ、活動、費用、合作方 API、統計及資料申請的說明，補齊實際成分用途：舊副本及归屬核對、固定 ID 與自填聯絡 QQ、性別可見設定、首位匹配的私人留言、同好圈、公開趨勢、找搭子及歷史、活動分房、瀏覽器分享與接收方副本，以及 bot 指令／回呼、群政策、任務與投遞紀錄。聯絡、隱私權利與 ICP 保留。

核對 `music-fields`、`music-contact`、`music-match-data`、`music-matches`、`music-circles`、`music-trend`、`music-room-source`、`music-shouts`、分享 Canvas 及刪除流程後撰寫，沒有以公開趨勢代表會員內容公開，沒有把「私人留言」描述成僅本人可見，也沒有承諾能撤回群聊、分享或下載副本。依匹配列表所選排序及單獨查询的預設排序描述留言範圍。配對恢復備份的數量／期限對齊目前實作：最多 30 份、備份任務清理超過 14 天的資料。

原正式 `public/`、`music_site/public/`、Python 政策常數、bot 指令／模板與深連結不改動。

## 獨立紀錄與版本銜接

schema **14 → 15**，總表數 **96**：59 張相容表、37 張重構／遷移表。新增 `unified_privacy_consents`（帳號＋版本、首次同意時間、來源）及 `unified_privacy_receipts`（帳號＋操作編號、原版本及內容簽章）。首次同意時間不因重試、重新授權或 replace 改變；回執不可更新或替換。沒有複製舊同意或為遷移帳號推定新同意。

舊 `privacy_consents` 每帳號僅一行，Python 仍讀 `2026-11-10`。新版不覆寫、刪除或補造這張表的同意；新註冊或新 QQ 確認只寫統一紀錄。因而回退至舊網站時，新帳號可能需要重新確認舊政策，不能把新版確認偽裝成已讀舊版本。

session 的 `privacyAccepted` 僅查當前統一版本。註冊在原帳號建立／cookie 輪換交易內記錄同意。QQ 登入仍需勾選，因為目標可能是另一個帳號；不能轉用目前帳號的同意。已同意會員綁定自身 QQ 可沿用該帳號的同意，但版本必須吻合。回調確認、OpenID／UnionID 分離、衝突拒絕、原任務和帳務歸屬保持原流程。

新增讀取狀態、明確同意與查詢原回執 API。寫入驗證會員、scope、Origin、CSRF、版本、true 同意與 UUID；同意及回執原子提交。原編號／同內容重試返回原回執，變更內容拒絕。已完成的歷史版本回執可查回，不表示同意當前版本；未完成的舊版本不被接受。

新增 `privacy_requests` trigger，讓 TypeScript 與既有 Python 關閉帳號時均移除統一同意及回執，並阻止關閉後補寫。成分單獨刪除保留帳號同意。既有恢復對帳將新表納入業務資料比較：拒絕選取會遺失較新同意的備份，完整候選保留原回執，帳號刪除重播不恢復同意。

服務啟動仍不自動升級；schema 14 需先離線遷移，缺少 lineage 的 14／15 庫拒絕遷移。舊 TypeScript schema 14 映像會拒絕使用 15 庫；不能把任意旧映像當成已相容的回退方案。

## 既有帳號的確認與恢復

`/me/privacy/consent` 從帳號及隱私刪除頁進入，显示版本、狀態、同意時間與政策入口。確認不需重新 QQ 登入；沒有以查看政策、開手冊、讀 session、裝置授權或帳號切換當成同意。未確認不阻斷既有活動、款項、刪除申請或 bot 操作；本批沒有新增資料用途或擴大任何會員可見權限。

勾選只對目前讀取的版本有效，不在本機保存勾選結果。按確認後，先持久保存原帳號、原版本、原編號及原內容，重新讀取 session 核對帳號／版本後才發送。原操作加入既有待確認清單，允許原帳號恢復；不把內容或政策版本放進清單輸出。

回應不明時只呈現查詢原結果；重載不重送。404 後可明確重試同一編號及內容，或保全原操作再閱讀新版本並重新勾選。保全清單立即刷新，下載保留完整原 JSON。回執編號／版本不吻合不清除原操作；本機完成狀態保存失敗也保留原操作。跨頁 CAS 保全競爭版本，跨帳號不查詢或提交另一帳號的原同意。沒有把不可確認的結果顯示為完成。
