日期：2026-11-17（Asia/Taipei）。分支 `codex/unified-rebuild`。發布範圍 **`none`**：本機實作、隔離驗證與原始碼同步，不部署、不整合 main。日後運行產物候選範圍 `web`；沒有修改相容 schema、原 Python bot、outbox、群設定或 bot 深連結，實際切換版本組合仍待成套驗收。

## 統一入口與操作

從 `/people` 進入 `/people/circles`。圈子、成分卡、比較、詞條與我的成分沿用同一套身份、固定成分 ID 與返回白名單。`minLink` 門檻保存於 URL，成員／比較往返不重設；預設 40，選單提供 20／40／60／80／100，也可恢復 URL 中 1–100 的其他整數。非法網址值回到預設，API 拒絕非法、重複或額外參數。

詞條連入現有共用 `MusicWorkspace`，選取／移除與程度修改使用同一分頁草稿；返回圈子時若未保存，保留既有離開確認。保存後使用最新資料重算。跨分頁保存選擇、改名及刪除立即刷新；登出、切帳號或失去已保存成分資格時清除名單，晚回應不能恢復私人畫面。

前八圈直接顯示，其餘圈子可展開，所有成員與獨立成員都可開啟成分；同名成員分別用固定 ID 連結。圈內常見詞條顯示前六項及次數，獨立成員顯示原順序前八個詞條及完整選擇數量。同名詞條合計次數，同時保留各詞條的獨立連結。沒有資料、沒有兩人以上圈子、讀取失敗及權限不足都有附近的操作提示。

沒有沿用來源的隨機團體稱呼、戲謔描述或裝飾文案。保留「嚴格重合與校準匹配度不同」「同圈不代表每兩人都達門檻」「次數不代表全員共同選擇」等必要規則；次數解釋只出現一處。360px 畫面檢查後縮減卡片間距，長姓名、同名詞條的個別連結仍可換行及鍵盤操作。

## 原始計算與差異

對照 `music_site/upstream.py::compute_clusters`／`similarity_pct`／`sel_ids`：

- 排除完全沒有選擇的成分。每次由剩餘成員中選擇數最多者起圈，同數保留原插入順序；循原順序掃描，只要與圈內任一人的嚴格分達門檻就加入。再掃描到沒有變動，保留橋接及間接連結，不改成兩兩皆須達標。
- 群組按人數降序、同數穩定。每圈姓名按 Python Unicode code point 排序，同名保留原加入順序。詞條按實際入圈順序與原選擇順序累計，按文字合併、次數降序且同次數穩定，最多六項；不同 ID 的同名詞條可能令次數大於圈內人數，不能硬壓成「幾人共同選擇」。
- 獨立成員保留原起圈順序、有效詞條前八個與完整有效詞條數。計算依已保存選擇，不以目前未保存草稿分組。
- 門檻使用既定 55／45 嚴格 weighted Dice 分，沿用前批整數權重／有理數半偶規則；不使用推薦的平方根校準分。例如單一相同詞條嚴格分 100、校準分 36，在 100 門檻仍能同圈。原 Python 浮點在精確半分偶有差一，差分依前批已明確記錄的決定性修正核對。

來源 HTTP `/api/clusters` 只呼叫預設門檻的 Handler，回應最多八圈；來源 HTML 缺少 `clustersCard`，既有 `renderClusters` 實際無法進入。新版新增可達的原生頁、可調門檻與剩餘圈子展開；前八圈與來源結果對帳，其餘圈子是保留完整分析結果的新增呈現，不能聲稱原畫面已具備這些操作。原 `/music/api/clusters` adapter 仍待後續驗收。

## 權限、資料及 bot 保全

`GET /api/v2/music/circles` 在同一 SQLite 讀取交易中驗 session／scope、已保存成分門檻及資料快照。查詢只載入固定成分 ID、目前權威名稱、詞條及選擇；不載入私人留言、性別、QQ、PIN、帳號連結或原始欄位。輸出契約也只允許姓名／ID／詞條及合計。沿用 `no-store`／`Vary: Cookie`，不因原內部 Handler 入口而放寬匿名權限。

私人查詢以 scope／musicEpoch／門檻分鍵，進頁等候新回應，門檻切換取消舊讀取；失敗不留下看似有效的舊名單。保存選擇、成分資料、帳號稱呼與自建詞條的相關失效流程已加入圈子查詢；既有帳號廣播刷新跨分頁狀態。刪除及重新指派後每次按目前資格判斷，沒有持久的舊授權。

API 測試比對所有資料表與 `total_changes()`，多門檻讀取完全不寫入；實際 Python `qgroup_core.accounts`／`bot_views`／`identity` 在隔離檔案庫讀取，圈子分析前後一致，相容 DDL 與 pending／retry／uncertain 等既有 outbox 紀錄不受改動。沒有啟動投遞者或呼叫真實 QQ。

## 效能範圍

將配對計算中的詞庫索引提取為同一快照可重用的 `prepareMusicMatchStats`，既有 `musicMatchStats` 介面與計算不變。圈子對稱配對結果只算一次，正門檻下跳過完全沒有共同詞條的比較；入圈／標籤順序不變，Python 差分仍通過。

可用 `node --import tsx tools/rebuild/benchmark-music-circles.ts` 重現固定 seed 的純合成 CPU 樣本：2,000 詞條、每人最多 20 項、門檻 40。在本機 Node 22.22.3／darwin arm64 單次量測，100／300／1,000 人約 27／179／2,127 ms，圈子數 4／19／80；300 人初版約 3,977 ms。這是開發機樣本，沒有負載門檻或正式容量承諾。大量成員仍有平方級配對成本，1,000 人約兩秒可能阻塞 API；正式副本、併發、記憶體、刷新策略及是否交由 worker 計算，仍是正式切換前的效能驗收工作。
