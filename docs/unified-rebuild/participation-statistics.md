## 入口與資料

- `/activities/participation`：活動頁「參與統計」頁籤；整體活動數、參加人次、參加者數與參加者次數列表，支援期間／類型篩選、參加者紀錄及分頁。
- `/me/participation`：本人參加次數與紀錄；「我的」總覽提供累計次數與入口。
- 列表序號依目前篩選與排序連續編號，第二頁從 21 接續。名字旁顯示已綁定帳號的頭像；無頭像或載入失敗時沿用名字首字。手機版把最近參加日期移至名字下方，保留序號、次數與紀錄按鈕。
- 原活動連結保留。統計說明收於使用說明「參與統計」，不新增展示文案或裝飾卡片。
- 「紀錄」開啟共用對話框，內容在目前視窗可見；可關閉、按 Escape 或「返回統計」回到原名單。修正原本紀錄顯示於 20 筆名單下方、點擊後看不到結果的問題。本次修正範圍為 `web`（`frontend`），不改動 API 或資料。
- 活動頁籤維持單行，手機可左右滑動；切換頁籤或調整視窗寬度時，選中的頁籤保持可見。移除手機版四欄排列，避免第五個頁籤換行。本次修正範圍為 `web`（`frontend`）。
- 往期活動的未達門檻項目顯示「未成團」與最低人數，可用 `status=unformed` 單獨篩選；不混入「已結束」。前端與 API 共用列表分類，未成團項目也不顯示於「我的」近期活動。已取消維持原分類；已歸檔的未成團項目仍可用歸檔篩選找到。分類不修改實際 lifecycle、成團確認或帳務。

## 計數口徑

- 既有 `activityState` 判定已結束或已過預定結束時間，且開始時間不在未來；活動不得為草稿、取消或刪除。未設定時長且未明確結束的活動不自動納入。
- 完整名冊的正式報名人數必須達該場 `minimum_participants`；未認領同行包含在人數內，候補、待確認及已退出不算。最低人數為 0 表示不設門檻。未達人數的活動即使已過時間、標記結束、確認成團或歸檔，也不計活動數、參加次數或紀錄。個人統計使用全場人數判斷門檻，再套本人身份與權限。
- 只計 `confirmed` 報名。同一已識別參加者每場最多一次；未認領同行按個別報名計人次，不依姓名合併。
- 這是正式報名次數，未核對／缺席／遲到等出席觀察不改變計數；不宣稱實際出席率。
- 歸檔與結算狀態不影響已符合條件的活動。取消、退出、認領與改期後重新查詢會反映目前資料，並非永久凍結的歷史快照。
- 期間依活動開始日期換算台北時間；選項取自相同授權範圍的符合活動。列表與紀錄各 20 筆，摘要先統計完整集合再分頁。

## 身份與權限

- 整體及參加者紀錄 API 只回傳公開活動。參加者使用獨立的不可逆統計識別值，不另外回傳帳號 ID、QQ 號碼、付款人或私人備註。頭像沿用活動名冊規則，只讀取目前 QQ app 的有效身份綁定與儲存圖片網址，經 `safeAvatar` 驗證；不依姓名、代報者或舊 app 配對。
- 個人 API 必須有有效登入 session 與當前 account scope，只採 `attendees.user_id`。發起、協辦、代報管理、姓名相同與帳款關係都不算本人參加。
- 私人活動同時要求本人正式報名，以及目前為發起者或具有 `event_access`。管理員／協辦不自動取得私人紀錄。
- 關閉帳號不重新暴露身份；沿用現有刪除與匿名化資料處理。
