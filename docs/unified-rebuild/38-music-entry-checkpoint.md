# 第三十二批實作：詞條詳情與選取者

日期：2026-11-17（Asia/Taipei）。分支 `codex/unified-rebuild`。發布範圍 **`none`**：本機實作、隔離驗證及原始碼同步，不部署、不整合 main。運行程式影響範圍為新版 web：React／TSX 頁面、會員唯讀 API 與回應契約；不修改 schema、Python bot、outbox、群設定或正式資料。

## 名單與權限

新增 `GET /api/v2/music/entries/:id/members`。依 `music_site/service.py` 的成分身份門檻，必須有目前有效的會員 session、符合的 account scope，以及一份尚未刪除的成分；只有看板帳號、尚未保存成分者不能查看選取者。明確建立的空成分仍具成分身份。先確認權限，再判斷詞條是否存在，不向訪客洩漏名單。

名單取實際已儲存的 selections，涵蓋會員成分、未關聯舊成分及僅刪除帳號後獨立保留的成分；排除已刪除成分。同名者不合併，回傳完整清單，沒有隱含筆數上限。沿用 Python Unicode code point 姓名排序，同名保留資料庫成分插入順序。差分測試使用原 wrapper、upstream endpoint 與 contacts payload，比對身份門檻、原名單、聯絡欄位與排序；正式匯入後的全量順序對帳仍待成套驗收。

回應僅包含固定成分 ID、目前名稱、目前聯絡 QQ 及來源標記。使用權威聯絡表，明確清空時不回退到舊 contact 欄位；不帶帳號 ID、舊身份鍵、PIN、token、私人留言或性別。回應 `Cache-Control: no-store`、`Vary: Cookie`。單次讀交易不寫資料，不建立操作回執、不產生通知或待送工作。

## 統一詞條動線

`/music?entry=<id>` 與獨立 `/music/entries/:id` 使用同一個 TSX 詳情元件，呈現類型、分類、別名、建立者、已保存選用人數與「誰選了」。獨立頁加入原共用音樂工作區，切換詞庫／詞條／成分編輯仍是同一份選擇、程度、草稿與保存操作；開啟獨立頁不觸發離站確認，搜尋與分類保留。草稿選擇不假冒已保存選取者；保存成功後刷新詞條人數、名單與成分卡。

選取者可開啟完整同好成分，並複製名稱、聯絡 QQ；沒有聯絡 QQ 時可複製固定成分 ID。舊查詢號碼與自填號碼保持標記及未經騰訊驗證的必要提示；複製失敗提供手動複製指引。同好成分卡補上名稱與 ID 複製，卡片內詞條可直接開啟詳情。

從詞條訪問成分卡，若有未保存修改仍須明確保留草稿；返回詞條時恢復原程度與篩選。返回位置只接受本地詞條頁，拒絕站外、雙斜線、路徑折返及附帶 fragment 的任意目的地。原活動名單返回動線保留。

私有名單快取依 scope、music epoch 與詞條區分，帳號切換、成分刪除或登出後撤下；讀取使用 AbortSignal，延遲回應不能恢復舊名單。重新進入音樂工作區須等待目前成分確認；每次開啟名單或成分卡也須完成當次讀取，不能先展示已刪除選取者的快取。成分卡查詢亦加入 music epoch 與 AbortSignal。修改成分名稱／聯絡 QQ 後使名單快取失效，改名亦刷新公開詞庫建立者名稱。

音樂工作區在 session、成分與詞庫完成初始化後才掛載可操作內容；讀取中顯示狀態，失敗提供重試。避免從暫時的公開內容切換成帶 selection／blocker 的工作區時重建輸入框、丟失首次搜尋。此競態由全站回歸發現，修正後以延遲成分回應與重複搜尋情境驗證。
