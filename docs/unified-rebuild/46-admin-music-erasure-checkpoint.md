# 第四十批實作：管理成分刪除與全站成分重置

日期：2026-11-17（Asia/Taipei）。分支 `codex/unified-rebuild`。發布範圍 **`none`**：本機隔離實作與驗證，未部署或整合 main。沿用 schema 12；持久刪除協議與恢復流程有變更，跨服務影響先按 `both` 評估，實際版本組合尚未取得正式切換證據。

## 管理流程

成分關聯詳情 → `/admin/music/:id/erase`，核對稱呼、固定成分 ID、目前關聯帳號、選擇與找搭子數、自建詞條轉交數，輸入 `DELETE` 並勾選影響確認才可刪除。已關聯、未關聯、沒有自建詞條的成分均可處理。詞條轉交管理員，不刪他人的選擇；會員帳號、活動、報名、帳務與 bot 工作保留。

管理後台 → `/admin/music-reset`，獨立核對全部成分、選擇與詞條，輸入 `RESET` 並確認後重置。移除目前成分與詞庫，外觀設定與趨勢歷史延續；對應成分的活躍／歷史找搭子及原始副本依持久刪除流程清除。原本無法對應任何成分的歷史找搭子不假裝已清除，也不列入刪除數。

兩處均為直接 React／TSX，沿用帳號管理員與救援管理授權，管理員無須先有成分。畫面只保留位置、資料、操作、刪除範圍及必要風險／恢復提示。

## 持久刪除與未知結果

管理寫入重新核對目前角色、同源、會員 scope、一般與管理 CSRF、明確確認字詞及完整範圍 revision。revision 包含成分、詞庫、選擇、建立清單、私人欄位、身份證據、找搭子與原始文件；核對後有變更即拒絕，不偷偷擴大刪除範圍。

新增版本 2 的 `admin_music` 刪除意圖，固定記錄本次目標成分／帳號 ID、重置詞條 ID、管理者參照及回執摘要，不保存姓名、聯絡號、PIN、原稿或回執密鑰原文。沿用既有獨立 JSONL ledger 的私有權限、禁止 symlink、完整寫入與檔案／目錄 fsync；成功保存意圖後，交易失敗也必須恢復完成。SQL 狀態、最小回執、追加稽核與 applied marker 同一交易提交。恢復失敗時全站暫停操作，不能把刪除當成未發生。

刪除清除成分私人投影、關聯／PIN／欄位歷史、聯絡資料、選擇與建立紀錄，保留固定 ID tombstone。原生及舊建立者詞條轉交管理員；舊保存回執改為 410，舊找回意圖及其 OAuth 證據失效，關聯帳號 musicEpoch 增加。無關的一般登入、其他 OAuth attempt 與找回限流紀錄保留。共用刪除核心同時補強會員自刪的找回授權撤銷。

瀏覽器先保存原操作編號、精確 body 與隨機 256-bit 回執憑證才送出；儲存失敗不寫入。未知結果重整後先查回執，即使原成分已 404 仍可完成核對。查不到時才提供相同編號與 body 的明確重送；原核對版本過期仍會拒絕。回執要求目前管理授權及密鑰，不透過一般會員隱私回執入口提供。撤權與切帳號移除畫面，晚回應不能恢復權限；損壞紀錄先保存恢復副本。

## 舊快照匯入與 bot 保全

同一 ledger 可重播到較舊的新系統資料庫副本，並以 captured IDs 為準。已完成意圖不會在每次啟動重做，不會刪掉重置後新建的成分或詞條。

成套舊快照匯入先恢復帳號刪除，再按管理目標排除舊成分，完成音樂投影後才套用管理刪除／重置；避免意圖先標完成後，來源詞條又被匯入。來源建立者轉交規則保留，每筆管理刪除只有一份稽核。匯入報告增加 `musicAfterErasure`，區分原處理數與最新刪除套用後的剩餘成分／詞條數。

59 張既有相容表 DDL、Python bot、outbox 契約、群設定與網址沒有修改。合成檔案庫在重置與恢復前後直接執行 Python `accounts`、`bot_views`、`identity` 讀取，核對活動、名冊、身份及既有待送狀態一致；沒有啟動實際投遞者或使用 QQ 憑證。Python bot 不讀取此 web 刪除 ledger；舊 Python web 的 `privacy.recover` 無法解讀新版 ledger，不能直接拿舊 web 啟動候選庫作為回退。新寫入回退匯出與成套恢復仍是正式切換門檻。
