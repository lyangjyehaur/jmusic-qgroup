## 原稿與明確恢復

bot 設定改用共用 IndexedDB 原稿，以原帳號 scope、管理授權 scope 及既有 v1 key 隔離。保留完整原 revision、未完成數字／時區輸入、群標識與名稱、回覆／通知目標、每類普通文字及 Markdown 模板、發送模式、勿擾／節流／提醒欄位。原稿關頁後須明確恢復；不自動套用成 bot 設定。讀取伺服器最新版不覆蓋尚未送出的輸入。

預覽、確認勾選及訊息只留記憶體；恢復、載入分頁衝突版本或保全版本後都清除預覽與確認，送出前重新核對。保存和恢復上一版都保留原 command／revision／UUID／body。恢復前版仍由伺服器追加新版本，沒有改成前端複製設定或改寫既有歷史。

白名單只允許已審查的管理 bot key；此表單沒有部署憑證、token、管理 CSRF、QQ App secret 等欄位。原授權由目前 session 重新取得，不寫入原稿。收件匣只索引固定 `/admin/bot` 入口與操作 UUID，不列出群、模板或設定內容；普通未送出原稿與完成的空紀錄不冒充待確認操作。

## 提交、故障與競爭

提交命令前必須等本機整筆交易完成。put 成功後交易 abort 不發 HTTP，原確認與輸入仍可核對；同步 busy guard 防止同一事件間隙重複提交。關頁或權限失效後不能從尚未完成的儲存回呼開始請求。

伺服器接受後，先讀取目前設定，再保存本機確認。最新讀取失敗或本機完成交易 abort，均保留原命令；「確認原操作結果」只以原 UUID／body／管理授權重試。即使其他裝置已保存較新的設定，原回執不會再套用舊設定；畫面顯示最新版本。測試包含原模擬設定已有回執、伺服器後來改成實際發送的情況，核對舊回執不會覆蓋新模式或新增設定版本。

明確拒絕也必須先成功保存解除 pending 的狀態才解鎖，原輸入不丟棄。新操作開始時立即移除舊成功訊息，避免在持久化等待期間把前一次成功當成本次結果。

雙分頁 CAS 競爭保全兩份原稿，明確讀取已保存版本後才能繼續；可載入與下載版本。原 session 紀錄在 IndexedDB 遷移交易提交後才移除，遷移中止仍留來源。pending 與目前欄位不相符時阻擋，保全原文，不代替使用者挑選另一份內容。

離開頁面等待原稿保存；儲存失敗時留在原頁。放棄原稿也等待清除交易，不以畫面先清空來假裝完成。

## 撤權與 bot 相容性

保存、預覽、重新核對均受目前管理授權限制。預覽先提交本機原稿並檢查管理清除世代；即使無 BroadcastChannel，已被其他分頁清除授權的舊頁仍不發修改或預覽請求。預覽與版本重讀收到 401／403 後刷新管理 gate，清除該管理 scope 的原稿和保全版本。

原 API 及兩種 bot 讀取政策、模板版本、群切換對待送工作的處理、模擬不重播與恢復前版語意全部沿用。瀏覽器測試只使用隔離 fixture 設定，不連 QQ、不啟動 worker、不更新正式 bot。正式 web／bot 實際版本組合與真實 QQ 驗收仍待完成。
