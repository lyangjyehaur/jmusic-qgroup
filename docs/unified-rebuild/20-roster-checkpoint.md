# 第十四批實作：活動名單與同好成分銜接

日期：2026-11-17（Asia/Taipei）。分支：`codex/unified-rebuild`。發布範圍 **`none`**；只修改隔離重構系統，未部署或操作正式 bot、資料與憑證。正式切換仍須先按 **`both`** 準備並完成全部相容性驗收。

## 入口與動線

活動詳情增加「活動名單」：保留正式、候補與待確認報名，以穩定 attendee ID 作為每列與查詢鍵。同名者各自顯示；目前站內稱呼、本人／未認領同行、候補序號、退出申請、安排待確認、原報名留言及實際付款責任皆來自名冊，不由成分稱呼代替。

名單排序沿用原 Python：按 party／attendee 序號計算原位置與候補票號，再把正式、候補、待確認分組顯示，不重排或寫回名冊。已退出與未接受的私人邀請不出現在公開名單，也不回傳邀請 token。凍結的認領付款責任優先於目前稱呼／代報人，顯示不變更帳務。

登入會員點「查看 … 的成分」在原活動開啟單一原生 dialog，以自己的已保存選擇標示共同喜好。浮層不新增瀏覽歷史，Escape／關閉返回原按鈕；明確點「查看完整成分」才進個人頁，並提供「回到活動名單」。手機可用，dialog 具有標題、焦點限制及關閉按鈕。

未建立成分的帳號仍可讀名單，查看共同喜好時提供保存入口；保存後可返回原活動 `#participants`。訪客可讀原本公開名單，成分操作引導登入並保留此返回位置。未認領同行、沒有成分或已註銷帳號保留原報名列，不借用代報者、同名者或相同自填 QQ 的成分。

## 後端與權限

- `GET /api/v2/activities/:id/roster` 回傳最小名單與 event revision；`GET /api/v2/activities/:id/attendees/:attendeeId/music` 回傳該報名者可讀的成分選擇及共同喜好。欄位使用前後端共用 Zod 契約。
- 成分浮層僅依該場 active attendee 的 `user_id` 與目前有效 profile 關聯。不把 pending claim 當作認領完成，不查 manager_id 的喜好。沒有本人 profile 為 `viewer_unlinked`；無目標關聯為 `unlinked`；來源失敗與權限錯誤仍是錯誤，不偽裝成空資料。
- 浮層不包含私人留言、性別、聯絡 QQ、原數字 QQ、OpenID、PIN、找回／管理狀態或帳號 ID。完整成分頁仍使用自己的會員可見性 API；沒有因活動存取權而擴大私人欄位權限。
- 活動詳情、名單與成分共用存取判斷。已刪除活動拒絕；草稿僅 owner／有明確活動 scopes 的帳號；其他公開活動可讀，邀請活動限 owner 或該 event 的 access grant。網站管理員、另一場活動的 grant、同行代報或單純持有 cookie 不構成該場邀請授權。
- 帶 scope 的請求必須通過目前 session／帳號核對。未帶 scope 的活動詳情／名單只讀匿名公開視圖，即使附有會員 cookie 也不讀私有活動。成分一律需要 scoped member。JSON 格式錯誤的既存角色不被當作已授權。
- 每個活動／名單／成分讀取在同一 SQLite read transaction 內核對權限及資料，無 schema 變更，無業務寫入。GET 保持私有 no-store，不將成分查詢轉為外站 proxy。

QQ 頭像只讀目前設定的 QQ client、有效身份對應與官方 qlogo URL；其他 app、任意網址或讀取失敗使用既有備援。按鈕開的是該 attendee，自訂／外部稱呼相同也不合併列。帳號 scope 切換或跨頁登出會移除舊私人 query 與浮層。
