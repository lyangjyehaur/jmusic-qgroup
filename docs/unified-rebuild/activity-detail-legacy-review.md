# 活動詳情：舊版對照與修正

2026-11-26。開發分支 `codex/activity-detail-review`，起點 `main`：`9c6dfd0bb92cf70a6897a75b74238bd838611fdd`。

## 對照來源

舊版封存 `legacy/pre-unified-rebuild`：`8da877857f163853c449474e168534e2e493121b`。逐項閱讀該版 `public/app.js` 的 `renderDetail`／`joinEvent`／詳情操作、`public/activity.js` 的狀態／管理／安排／出席，以及 `public/roster.js` 的名冊／本人與同行／逐人管理／邀請／歷史。工作目錄的這三份保留來源和 `ui/board/domain.ts` 與封存 SHA 沒有差異。

新版對照 `ActivityDetail`、`ActivityParticipation`、`ActivityParticipants` 及各既有活動操作頁。這是活動詳情的來源與互動對照，並非重新宣稱全站業務、所有舊資料或實際正式 bot 組合已完整驗收。

## 已修正

| 項目 | 最終行為 |
| --- | --- |
| 費用與注意事項 | 活動的 `description` 顯示為「注意事項」，保留換行。沒有費用規則時不顯示空白費用區塊；舊資料實際存在的 `feePolicy` 仍顯示，付款歸屬與帳務仍在管理／結算。 |
| 時間 | 直接顯示起訖與時長。同日省略重複結束日期；跨日列兩天並標示跨日。UTC+8 不顯示額外時區字串，其他 offset／夏令時間差異保留。分享摘要仍提供明確時區。 |
| 名冊操作 | 「更新名單」改為「重新整理」，只重新讀取名單、權限、活動狀態及成分，不重新提交報名或群通知。 |
| 名冊排版 | 頭像與名字合為成分入口，狀態靠右；取消獨立查看按鈕和付款人文字。備註放在名字下方、保留換行與長字串換行；代報管理人、候補位置、退出申請、安排確認及出席狀態仍可辨識。 |
| 成分對話框 | 修正本機 React StrictMode 重掛時，舊的原生 dialog 關閉事件誤關新對話框的問題；點姓名或頭像可正常查看，關閉後保留成員分頁和位置。 |
| 名册數量 | 總覽與成員分頁都顯示全部有效报名，不截取前五位。 |
| 本人報名 | 使用者確認恢復舊版行為：本人報名／加入候補按一次提交；備註與退出規則收在展開選項內。內部沿用既有預覽 token／revision／安排版本協議，沒有另改分配規則。 |
| 同行與代報 | 保留預覽、部分正式／部分候補的明確接受及提交確認；本人備註可以銜接同行表單。 |
| 報名恢復 | 空白同行預設不視為未完成輸入；完成後的空白狀態不再在退出後被誤認成同行草稿。真實輸入保留；儲存失敗先阻止送出，回應未知沿用原 key／payload 查回，不重複報名。 |
| 詳情摘要 | 會員重新看得到發起者、指定結算人、成團進度、取消原因及安排待確認／暫不同意人數；實際起訖和協辦放在可展開區塊。 |
| 自動更新 | 恢復舊版每 30 秒更新及頁面重新可見時更新。只刷新目前可見的活動詳情，暫停隱藏保留頁與活動操作對話框的定時更新；不重掛表單。乾淨本人表單跟隨新 revision，已輸入備註仍保留並要求核對變更。 |
| 結束並結算 | 使用者確認恢復連貫流程：從詳情按「結束並結算」，預選結束操作，明確確認後執行；成功且本機確認已保存後重新讀取結算權限，有權限才自動開結算表單。日程協辦沒有結算權限時顯示由發起者／指定結算人處理。未知回應沿用原 key 重試，未確認前不跳轉；讀取權限失敗只重讀，不再次結束。帳單仍需獨立核對與發布。 |

## 尚存差異

- **未登入訪客摘要不足**：舊版公開活動可直接看發起者／取消原因等資訊；現有新版公開 `Activity` 契約沒有這些欄位，相關 lifecycle／delegation 讀取需要會員。這次只恢復會員摘要，未擴大登入或邀請權限；補齊訪客摘要需要另做公開讀取契約，不能只用 CSS 完成。
- **資訊位置不同**：舊版把已發布帳單、待接受邀請、認領待審及完整帳務集中在詳情；新版依已確認的原型分頁放入結算／管理與收件匣。功能與網址仍在，但總覽不直接呈現全部這些內容。
- **「暫待確認」入口較深**：仍可在報名表單切換參加意願，並保留 `signup?preset=tentative`；目前沒有恢復舊版詳情旁的獨立捷徑。這不是取消待確認或名額規則。
