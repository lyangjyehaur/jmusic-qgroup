日期：2026-11-17（Asia/Taipei）。分支 `codex/unified-rebuild`。發布範圍 **`none`**：本機實作、隔離驗證及原始碼同步，不部署、不整合 main。本批修改新版 web、公開契約及重構 schema 9 → 10；schema 按 **`both`** 評估。新增表與觸發器只涉及重構成分，不更動原 Python bot 的資料表、設定、outbox、工作狀態、網址或投遞程式；仍須正式切換版本組合驗證，不能據此直接單邊發布。

## 排行與完整詞庫

`/music` 預設顯示領域／細分各前 10 名，領域可展開全部、細分可展開至前 20 名；超過 20 項仍保留完整詞庫入口。兩類獨立展開與切換清單／氣泡，完整詞庫顯示全部。搜尋、分類及類型篩選對完整目錄生效，不被熱門筆數限制；離開篩選後回復原範圍設定。各類清單從 1 重新編號，選取草稿有可見「已選」狀態，保存人數與草稿分開。

舊 Python payload 使用 Unicode code point 排序，舊顯示控制器則再按 `count DESC → name.localeCompare('zh') → id.localeCompare` 排序。保留兩者各自契約：API 原排序不變，原生 TypeScript 顯示層套用舊顯示規則；測試擷取舊 `renderRankFor` 的排序式進行差分，不在運行時匯入舊控制器。

URL 保留 `library=all`、`mainExpanded=1`／`subExpanded=1`、`mainView=bubbles`／`subView=bubbles`，連同搜尋／分類在詞條頁與成分編輯間傳遞。瀏覽器驗證發現 React Router 的 functional search setter 不會像 React state 一樣累積同一輪修改；快速切換完整詞庫後輸入搜尋可能套回前一次 URL。本批改為保留事件當下的待套用參數，防止搜尋覆蓋剛選的範圍或檢視。

## 氣泡與可及性

原生 React SVG 氣泡包含該類全部詞條，不因清單的 10／20 項上限裁切。人數控制半徑，決定性分列配置保留每項與間距，隨容器寬度重新配置；圖高隨內容增加，不把大量項目縮成無法操作的小點。沒有使用新繪圖依賴或舊頁面 controller。

每個氣泡都是可用鍵盤聚焦／Enter 操作的站內連結，開啟共用 `/music/entries/:id`，沿用同一份草稿、程度與保存操作；原搜尋與檢視保留。完整名稱、人數與已選狀態保留於 accessible name／title，選取亦有可見文字與外框。可見名稱按 grapheme 換行，英文盡量按空白分詞，超過三行才截短，不切開 emoji、組合字或補充平面字元。清單切換按鈕隨時可用，完整清單提供全部名稱及人數。

## 統計與時間保全

公開目錄新增 `stats`：實際未刪除成分數、詞條數、24 小時新增成分／詞條及計算時間 `asOf`。成分數涵蓋尚未關聯帳號或帳號已關閉後獨立保留的成分，也涵蓋建立首個詞條時明確建立的空成分；不拿所有看板帳號數代替。讀取與詞條／選用人數在同一交易快照完成，沒有資料寫入或 bot 副作用，回應沒有增加個人欄位。頁面每 10 秒刷新，保存與本頁／跨分頁刪除亦使公開目錄失效。已有公開詞庫資料時，背景讀取失敗只在頁內顯示錯誤與重試，不卸載共用選擇／保存控制器；session 或私人資料讀取錯誤仍阻擋存取。新增回歸先重現原編輯器消失，再驗證錯誤期間的搜尋、草稿程度、保存按鈕與重試，且不送出任何選擇寫入。

匯入成分取 `music_legacy_profiles.fields_json` 的原始 `createdAt`，詞條取 `music_entry_details.created_at_json`；缺失／零值保持原意，絕不拿匯入時間或更新時間替代。沿用原 `float(value or 0) > now - 86400` 的嚴格邊界、秒單位及未限制未來時間的語意；數字字串、指數、底線與 Unicode 十進位數字按 Python 浮點語法處理，不誤收 JS 的十六進位或陣列強制轉換。無效匯入值按原詞條統計的零值退路處理，避免整個公開讀取失敗。

schema 10 新增 `music_profile_creation(profile_id,created_at)`，捕捉原生成分首次 INSERT 的時間。後續保存、改名、聯絡更新與解除帳號關聯不重設；匯入舊成分後移除暫時原生來源，刪除成分也移除時間紀錄。未修改既有表結構或五欄 profile INSERT 契約。

schema 9 的原生成分只有 `updated_at`，不能可靠推算建立時間。遷移只回填可由 `revision=1 AND before_json='null'` 初始 audit 證明的建立時間，其餘保留 `NULL`；既有已刪除與舊成分不新增來源。早期開發版中只建立空成分、之後又編輯或刪除原始詞條且沒有初始 audit 的資料，24 小時新增數會排除這些未知來源；不捏造新增時間。新版尚未部署，正式舊成分仍走保留原 `createdAt` 的匯入路徑。遷移為交易，失敗回退 DDL／版本，重開不覆寫來源。
