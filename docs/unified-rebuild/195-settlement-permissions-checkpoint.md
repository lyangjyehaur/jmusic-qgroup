# 結算、付款責任與歷史憑證權限

日期：2026-11-22。變更範圍：`none`；實際部署：`none`。只新增驗收測試及文件，沒有修改運行程式、schema、outbox、設定或網址。未整合 main，保留 Python bot。

## 新增驗證

`apps/api/testsupport/settlement-permission-matrix.test.ts` 獨立宣告活動查看權、結算職責、包間所有權及原發布者身份，不使用 runtime guard 計算預期結果。15 種身份與公開、邀請、草稿、刪除四種活動組成 60 個交叉案例，包含發起者、結算協辦、名單與結算協辦、其他單項協辦、實際代理、由他人代理的參加者、查看會員、管理員、獲邀管理員、無關會員、救援管理員訪客、訪客及未登入者。

每個組合核對帳單、歷史、單版內容、資產版本、圖片描述、結算 context 與預分包間。公開帳單及歷史圖片可由訪客或未登入者查看；私人／草稿／刪除活動依原查看政策限制。協辦與管理員不能因此取得結算職責；結算協辦可查看包間，保存預分包間仍只限發起者。历史收款碼的保存資格依原發布者判斷，不能用當前結算職責代替。

測試保留詳細版本的消費憑證與另一個舊人均版本的獨立 QR，逐位元組核對原 PNG 及 MIME。新版路徑與 bot 依賴的 `/api/events/` 歷史圖片入口均檢查查看權，不能讓舊入口繞過私人限制。

以有效 body 檢查結算預覽、發布及包間保存的拒絕，斷言具體的 401／403／404／409，不把 `INVALID_INPUT` 當成權限驗證成功。每批讀取及每次拒絕都比對全部使用者資料表。各 fixture 使用自己擁有的 `:memory:` 資料庫、synthetic session、模擬救援憑證與停用 bot。

另外 14 個案例檢查合法操作與撤權：

- 發起者與結算協辦可在公開／邀請活動預覽並發布，預覽不寫入，原 UUID 重播不重複新增帳單、通知或款項。
- 已認領人員的實際代理與登入會員維持新身份；結算保留原代理付款責任，不把款項移給認領者。
- 撤銷結算職責、私人查看權或活動所有權後，原發布收據不能越權重播，預覽及 context 也須重新授權。只撤銷職責時，原發布者仍保留該歷史版本的保存資格；撤銷私人查看權阻擋資產描述查看。
- 發起者保存包間只寫入一次；結算協辦不能保存同一安排。移轉所有權後，原發起者即使仍有私人查看權，也不能重播原包間操作。
- 歸檔、取消、草稿及已有結算四種限制阻擋新的預分包間修改。

初次 fixture 把憑證直接掛在人均歷史上，沒有其所需的詳細版本而違反外鍵；補正詳細版本後，另一批首次發布 fixture 嘗試刪除不可改寫的詳細歷史而失敗。已分別建立含歷史及首次發布的獨立 fixture，保留外鍵與 append-only 限制，沒有移除資料庫保護。兩份失敗報告均保留，不記成通過。
