# 第二十八批實作：時間投票

日期：2026-11-17（Asia/Taipei）。分支 `codex/unified-rebuild`。發布範圍 **`none`**：本機實作、隔離驗證及雙邊原始碼同步；未部署、未整合 main。投票定案、活動與 outbox 涉及 web／bot 契約，未來切換仍按 **`both`** 驗證，保留 Python bot。

## 原生入口與規則

- 活動導覽的「時間投票」連到 `/time-polls`，區分開放／待定案與往期；`/time-polls/new` 建立公開投票。日期模式提供跨月點選不連續日期的 React 月曆，亦可直接編輯候選日期；精確模式逐項填寫含時區的時間與共用時長。至少兩項，按需增刪，不沿用固定項數上限；HTTP 仍受既有請求體資源限制。切換已填模式先明確確認，未完成草稿可保存。
- `/time-polls/:id` 集中結果與本人填答；`/time-polls/:id/manage` 由發起者核對管理操作。投票不占名額；定案建立活動後，投票者須另行報名。新投票預設群同步，實際排隊仍須滿足 bot 類型與目標群政策。
- 每個有效候選必須明確選 yes／maybe／no，顯示已填進度；批次按鈕只填未選項。使用原生 radio、可鍵盤切換及清楚選中狀態。改票只增加 `vote_revision`，不增加安排 `revision`；同 UUID 重試不再次加票數版本。
- date 在候選 IANA 時區的隔日零時失效，exact 在開始時失效。過期候選、原票與統計保留，不能修改；舊客戶端同時送過期項時，忽略過期修改。排名只比較仍有效候選；定案結果凍結後不因時間推移重算。開啟中的頁面在時間界線／定期重讀控制狀態，不覆蓋未保存選擇，伺服器再驗截止與候選。
- 截止到期只以有效狀態顯示已截止，不偷偷延長或改資料。發起者可提前截止、明確調整截止並開放、附原因取消、軟移除，歷史追加不可改。移除投票不刪除已建立活動；定案活動被移除時保留原票並明示無法前往。
- 發起者可查看填答者姓名／逐項答案、管理歷史及群通知狀態；其他人只能看統計與本人答案。輸出使用欄位白名單，不公開內部 user ID、原 SQL JSON 或其他人的答案。

## 定案與交易

TypeScript API 原生處理查詢／分頁、建立、填答與管理，沿用 schema 9 的 `time_polls`、options、ballots、votes、append-only history 及 outbox，不呼叫 Python 執行業務。原 `/?poll=…`直接導航到投票頁，開啟不執行寫操作；全部舊 HTTP adapter 仍待後續補齊。

寫入驗證會員、相符 account scope、同源、CSRF、UUID、操作內容與當前管理權限，再查原回執。回執、安排、票／名冊、歷史、必要通知同一 SQLite immediate 交易；任何必要寫入失敗全部回滾。可選 bot 組稿使用 savepoint，失敗不撤回必要業務，亦不留下部分工作。

定案要求精確安排版本及票數版本、仍有效候選、明確接受場地／安排，以及有效正式報名截止。零支持、低於最低人數或未選有效最高票，必須填原因。日期模式另填同一候選當地日期內的開始時間及 1–24 小時時長。只有一次成功可建立關聯活動，保存不可變票數與填答人數，通知投票者查看安排再報名；發起者依原規則自動加入。活動建立的 conditions、event_created／signup audit、原名冊／同意與 bot 文卡／提醒，已對照 Python `time_polls.manage` 的日期和精確模式逐列差分。

## 原稿與未知結果

建立、填答與管理各自使用 account scope 隔離的 `qgroup:rebuild:activity-draft:poll-create|poll-vote|poll-manage:v1:<scope>:<id>`。儲存 pending 的唯一原 UUID 與完整原提交內容；重整與收件匣只提供恢復入口，不自動重送。明確重試先查原回執，再讀目前狀態，不把舊回執當最新票數。

儲存拒絕時不送出，損壞原稿先保全副本；離開保稿、跨帳號隔離及登出清除沿用共用規則。移除成功但回應不明時，只有發起者能從管理 context 讀取已移除投票，保留同一管理表單精確查回；公開入口仍回不存在，其他會員無法取得管理 context。安排／票數衝突保留輸入，明確重讀後重新勾選核對；過期候選不因原稿而恢復可投。建立／移除成功先清除未完成狀態再導航，避免被自己的離開保護攔住。延遲讀寫在元件卸載後不恢復私人快取或原稿。

## bot 與驗證

保留 Python worker。原生投票組稿沿用來源的文字／Markdown、自訂模板 context、群政策、深連結按鈕及 fact key 雜湊，`event_id=NULL`、`poll_id` 明確歸屬。定案活動沿用原投票的同步選擇。關閉同步、提前截止、取消、定案或移除會跳過舊 pending／sending 工作，不修改原 payload；只能明確重送失敗／模擬通知，有待送工作時阻擋重送。

隔離差分驗證序列化、五個時區／DST／跳日邊界、定案資料、文卡與工作去重。實際保留的 Python worker 透過 Mock transport 消費新版工作，延遲投遞重新摘要仍有效的候選，只送一次，第二輪不重播；沒有真實 QQ、正式憑證、群設定或真實待送工作。

最終後端全套 45 個檔案、394 項測試通過，其中新增投票 14 項；涵蓋必要回執／通知故障回滾、並行定案、嚴格輸入／時區／模式、權限、精確重試與 bot 消費。Chrome 全站 208 項回歸全部通過；其後補上跨月月曆、持續失效重讀及已移除管理恢復 context，再於最終建置重跑 19 項投票／結算測試全部通過（投票 11 項、結算 8 項）。這是完整 208 項加最終受影響範圍重跑，並非單次完整 210 項執行。360px 月曆與管理視圖已檢查，沒有水平溢出。

產物 smoke 另修正未讀完大型 JS 回應造成的測試關機等待：完整讀取資源後才關閉隔離 API，重跑正常結束。
