# P5 日常体验与恢复约定

## 本机草稿

活动（新建／编辑／复制）、逐人结算与款项表单使用 IndexedDB，按浏览器身份、表单类型、活动及操作分开保存。图片跟随结算草稿保存，不使用 localStorage 的小容量同步写入。只保存未发布的输入，不保存预览令牌；成功后清除对应草稿。恢复须显式选择，重新核对人员并预览，不能直接沿用旧的发布确认。

草稿保留原 revision／账单版本、款项记录 ID、实际时间、人员与图片引用。发现版本变化，显示持续提示并阻止提交；「载入最新版」明确替换输入，不把旧决定自动套到新账本。关闭、遮罩、Escape、返回使用同一保存提示；刷新有浏览器离开提示，并触发保存。输入自动暂存，保存失败明确提示。强制杀死浏览器或设备断电仍可能丢失最近尚未完成的写入，不承诺跨设备恢复。

`GET /api/me` 与 profile 返回 `draft_scope`，它仅是隔离本机存储的标识，不是登录凭证。改称呼不变，更换 Cookie 身份不共用。新版写请求及结果查询携带 `X-Kanban-Identity`，与 Cookie 当前身份不符时返回 409。授权仍完全由 HttpOnly Cookie 和后端权限决定。

## 结果未知与重试

每个写操作先持久化原路径、方法、完整 JSON、身份及去重键，再发送请求；不能保存凭证时不发送。预览不写业务资料，不纳入待重试清单。

网络中断、超时、响应损坏或服务器 5xx 保留凭证。消息页的「待确认操作」先查询原结果；若尚未提交，才显示原请求安全重试。保留原金额、记录 ID、时间、base_revision 和预览令牌；409 不自动改版本、不自动重试。重复点击共用正在执行的请求。只有创建活动的 client_intent 使用跨标签页稳定键；其余新操作使用新随机键，原结果未知的重试才沿用原键，避免称呼 A→B→A 被旧成功结果吞掉。

创建活动另含表单 client_intent，恢复草稿沿用它，新建／复制产生新值；创建去重键取自该值。相同创建意图修改内容也不能变成第二个活动。已提交的创建凭证继续保留，覆盖「响应成功，但还没清除草稿就刷新」窗口。查询确认创建成功时，剩余草稿转为对应原活动的待核对编辑，保留可能追加的文字，要求显式载入最新版。

`GET /api/requests/{key}`：

- 只查当前身份的请求；无记录返回 `{committed:false}`，不创建或执行操作。
- 成功返回 `{committed:true,result:...}`。活动结果重新检查当前可见性，返回当前角色与活动视图，防止转交后取回旧的发起者私有结果。
- 未登录 401；身份不一致 409；原活动不再可见 404。查询失败不会自动转为写请求。
- 业务写入、审计、通知与原请求结果维持同一个事务；无需新增数据库表或迁移。

## 手机日常使用

首页卡片保持简洁；详情收合「我的报名／同行」和角色管理入口，现场权限对应现场名单。消息页分开待确认操作、动态待办与历史通知。读通知不代表完成待办；待办根据最新安排确认、退出申请、最低成团决定、预计结束、待结算、申报核对、补退款与未结清状态重新推导。递补和重要变更沿用站内未读通知，不推送 QQ。

活动摘要包含安排、费用约定、截止与当前变更摘要，手动复制给群；剪贴簿失败可选择多行文本复制。邀请活动仍使用受控链接，不复制专属接任／报名凭证。复制活动只取标题、类别、时间段、时区、地点、说明、名额与费用规则，日期／截止重填；不复制人、钱、图、历史或协办。

新活动按类别提供时长默认值；手改时长后切类别不覆盖输入。地点提供高德搜索导航，由用户点击打开；不请求定位。收款码保留原图查看、下载和长按退路，图片失败可重试。手机表单使用可见视口高度响应键盘，长文字可换行。

## 验证范围

自动测试覆盖原有业务流程、身份隔离、查询权限、转交后角色、失败请求无提交、原请求安全重试、刷新恢复凭证、持久化失败时不发送及动态待办。

浏览器验收使用 360 × 800：活动草稿返回／关闭／刷新恢复并发布；复制活动空日期；结算金额、备注及合成图片恢复后重新预览发布；款项原时间恢复；另一页面更新后 409 保留输入及过期草稿阻止提交；本机代理模拟提交后丢失响应，刷新查询成功，数据库仅一个活动；恢复后追加文字保留并阻止重建。款项确认保存后草稿清除、余额更新；原图下载成功且 360px 无横向溢出。所有演示写入均为隔离本机测试库。

真实手机 QQ WebView、系统软键盘和原图长按／保存需要真机补验，桌面视口模拟不视为已完成。QQ OAuth 仍等待官方审核。
