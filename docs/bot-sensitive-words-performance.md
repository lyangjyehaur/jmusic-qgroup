## 實測結果

詞庫共 64,578 條原始禁用詞（正規化後 64,568 條），12 條允許表達。[來源、授權與衍生修改](../qgroup_bot/wordlists/README.md)均已記錄。

環境為 macOS arm64、Python 3.9.6；每種匹配器各執行三個獨立行程，表中取三輪中位數。這是本機微型基準，不是正式 Linux／Python 3.11 的服務延遲或效能保證。所有文字由工具合成，不包含正式群聊或資料庫資料，也不呼叫上游或 QQ API。

47 個候選的樣本是重複的「永远的神」，用於測量逐項呼叫成本，不是對真實 API 47 個候選的端到端測量。長文字由「永远的神，音乐大师，周末一起聊天。」重複至指定字數；前綴測試為重複的「中」。各行程內短候選及 300 字各測 15 次取中位數，10,000 字及前綴各測 3 次，100,000 字測 1 次。正則基線重現上一版的匹配方式，使用同一份完整禁用詞表，但沒有例外詞功能；這些計時樣本均未命中禁用詞。含命中、重疊與例外的正確性由獨立測試驗證。

RSS 是整個隔離測試行程的高水位，包含 Python、JSON 解析、匹配結構、輸入正規化和暫存配置，**不是詞庫額外占用量，也不是線上 bot 的完整記憶體用量**。重載時舊快取與新建結構會同時存在，因此需預留約 175 MiB 測試行程峰值以上的空間；實際 bot 還有其他功能與快取。Python 配置器可能保留已釋放空間，RSS 不一定立即下降。正式主機的時間與記憶體仍需另行觀察。

## 實作選擇與限制

- 使用標準庫實作稀疏 Aho–Corasick 多詞匹配，不新增 runtime 套件、Java 服務或外部審核請求。避免每個字元都嘗試數萬個正則分支；這組樣本的掃描耗時約隨輸入長度增加。
- 每個狀態只保留同一結尾最長的命中長度；較短命中完全包含於其中，不影響遮蔽覆蓋範圍，避免複製大量後綴輸出清單。重疊命中合併遮蔽，保留正規化前的字元位置。
- 只快取最近一份規則，由原先 8 份降為 1 份。首次查詢或詞檔變更才讀檔／建庫；正常查詢只檢查檔案時間與大小。一次重載仍有新舊結構並存的成本。
- 沿用背景執行緒和原有查詢互斥鎖。建庫與比對仍會消耗 CPU、與其他 Python 工作競爭，不能把背景執行緒視為零成本。
- 詞庫越大，建庫及常駐結構越大；文字越長，正規化位置表與輸出占用也增加。不新增候選數量、釋義長度或 API 回應大小限制，仍按原始順序保留重複候選。
- 本機詞庫無法判斷全部語境／變體，可能誤判與漏判，也不保證通過 QQ 的審核。

## 重現與驗證

```sh
python3 tools/benchmark_sensitive_words.py --runs 3
python3 -m unittest discover -s tests -p 'test_bot_*.py' -q
```

基準工具僅在子行程內使用規則，不修改詞庫或正式設定；用虛擬的檔案時間變更觸發重載，以量出舊結構仍在時的成本。完整 bot 266 項測試通過，涵蓋完整結果／重複項目保留、整詞及重疊遮蔽、例外範圍、簡繁與 Unicode 變體、隨機字典與窮舉範圍對照、錯誤規則不洩漏原文、快取重新套用更新後規則，以及模擬 QQ 投遞。未操作正式服務或向真實 QQ 群發送訊息。
