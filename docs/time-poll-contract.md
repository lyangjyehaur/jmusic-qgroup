# 活動時間投票（第一版）

發布範圍為 `both`：新增共用 schema 16–17、初始化遷移、帳號清除與投票 outbox；發布須依 [發布政策](deployment-policy.md) 驗證實際線上版本組合，正式版本見 `docs/releases/`。

## 流程與邊界

發起者填活動內容、時區、共同時長及 2–6 個不重複的開始時間。投票截止須晚於現在並早於最早候選時段。公開後候選及活動設定鎖定，需修改請取消後重建。第一版只有公開投票，不提供私人投票、同行代投、場地預訂或 QQ 投票指令。

每個登入帳號對所有時段各選「可以／勉強可以／不行」，截止前可改票；每人只保留一份有效選擇。未投票不算「不行」。未登入可查看合計，僅本人及發起者可查看個人選擇，其他投票者姓名不公開列出。

最高票按「可以」人數比較，「勉強可以」另列且不折算分數。截止只停止投票，不自動建立活動；發起者可提前截止、調整期限重新開放、取消或定案。同票自行擇一；零人可以、未達最低人數或未選最高票時須填原因。最低人數是參考門檻，不代表正式報名人數。

定案須確認安排並指定未來的正式報名截止，且不晚於選定開始時間。在同一資料庫事務中建立普通公開活動、替發起者本人報名、保存定案及票數快照，並向其他投票者新增站內消息。**投票不占名額，也不替其他投票者報名**。正式活動繼續使用原有報名、候補、改期與結算規則，並繼承投票的 QQ 群同步開關。

## QQ 群通知

新投票的 `bot_enabled` 預設 true，表單可取消；schema 17 升級前的既有投票維持 false，不自動追發。發起投票在同一事務呼叫 outbox hook，通知組裝或入列失敗沿用既有 bot 隔離規則，不影響投票保存。發起者可查看投遞記錄、切換同步及重送失敗／模擬消息；重送不重做建立或投票操作。逐次投票不廣播。

`time_poll_published` 是獨立後台通知類型，新預設包含此類型；已保存的類型清單不會被遷移改寫，發布時需另外啟用。沿用既有目標群、允許主動發言、勿擾、限速、模擬、重試和網址白名單規則。消息包含全部候選的開始／結束、時區、地點、投票截止和 `/?poll=<id>` 連結，不帶個人選票及投票人名。支持文字／Markdown 及跳轉按鈕，模板可在後台預覽。

worker 實際投遞前核對投票仍開放、期限未過且同步仍啟用，重新取得有效截止及模板；截止／定案／取消／關閉同步後，未送出消息失效，已發消息不撤回。定案時沿用群同步開關發出原有 `activity_published` 普通活動通知。重新開放本身不額外廣播，發起者可重新切換同步以發新邀請。

## 資料與 API

新增 `time_polls`、`time_poll_options`、`time_poll_ballots`、`time_poll_votes`、`time_poll_history`。投票不加入 `events`，不擴充既有活動狀態；歷史表禁止更新／刪除。定案關聯唯一 `event_id` 並凍結合計及投票人數。

| 路徑 | 用途 |
| --- | --- |
| `GET /api/events` | 保留原 `events`，附加 `time_polls`；開放／待定案公開列出，定案／取消只向發起者及仍有選票者列出 |
| `GET /api/time-polls/:id` | 公開詳情與合計；依登入身分附帶本人選擇及發起者管理資料 |
| `POST /api/time-polls` | 建立投票 |
| `PUT /api/time-polls/:id/votes` | 整份替換自己的各時段選擇 |
| `PATCH /api/time-polls/:id` | `close`、`extend`、`cancel`、`finalize`、`bot_sync`、`bot_retry`、`remove` |

所有寫入使用現有協議 2、登入帳號、`Idempotency-Key` 及請求查回機制。投票／管理檢查 `base_revision`；改票只增加 `vote_revision`，不同人可依同一管理版本投票。定案另核對 `base_vote_revision`，其他人改票或清除選票後，過期票數須重新核對。重複定案只建立一場活動，消息或歷史寫入失敗會一併回滾。

帳號關閉會清除私人選票；尚未定案合計隨之變動並增加票數版本，定案快照維持原合計。發起者須先定案或取消自己仍待處理的投票，才可關閉帳號。發起內容及管理歷史依現有共用記錄規則保留待審查。

發起者可對任意未刪除狀態執行 `remove`：設 `status=deleted`、關閉同步、作廢 pending／sending 邀請並留操作歷史。名單與詳情不再返回，投票／管理返回 404；刪除回應使用 `{id,status:deleted}` 墓碑，支援相同請求重播及請求查回，不重做操作。原選票與歷史保留供資料審查；刪除投票不刪除已建立的正式活動。活動刪除後投票不再顯示該活動入口。

## 相容性與驗證

schema 16 新增投票資料表；schema 17 新增投票同步欄位，重建 `bot_outbox` 以接受互斥的 `event_id`／`poll_id` 來源，保留既有工作 ID、內容、送達狀態、claim fence 及自增序號。事實欄位仍不可改寫；投票和活動各有去重約束。bot 的活動列表只查 `events`，投票不會被當作可報名活動，定案後才使用普通活動入口。新增 schema 與通知類型需 web／bot 成套發布；舊 bot 無法投遞投票通知，不以舊 bot 搭配新 web 上線。回退前需檢查未送投票工作及新版通知設定，不能單憑加欄位宣稱相容。

執行 `python3 -m unittest discover -s tests -q`、`node tests/test_time_polls.js`、`node tests/test_client.js` 及既有前端回歸。`tests/test_time_poll_bot.py` 覆蓋發起通知、設定門檻、模擬／重送、過期／取消防護、模板、定案通知及 schema 17 保全／失敗回滾。遷移測試涵蓋舊 schema 副本、重複初始化；UI 使用隔離本機資料驗證建立、改票、定案及手機尺寸。正式部署結果另記於發布紀錄；模擬測試不代表真實 QQ 投遞驗收。
