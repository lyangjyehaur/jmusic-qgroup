## 活動序號

`/活动` 等指令在多場活動時顯示 `1.` `2.` …；使用者直接打 `/名额 2` 即可。
序號解析用與選擇清單相同的 `candidates(db, command)`，因此 `/活动` 看到的第 2 場
就是 `/名额 2` 的第 2 場。8–16 位短碼仍可輸入（向後相容），但不再顯示在清單上，
按鈕 callback 也仍帶完整活動 ID，不受序號變動影響。

被動回覆也全數補齊：`/帮助`、選擇清單、`/活动`＋`/往期`、`/待办` 有專屬卡片，
其餘指令由 `_generic_markdown()` 把既有純文字答案轉成一致版面（固定系統標題／
**純文字**活動名稱行／清單／連結／免責引用），事實來源仍是同一個 `answer()`，
不會出現兩種說法。使用者原文不再放進 `##` 標題或 `**...**` 包覆裡。

**限制**：序號是無狀態、每次重新計算的便利值，活動增減或時間推移可能改變排序；
文案已明示「以最近一次清單為準」。財務類／`/往期` 指令的候選集合不同，序號以
**該指令自己**的清單為準。沒有引入跨訊息的選擇狀態或資料庫欄位。

## 安全與合規

- **信任邊界（2026-11-11 第三次修訂，取代先前「讓使用者原文 Markdown 生效」）**：標題、地點、說明、變更摘要等常規使用者輸入，本來就不該擁有樣式能力。QQ 沒有 escape 機制，實機 A／B／C／D 也證明反斜線、零寬插入、全形替換三種「保留符號但中和樣式」的做法在用戶端全部顯示異常，所以 `qgroup_core/bot_markdown.plain_text()`（原 `escape_markdown()`）改為**直接剝離語法**：`[文字](url)`／`![圖](url)` 只留可見文字、`<https://…>` 自動連結整段移除、`* _ ~ # > < [ ] ! |` 以及反引號、反斜線等語法字符刪除、`<qqbot-at-*>` 平台提及標記移除、換行／Tab／控制字元摺成單一空白、行首 `- `／`1. ` 移除。一般括號與中文標點保留（`(周六)` 仍可讀），時間 `11-13 18:00` 不受影響。**只有系統產生的片段**（固定標題、欄位標籤、時間、人數、連結、按鈕、免責引用）與**管理員撰寫的 `@md` 模板本文**可以輸出 Markdown；代入模板的每個變數值仍先淨化。
- **改期對照（唯一需要「樣式表達語意」的場景）**：`event_conditions` 每版存 `snapshot_json`（含 `starts_at`），`build_message()` 只讀前一版算出系統值 `previous_starts_at`，**不改 schema、不需 migration**。系統預設 `conditions_changed` 卡片會加一行 `- **时间** ~~原時間~~ → **新時間**`，由 `system_time_change()` 完全以系統時間組成、不含使用者文字；管理員也能在 `@md` 模板寫 `~~{previous_starts_at}~~ → **{starts_at}**`。純文字退路與既有 14 類文案不變，管理員可自行把該變數加進純文字模板。
- **標題位置**：QQ 不在 `##` 標題內解析行內語法，外層 `**...**` 包覆也會讓裡層同標記提前關閉。因此保留 `plain_line('活动名称：', title)` 純文字行與固定系統標題（`## 活动详情`／`## 待办`／`## 活动发起`），選擇清單用 `1. {標題} · …`。現在標題已先淨化，這個版面主要負責一致性與防止 `#`／`-`／`1.` 開頭的結構注入。
- 外部連結由 `content_problem()` 的 URL 白名單（`KANBAN_BOT_ALLOWED_HOSTS`）把關：含未報備網域的 Markdown 卡片會被攔下並降級純文字；**keyboard 跳轉按鈕的 URL 也比照白名單**（`OutboxWorker._keyboard_problem`）。使用者值中的 Markdown 連結目標已被剝離，不會再因 `[文字](外鏈)` 誤觸降級；若原文仍含**裸 URL**，白名單照舊攔下並降級純文字（既有安全網）。啟用白名單後，含外部網址的純文字通知同樣會被既有 `_content_problem` 攔住；下單前已盤點正式 DB，現有活動與兩則待送提醒都只有官方站連結。
- `msg_type=2` 的 body 不帶 `content`（官方要求互斥）。
- 結算逐人明細（顯式 opt-in 的 `group_notice`）在系統卡片與自訂 `@md` 模板都固定附上，
  不會因美化而被省略。
- Markdown 渲染失敗、內容檢查失敗、模板錯誤一律降級純文字；平台回傳 markdown
  拒絕碼只記 log，**不自動重發**，避免重複訊息。
