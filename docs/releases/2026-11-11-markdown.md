## 行為與契約

- 多活動選擇清單改為 `1.`～`8.` 序號，`/名额 2` 直接選第 2 場；解析與清單使用同一份 `candidates(db, command)`。8–16 位短碼保留向後相容但不再顯示。序號是無狀態便利值，活動增減會變；按鈕 callback 仍帶完整活動 ID，不受影響。此改動不受開關控制，已生效。
- 25 個被動指令都有 Markdown renderer；`msg_type=2` 只送 `markdown.content`、不帶 `content`。renderer 例外、內容檢查不過或模板錯誤一律降級成原純文字；平台拒絕碼只記 log，不自動重發。
- 14 類主動廣播的 outbox payload 新增**可選** `markdown_text`，後台可為每類通知寫 `<kind>@md` 模板。兩者皆為加法：不改 schema、不需遷移；舊版 bot 忽略新欄位照送純文字，舊版 web 產生的待送訊息也不受影響。
- 共用 `qgroup_core/bot_markdown.py` 統一 escaping（使用者原文反斜線跳脫、摺換行、`://` 插零寬空格）、4000 字／控制字元／URL 白名單檢查，keyboard 按鈕 URL 也納入檢查。結算逐人明細在系統卡片與自訂模板都必須保留。
- 唯一已知單邊不相容點：舊版後台的模板驗證不接受 `<kind>@md` key，過渡期不能用舊後台儲存設定。本次成套切換後 web 與 bot 皆為新版，不存在該混合組合。

## 02:04–02:10 補充驗收（範圍 `none`，僅唯讀探針＋測試群訊息）

針對上一節列出的三項缺口，以「不進正式群、不改正式 DB／env／後台設定」為前提補測。三支探針皆在 bot 容器內以 `docker exec -i … python3 -` 執行，來源檔未進專案、未寫入正式磁碟；活動資料建於 `/tmp` 的隔離 SQLite，用完即刪。

1. **離線組裝**：以標題 `*特别* _唱K_ [官網](https://evil.example)`、地點 `*小馆_ [传送门](…)`、說明含 `**加粗**`、`\`代码\``、`<qqbot-at-everyone />` 造隔離活動。被動 `/活动` 卡片 298 字、廣播卡片 368 字，`* _ [ ] ( ) < > \`` 皆反斜線跳脫、`://` 插零寬空格、提及標籤不再是可解析標籤、外部網址不再是可點擊連結；兩者 `content_problem` 皆為 `None`。
2. **平台接受度**：直接以 bot 憑證送三則明確標記「🧪 驗收測試訊息」的卡片到測試群：`A` escaping 卡片、`B` 廣播卡片、`C` 廣播卡片＋兩顆跳轉型 keyboard 按鈕。三則皆 `ok=true`、`api_code=null`、回傳 message id，**證明 `msg_type=2` + `markdown.content` + `keyboard` 的組合被 QQ API 接受**。
3. **worker 完整投遞鏈**：在隔離 DB 把廣播目標唯一設為測試群（並於送出前 `assert target == TEST_GROUP`），以新版 `enqueue()` 產生含 `markdown_text`／`keyboard` 的 outbox 列，再呼叫 `OutboxWorker.claim()` → `deliver()` → 真實 API。`payload keys = ['_template_context','keyboard','markdown_text','msg_type','text']`，`result=sent`、`final status=sent`、`delivered msg_type=2`、`has markdown.content=True`、`has keyboard=True`、`content` 欄位不存在（互斥正確）。**14 類廣播的 `msg_type=2` 首次真實投遞已於測試群完成**（此處以 `activity_published` 為代表，非逐類實發）。

**兩個新發現（影響正式行為，尚未改動）**

- `KANBAN_BOT_KEYBOARD` 未設定，`keyboard_enabled()` 在正式 bot 為 `False`；被動回覆本來就不帶按鈕（`reply_prepared` 三則皆 `keyboard=false`）。因此**正式廣播目前仍不會附按鈕**；上述 keyboard 測試是在探針 process 內設 `KANBAN_BOT_KEYBOARD=1` 才產生，不代表已對正式環境啟用。要啟用須改 env 並 `--force-recreate bot`。
- worker 對帶 `_template_context` 的**舊 outbox 列會重新渲染 `markdown_text`**（`worker.py` 的 `elif payload.get('_template_context')` 分支），所以「舊版佇列保留原文」只對純文字成立。開關開啟後，切換前就存在、尚未送出的列（例如 `estimated_over_reminder` id=4，排程 2026-11-15 09:00 UTC）在投遞時會變成 Markdown，且目標是後台設定的正式群。這符合預期，但與先前文件措辭不同，特此更正。
