# 指定結算人、墊付款抵扣與群收款通知

發布範圍：`both`。目前為待發布紀錄，尚未填入正式映像或切換結果。

## 行為

- 發起人可在活動結束前或結算時邀請指定結算人。對方須明確接受，才能發布結算、管理收退款並使用自己的私人收款碼。新指定者取代原指定者的結算權，其他協辦職責保留；普通協辦與網站管理員不取得財務權。
- 每版帳單凍結發布帳號的收款人姓名及活動內帳戶識別。換帳號發布不能繼承別人的收款碼引用；舊版圖片繼續保留。
- 結算表單明確核對未付店家、一人已墊付、已在帳本登記。確認發布時才將明確填寫的個人墊付與帳單原子寫入；預覽不寫錢，重送同一請求不重複入帳。多次／多人付款在既有帳本處理。
- 保留墊付人的 AA 責任，以已確認墊款抵扣應付。例如五人各 AA 100 元、一人先付 500 元，其他四人各補 100 元，墊付人待收回 400 元。收款人與墊付人不同時，仍須登記後續償還。
- 每次發布可確認向公開同步群分享逐人 AA、付款帳戶待補／應退、收款人及所選圖片。長名單顯示部分明細與網站入口；金額標為發布時快照，後續以帳本為準。
- 文字及每張收款碼為獨立 outbox 工作。圖片只在文字確認送出後發送，重試圖片不重播已確認的文字／其他圖片；版本更新、收款發布者撤權、可見性與群同步變更均於發送前驗證。模擬模式不上傳也不發送，平台未確認的結果不視為送達。

## 契約與發布順序

schema 維持 15，沒有資料遷移。沿用既有邀請 kind、JSON scopes、不可變帳單及 append-only 款項表，新增明確的 `settlement` scope、帳單快照欄位及可選請求欄位。舊請求不會憑空產生墊付款，也不會自動重發舊結算或更正正式帳務。

新 bot 保留處理舊 outbox 文字的行為。新 web 產生的圖片工作需要新版 bot；不能讓目前舊 bot 消費新圖片工作後宣稱已支援。按 `both` 發布，先建置及驗證映像，再停舊 bot／web、啟動新 web、啟動新 bot並核對實際來源與健康。不得只更新 web。

正式操作遵循 README 的 server2 部署與保全流程：取得部署鎖，核對目前混合版本 manifest 與來源摘要；保留兩個舊映像、來源、Compose 環境及配對 SQLite／圖片備份；以 UID 994:992 在隔離備份演練；不由 root 遷移正式庫。回退須分別恢復原 web／bot 映像組合，保留發布後的財務寫入，不能覆蓋舊資料庫。若新版已產生待送圖片，回退前須停止 bot 並明確處理不支援的待送工作；權限與新功能回退也須告知指定者。

## 驗證

- 後端涵蓋指定者接受／撤權、非參加者接任、保留其他協辦職責、私人碼庫與歷史圖片、實際墊款抵扣、帳單及款項共同回滾、請求重播、編輯不重複墊款、群通知淨額、圖片失敗單獨重試、舊版／撤權拒送、文字失敗阻止圖片、模擬零網路與模板保留明細。
- 既有 11 組 JavaScript 測試，包括 `action=join` 預設收起高級選項。
- Chrome 簡、繁兩套手機流程實測：詳情直接指定結算人、指定者發布自己的收款碼、確認店家實付、兩人各 AA 50／實付者墊 100 後零補款且待收回 50、另一人待補 50；320 px 寬度不溢出。
- 群投遞為受控模擬 API 驗收，未對正式群發測試消息，不代表已完成 QQ 平台真實收圖驗收。

官方接口依據：[群聊富媒體上傳](https://bot.q.qq.com/wiki/develop/api-v2/autogen/api/v2_groups_group_openid_files.post.html)、[富媒體消息](https://bot.q.qq.com/wiki/develop/api-v2/server-inter/message/rich-media.html)。圖片由私有檔案以 `file_data` 上傳，`srv_send_msg=false` 取得 `file_info`，再用 `msg_type=7` 和 `media.file_info` 發送；不將私人碼庫改成公開 URL。
