# 報名名單 QQ 頭像（20261110-avatars1）

使用者確認方案後發布：群內稱呼左側加入 24px 圓形頭像；未認領同行、未綁定 QQ 或載入失敗顯示姓名首字。姓名仍使用站內群內稱呼，不以 QQ 暱稱替換。

頭像只讀取參加者本人帳號在目前 QQ 應用下已綁定的資料，沿用既有 qlogo.cn 網址驗證及 HTTPS。未認領同行不沿用代報者頭像；認領後顯示本人頭像。維持邀請活動既有存取檢查，不新增公開個人資料接口。

頭像是目前顯示資料，不加入報名快照或結算歷史，更新照片不產生假異動紀錄。同時修正未登入訪客與未認領同行的 user_id 同為空值時，同行被誤判為「我」的問題。

## 驗證

- 以實際對外 Docker 容器程式的隔離副本套用本次修改，使用對應資料表版本的既有測試，80 項報名、認領、QQ、隱私與頭像測試通過；資料全為隔離測試資料。
- Node 測試涵蓋原版、簡中、繁中名單輸出：本人頭像、同行首字、原始姓名保全、HTML 轉義及圖片失敗退路。既有簡繁測試通過。
- Headless Chrome 於簡中及繁中各驗證 320、375、1280px：24px 頭像、無照片與失敗照片的首字退路、長稱呼換行、無水平溢出或頁面例外。

## 部署範圍

僅部署 `qgroup_core/roster.py`、`public/roster.js`、其簡繁版本與 `public/style.css`。沒有資料表變更；不部署工作目錄中其他尚未發布的功能。實際線上為 Docker Compose 的 `qgroup-web`，以目前運行映像為基底只覆蓋上述五個檔案，建立新版映像，再沿用既有 Compose 重建 web。先完成 SQLite／圖片備份並保存原程式及映像標籤，確認容器健康狀態與對外檔案摘要。bot 容器與反向代理設定不變；舊 systemd web 服務維持停止，避免搶占 8791。沿用現有靜態資源 no-cache 策略，重新整理即可取得新版。
