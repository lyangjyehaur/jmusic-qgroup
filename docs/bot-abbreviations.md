功能發布範圍：`bot`。初版與投票調整成套發布（`both`），見[初版發布紀錄](releases/2026-11-13-flexible-polls-abbreviations.md)；完整結果修正已單獨更新 bot，見[完整結果發布紀錄](releases/2026-11-13-bot-full-abbreviation-results.md)。尚未完成真實 QQ 群聊驗收。

## 使用

在允許指令回覆的群 @ 機器人後發送：

```text
/缩写 yyds
/縮寫 nbnhhsh
/nbnhhsh yyds,nbnhhsh
```

支援空格、半形／全形逗號和頓號分隔；每次最多 5 個不同縮寫，每個限 2–32 位英文字母或數字。新增句子輸入時會先在本機提取含英文字母的片段；只傳送正規化的小寫縮寫，不傳送整段原文、群組、成員、訊息 ID 或 QQ 憑證。不帶參數且沒有引用時會顯示用法。結果以純文字列出，按 API 回傳順序顯示全部候選，不限制候選數量、不截斷單個釋義，也不合併重複候選；尚未確認的 `inputting` 結果會另加標示。候選資料來自社群，含義仍需配合語境判斷。

### 引用訊息與句子提取

發布範圍：`bot`。引用別人的「這也太 YYDS 了，awsl！」，新訊息只 @ 機器人，即查詢 `yyds,awsl`；也支援 `/縮寫 這也太 YYDS 了，awsl！`，或引用後發 `/縮寫`。只 @ 機器人但沒有引用時仍顯示活動；明確的 `/幫助` 等指令優先，不會執行引用原文裡的指令。一般未 @ 訊息、@全體、未授權群與關閉回覆的政策保持原樣。

依 [QQ 官方群 @ 事件](https://bot.q.qq.com/wiki/develop/api-v2/autogen/event/group_at_message_create.html) 的 `message_type=103` 或 `message_scene.ext` 中的 `ref_msg_idx` 識別引用，讀取 QQ 隨事件提供的 `msg_elements` 及巢狀文字。有訊息索引時只選取對應項；官方範例沒有索引的文字包裝也支援。不讀取／保存群聊歷史，不下載附件，不把引用裡的提及當成這次 @ 機器人的證據；仍須由當前訊息提供直接 @ 證據。若 QQ 沒附原文、格式無法辨識或沒有合格片段，回覆用法並提示複製原文查詢。

提取完整、2–32 位、含英文字母的英數片段，保留首次出現順序、忽略大小寫並合併相同查詢詞；中文、純數字、單一字母、網址（含域名）、Email、@提及及底線識別字不送查詢。一般英文單字與拼音縮寫無法只靠字面可靠區分，因此也可能被提取，釋義由上游決定。沿用每次最多 5 個不同查詢詞的輸入規則，超過時顯示用法，不悄悄只取前 5 個；這不限制任何候選結果或釋義長度。

引用查詢沿用背景工作、快取、敏感詞遮蔽、長結果續讀和模擬模式。去重指紋包含引用元素的摘要，避免同一時間引用不同原文互相覆蓋；雙事件推送仍只處理一次。日誌不新增引用原文或場景鑑權資料。新增 15 項引用／提取測試，並擴充 WebSocket ACK 測試涵蓋引用查詢；完整 bot 303 項測試通過。自動驗證使用隔離資料庫及模擬 QQ／上游。已於 2026-11-13 21:35（Asia/Taipei）完成 bot 單邊部署，正式映像兩輪完整 Python 測試各 638 項通過（各 skipped=8），詳見[發布紀錄](releases/2026-11-13-bot-quoted-abbreviations.md)；尚未完成真實群聊驗收。

完整結果修正於 2026-11-13 17:44（Asia/Taipei）完成部署，僅更新 bot，web 保持原映像與容器。

## 敏感詞處理

發布範圍：`bot`。API 候選釋義及回覆中的縮寫名稱，命中本機詞表時將整個命中範圍替換成 `[已遮蔽]`，保留其餘文字、候選數量、原始順序與重複項目，不恢復結果數量或字數限制。禁用詞、允許表達和輸出共用 OpenCC 4,113 條字元映射進行簡繁比對；匹配也正規化全形／半形、英文字母大小寫，並忽略詞內空白、標點和零寬字元，因此插入星號並不會使詞表失效。正常釋義仍保留原始簡繁寫法。檢查最終組裝後的全文，跨候選的命中會分別遮蔽各候選內的文字，保留候選分隔符和數量。

內建詞表 `qgroup_bot/sensitive_words.json` 已合併 houbb 主詞庫、konsheng 的政治及反動分類和本機簡繁基礎詞，共 64,578 條原始禁用詞，另保留 12 條允許表達以減少誤判；來源固定 commit、原始檔雜湊、授權及修改方式見[資料說明](../qgroup_bot/wordlists/README.md)。這不是 QQ 官方敏感詞庫，不能涵蓋語境、諧音、所有變體及 QQ 的全部規則，可能誤判或漏判，也不保證 QQ 接受消息。正常釋義完整保留；不使用露出一兩個字的方式嘗試避過平台審核。

若需補充規則，可在 bot 可讀路徑放置 UTF-8 JSON 字串陣列，例如 `["需要遮蔽的词"]`，並在 bot 環境設定 `KANBAN_BOT_SENSITIVE_WORDS_FILE` 指向該檔案。額外規則與內建規則合併；檔案修改後，每次查詢（含一小時上游快取命中）都按最新規則重新處理，不需重新呼叫上游。新增環境變數仍須重建 bot 容器載入。已指定的檔案無法讀取或格式錯誤時回覆暫時不可用，不退回未過濾的原文；日誌不記錄命中詞或上游本文。此功能只處理縮寫查詢，不影響活動與主動通知。

匹配改用 Aho–Corasick 多詞匹配，詞庫未變更時只保留一份編譯快取，每次查詢不重新建庫；第一次使用或詞檔變更時才重建。重疊的命中會完整合併遮蔽，允許表達只豁免完全落在其內的命中。效能數據與重現方式見[效能紀錄](bot-sensitive-words-performance.md)。不新增 runtime 依賴，也不限制候選數量或釋義長度。純文字不再套用 Markdown 語法清理，因此 `C#`、`a_b`、`a < b`、星號與括號等正常符號會保留；僅摺疊換行／控制字元，繼續排除 URL、@ 提及及 QQ 提及標記。

本機詞表不產生第三方審核費用，未開通或呼叫付費服務。[騰訊雲文字內容安全購買指南](https://cloud.tencent.com/document/product/1124/37118)（2026-11-13 查閱）列出：首次開通 3,000 條、15 天有效的試用額度；按量後付費人民幣 25 元／萬條，不足萬條按比例計算。每條送審需呼叫一次，單條最多 10,000 個 Unicode 字元；試用到期或用盡後繼續呼叫會轉入計費。若未來接入，需另行配置服務與憑證、確認送審粒度和預算；雲端審核同樣無法保證與 QQ 群審核結果一致。

2026-11-13 本機驗證：258 項 bot 測試通過，包含整詞遮蔽、簡繁／大小寫／全形／分隔字元、快取結果套用最新詞表、錯誤詞表不回傳原文，以及 QQ 發送與輸出預覽日誌只取得處理後文字。測試以隔離資料庫、模擬上游與 QQ 投遞執行，未操作正式服務。

2026-11-13 大詞庫改版驗證：266 項 bot 測試通過，新增重疊詞完整遮蔽、例外詞範圍、Unicode 展開、政治詞與異常詞庫測試；以隨機字典對照窮舉命中範圍。最終 64,578 條詞表的三輪效能量測見[效能紀錄](bot-sensitive-words-performance.md)。此改版連同下列六項修正於 2026-11-13 19:10（Asia/Taipei）完成 bot 單邊部署，見[發布紀錄](releases/2026-11-13-bot-sensitive-abbreviations.md)；未向真實 QQ 群發送測試訊息。

## 長結果投遞與續讀

先完整發送一則純文字；只有 QQ 明確返回 `40054007`（訊息長度超限）才開始分段，不自行裁切釋義或候選。分段按 UTF-8 字元邊界處理，初始每段預算預設 2,000 bytes，可用 `KANBAN_BOT_ABBREVIATION_PAGE_BYTES` 調整；這是傳輸分段預算，不是 QQ 官方固定長度，也不是查詢結果上限。分段若仍遭明確長度拒絕會縮小預算。

[QQ 官方群聊發送文件](https://bot.q.qq.com/wiki/develop/api-v2/autogen/api/v2_groups_group_openid_messages.post.html)（2026-11-13 查閱）明訂：被動訊息有效 5 分鐘，每則訊息最多回覆 5 次，同一 `msg_id + msg_seq` 不可重複。該頁未公布純文字固定長度，所以不把其他訊息類型的字數當成此介面的硬上限。

每次最多嘗試 5 次發送，序號遞增，保守地把被拒絕的嘗試也計入，並為剩餘結果／錯誤提示保留一個名額。尚未發完時會提供：

```text
@機器人 /缩写 继续 <回覆提供的編號>
```

亦接受「繼續」「下一页」「下一頁」。續讀以新群訊息的 `msg_id` 取得新的回覆額度，不重新呼叫上游；全部內容依原順序續送，重複候選保留。互動事件的 `event_id` 沒有沿用 `msg_id` 的序號保證，超長時只提示改用群訊息續讀，不假設能連續分段回覆該事件。

待續讀文字以 0600 權限存放於資料庫同目錄的 `bot-abbreviation-results/`（0700），只保存已遮蔽文字、群識別雜湊及投遞進度，不寫入共用資料庫。編號綁定群組，首次建立後 1 小時有效；全部送完即刪除，建立後續待讀結果時清理過期檔案。正常短結果不建立檔案。bot 重啟可在有效期內續讀；每次續讀及真正發送前重新套用規則。若更新規則時剩餘文字有變更，先保存處理後內容再投遞。

只在平台確認成功後推進進度。明確拒絕時不跳過該段；網路例外或 202 等不確定結果不自動重發，提示使用者續讀可能重複上一段。儲存失敗時提示無法保存完整結果，不以截斷結果冒充完整回覆。若 QQ 連錯誤／續讀提示也拒絕，日誌記錄 `notice_sent=false`，使用者需重新發起查詢；不改用未授權的主動訊息發送。

本次六項修正通過 288 項 bot 測試：符號保留、簡繁／跨候選遮蔽、整體網路時限、收訊／心跳不等待縮寫工作、長度拒絕／多輪續讀／不確定投遞、快取容量管理。使用隔離資料庫、本機慢速 HTTP 伺服器及模擬 QQ，未向真實群發送。本次修正與敏感詞功能已完成部署；正式映像兩輪完整 Python 測試各 619 項通過（各 skipped=8），備份副本演練、混合版本驗證及上線後檢查通過，詳見[發布紀錄](releases/2026-11-13-bot-sensitive-abbreviations.md)。

## 運行與相容性

- 縮寫事件獨立成背景工作，不持有 SQLite 連線，也不讓 WebSocket 收訊等待查詢／投遞；心跳 ACK 及其他指令可繼續處理。最多保留 16 個縮寫事件工作，超載時記錄 `abbreviation_dispatch_overloaded` 並不再建立工作，避免無限排隊。等待投遞鎖使用 asyncio，不占住共用執行緒池。
- 上游網路工作具有 4 秒整體等待時限，涵蓋 DNS／建立連線／持續慢速回應；底層仍使用 socket 逾時。若 OS 的 DNS／讀取尚未結束，原工作持續占用唯一網路槽，後續查詢不再建立被遺棄的網路執行緒。遲到結果不入快取。JSON 解析、遮蔽及 QQ 投遞時間另計；完整讀取正常 JSON，不以固定回應大小截斷。
- 每個 bot 行程共用最多 256 筆、一小時有效、原始 JSON 合計 8 MiB 的快取，成功的空結果也快取。以 JSON bytes 保存以便直接計量，超過容量的單筆照常處理和回覆但不快取；其他條目按 LRU 及到期時間清理。8 MiB 不包含本次解析／渲染暫存及整個 bot 的其他記憶體。每秒最多一次上游請求，同時最多一筆；失敗後暫緩 10 秒，不重試該請求。重啟後快取消失。
- 網路錯誤、429、無效 JSON 或資料結構會回覆暫時不可用；不把上游本文或例外文字送到群裡。詞條中的連結及 @ 提及不轉發。
- 沿用原有群組授權、全域指令回覆開關、模擬／實際發送設定。模擬模式仍執行縮寫查詢，但不向 QQ 投遞。
- 僅修改 bot 程式、bot 環境範例、詞庫產生／量測工具、測試及文件；不變更 schema、outbox、共用設定、網頁入口或 web 運行程式。程式相容性判定為 `bot`；發布時仍須按部署政策核對線上 web 的來源與映像並驗證版本組合，真實 QQ 驗收另行記錄。
